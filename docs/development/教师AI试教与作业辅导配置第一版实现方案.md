# 教师 AI 试教与作业辅导配置第一版实现方案

创建日期：2026-11-07。方案修订：2026-11-08。

状态：2026-11-08 按用户“开始执行”授权完成本地多模型试教与方案保留改造；当前验收见第 13—16 节；第 14 节收缩试教界面，第 16 节更新初读输出协议，以最新规则为准。第 12 节保留旧版记录，不与本次测试混计。未部署。

本次确定：试教页直接展示并允许编辑作业题目、作业要求和完整辅导提示词，支持选择多个模型同时生成、并排比较；移除试教中的“整段复看”、试教评价与调用记录界面；教师可保留满意的“模型＋修改后的提示词”组合，之后选择采用。正式作业仍只采用一个模型，用于初读和后续交流。

## 1. 第一版边界与核心决定

第一版先开放给段落论证作业 `revise_argument`，沿用已有教师类型授权。文献综述与从零写作保持各自现行功能；共享服务可以支持扩展，但本轮不把读者试读、图片识别、班级归纳等全部纳入教师配置。

| 项目 | 第一版决定 |
| --- | --- |
| 提示词 | 管理员提供推荐模板，教师编辑本次作业的完整副本，最终只使用一份生效的教学提示词 |
| 模型 | 试教可同时选择多个教学模型；正式作业最终选定一个，初读、普通交流及既有学生端改稿反馈均使用它 |
| 思考 | 与模型一起保存为作业配置，初读与交流共用；学生不能逐轮覆盖 |
| 试教 | 页内编辑题目、要求、完整提示词和模型；覆盖确认初稿、初读、交流、改稿后继续交流、自主结束与提交预览，使用正式学生流程的核心服务 |
| 配置比较 | 本轮支持 1—3 个不同模型，默认单模型；同一轮共享题目、要求、提示词、样稿和教师输入，各模型独立流式输出，桌面并排比较 |
| 保留方案 | 每列结果旁有“保留此方案”，保存该结果实际使用的题目、要求、完整提示词、单个模型及思考设置；可命名、重复取用并保留多个候选 |
| 页面精简 | 移除试教中的整段复看按钮、试教评价表单和调用记录／原始请求展示；改稿后通过正常消息继续交流 |
| 正式生效 | 编辑和试教只影响草稿；明确点击“正式布置”或“应用新版本”才改变正式配置 |
| 开始后修改 | 允许发布新辅导版本，统一作用于本作业之后获准开始的 AI 请求；不按学生进度分流版本 |
| 历史 | 已有回复、稿件、提交、成绩和过程证据保持原样；每次实际调用记录所用版本 |
| 试教门槛 | 鼓励试教，但不把模型成功回答设为布置作业的硬门槛；未试教时明确提示并允许教师继续 |

教师无需逐次请求管理员批准提示词。管理员负责推荐模板、可用模型和资源权限；教师负责本次教学方法。代码保留权限、真实稿件来源、流程状态、输出格式和引用校验，不把反馈条数、先肯定后提问等教学偏好重新写成隐藏规则。

## 2. 教师首次布置作业的操作流程

| 步骤 | 教师看到与操作的内容 | 保存结果及下一步 |
| --- | --- | --- |
| 1 填写任务 | 选择段落论证、填写题目与要求；班级、截止时间、评分和反思沿用原表单 | 形成教师私有的准备稿，学生不可见 |
| 2 设置 AI 辅导 | 编辑完整提示词，选择一个候选模型；展开高级设置可调整思考 | 只保存候选配置，进入试教后仍可直接调整 |
| 3 进入试教并比较 | 在试教页直接修改题目、要求和提示词，选 1—3 个模型；放入样稿，同时观察各列初读并继续交流 | 每组运行固定自己的输入快照，各模型结果和对话独立保存；修改输入后运行新一组 |
| 4 保留满意方案 | 在满意的模型列点击“保留此方案”，确认名称 | 保存该列实际使用的完整组合，留在试教页继续比较；不更改作业准备稿或正式作业 |
| 5 采用到准备稿 | 从结果列或“已保留方案”选择一个方案，预览差异后点击“采用到准备稿” | 新建作业可带回试教修改后的题目、要求和该列 AI 配置，仍未布置作业 |
| 6 正式布置 | 核对任务、班级、截止、单个模型与提示词，点击“正式布置” | 创建正式作业和辅导版本 v1，再发送既有作业发布通知 |

教师可以不进入试教，直接使用推荐提示词布置作业。准备稿和已保留方案均有可恢复的列表入口，不引入审批、排期发布或完整课程发布系统。

### 2.1 提示词设置

- 面板标题使用“AI 辅导设置”，提示词字段使用“你希望 AI 怎样辅导学生”。完整原文可编辑，不只允许在管理员提示词末尾追加补充。
- 新建时复制当前类型推荐提示词；教师改动仅属于本次准备稿，管理员模板不被修改。
- “编写提示”提供目标、判断依据、表达方式、示例等说明，不自动额外注入不可见文字。教师写的批注示例是完整提示词的一部分。
- “恢复推荐版本”展示将替换的内容并确认后替换。模板来源版本只用于追溯，不表示教师副本持续跟随模板更新。
- 管理员后来发布新模板，正式作业和教师草稿均不自动被覆盖。教师可主动取用，之后视为新的候选配置。
- 作业题目和要求仍用于描述题目、材料与完成任务；评分和反思仍按现有边界用于评阅及提交，不自动注入修订辅导上下文。

### 2.2 模型与思考设置

- 作业准备页仍提供一个“本次作业的辅导模型”。试教页提供“参与对比的模型”多选，允许 1—3 个不同模型；仅选一个时也可完整试教。每列固定显示模型名称和对应的思考设置，采用到正式作业时只能选一个组合。
- 教学模型清单由管理员明确配置，可指定一个推荐模型。只剩一个可用模型时自动选中并展示；有多个且没有合法推荐值时要求教师选择，不任意选列表第一项。
- 选择教学模型不要求把它开放到学生普通聊天列表。学生通过合法作业获得受限的任务调用权，不能在其他会话借此使用模型。
- 默认思考取推荐值并在候选中固定。每个模型分别展示真正支持的选项，不支持控制时显示“模型默认”；不强迫所有模型使用相同的供应商参数。复用现有能力识别与参数转换，不能把平台档位名称当成供应商原始值。
- 第一版不向教师开放 temperature、top_p、工具、知识库、系统消息层级等通用 playground 参数。非教师可调的生成参数也须在运行配置中明确解析和记录，不能两条路径各自取不同默认值。
- 对本功能覆盖的作业，既有全局初读模型、学生模型选择、学生思考开关不再覆盖教师已发布的配置。管理员相关页面需说明这些作业从作业版本取值。
- 图片识别、班级归纳等未纳入本方案的步骤继续遵循原有管理设置，不因“统一模型”而误用文本辅导模型。
- 指定模型被删除、撤权或底模失效时，给出清楚的不可用原因，不静默切换其他模型。教师可选择新模型试教并发布新版本；AI 暂时不可用不应额外阻止学生按原规则提交。

### 2.3 准备稿与发布

准备稿保存教师已填的表单和候选 AI 配置，显示“保存中／已保存／保存失败”。允许暂时缺少班级或截止时间；正式布置时执行完整校验。试教只要求足够的题目要求、有效 AI 配置和合格样稿。

在现有作业列表中提供简洁的“准备中的作业”入口。准备稿使用独立资源，不恢复已删除的 `Assignment.status`、`archived_at` 或作业归档接口。编辑已有作业的 AI 草稿也与生效配置分开。

“保留此方案”保存一个教师私有、可再次选择的组合，不等于采用或发布。“采用到准备稿”先展示将使用的题目、要求、完整提示词、单个模型、思考及非秘密生成配置，并与目标准备稿比较。新建用途明确采用后一起带回，保证教师在试教页编辑的题目和要求不会丢失；若选择保留当前题目要求，则仅取 AI 配置，并将当前试教依据标记为不匹配。班级、截止、评分和反思均不从试教方案恢复。

已有正式作业的 `update_ai` 准备稿仍只负责 AI 配置。试教中的题目、要求可以自由编辑作为测试情境，但不经“应用新版本”改写正式题目要求。若要原样采用不同题目要求的方案，先返回作业设置按既有规则显式保存题目要求，再刷新调整准备稿和差异；也可明确仅采用 AI 配置并提示需要按正式题目要求重测。检测目标 revision 冲突，不能覆盖在另一页面修改的任务。

发布前仅在准备页展示准确的运行事实，例如“本配置已试教：初读、交流”，或“本配置尚未试教”；不展示评分、评价表或“教学质量通过”。未试教、配置变化或只覆盖部分流程时给出提示；教师可以在发布区域明确选择“按当前配置布置”，无需增加管理员审批。

发布以服务端保存的草稿版本为准，不相信前端传入的 `tested=true`。教师双击、网络重发不能重复创建作业或通知。向多个班级布置时一次提交相同配置，为每个班创建独立作业及其 v1；失败不得遗留部分班级已发布的结果。

## 3. 试教的具体体验

### 3.1 页面与保存

试教页是可直接调整输入的对比工作台，顶部常驻“教师试教，学生不可见”。不能只展示配置摘要，也不能要求教师返回作业设置页才能改题目、要求、提示词或模型。

| 区域 | 内容与操作 |
| --- | --- |
| 顶部导航 | 返回作业准备、已保留方案；不放正式发布按钮 |
| 任务与辅导设置 | 默认展开的可编辑“作业题目”“作业要求”“辅导提示词”全文输入；模型多选及各模型思考设置 |
| 样稿与模拟输入 | 共用样稿编辑区；初稿确认后共用消息输入框，可保存修改稿后继续提问 |
| 对比结果 | 1—3 列独立模型对话，列头显示模型、思考、生成状态；各列均提供“保留此方案”与“采用到准备稿” |
| 已保留方案 | 教师私有列表，显示名称、题目、模型、保存时间；可展开完整提示词及要求，选择加载继续试教或采用到准备稿 |

桌面同屏并排显示各模型结果；390px 窄屏用模型标签切换完整结果，保留模型名称、各列运行状态和方案操作，不把多列挤成不可读的窄条或裁切内容。

进入前保存准备稿，恢复完成前禁用编辑，保存失败保留输入。进入后编辑的是教师私有的试教工作稿，单独保存并可恢复，不自动回写目标准备稿。运行前先保存工作稿、样稿和当前 revision，再冻结一组输入。输入变化后明确显示“尚未用于新一轮试教”，原结果仍标识原组合；不得把编辑框新内容冒充旧结果的配置。

“开始试教／用当前设置重新试教”启动新组；如保留历史，则通过指定已完成节点另开组。生成中的组保持原快照，不因教师继续编辑而变更。结果卡可展开查看实际使用的题目、要求和完整提示词，供保留前核对；这是教师配置内容，不展示底层消息、调用记录或供应商参数。

第一版样稿支持输入或粘贴，继续使用学生相同的初稿长度、段落处理和确认规则。文件与图片导入不是首版试教必需项，不为了复用导入按钮而放宽仅学生本人可调用的接口权限。

### 3.2 从初稿开始试教

1. 编辑题目、要求与完整提示词，选择 1—3 个模型，放入样稿，点击“确认初稿并开始试教”。
2. 同一组各模型使用相同任务、提示词和初稿，独立并行生成初读，分别展示输出、等待与失败状态；不等待最慢模型完成才展示其他结果。
3. 教师可以扮演学生追问、反对或提出疑惑。默认“一起发送”将同一输入发送到本组可继续的模型，每列只承接自己的对话历史；不得把模型 A 的回答自动拼入 B 的历史。
4. 修改共用稿件后先保存，再通过正常输入框提问，如“我修改好了，请看看现在这段”。移除“整段复看”及专门复看操作，不生成隐藏复看指令、不自动附旧稿。若当前设置已经改动，必须先启动新组或明确返回原组设置，不能静默忽略编辑内容继续发送。
5. 说“我准备提交了”检查收尾体验，再选择一列进入提交预览，查看适用反思与结束状态。
6. 提交预览只结束所选列的测试，不结束其他列，不创建真实 Submission、成绩、班级通知或画像事实；不得要求 AI 同意才能结束。

移除“适合／还需调整／不适合”、自由评价备注及其保存入口，不用评价面板替代方案保留。试教页也不显示调用列表、实际请求、原始响应、用量或参数调试面板。保留可理解的生成中、完成、失败、已停止状态与必要的错误原因，不由 AI 自动打分或推荐胜出模型。

“保留样稿重新试教”创建新对比组及各列测试会话，并实际重新调用模型，不因输入相同返回上次缓存结果。同一次请求因网络重试则使用幂等键复用，避免重复收费。两种操作必须区分。

### 3.3 带着已有对话测试新版本

在可见对话的已完成节点提供“从这里比较新方案”：从教师自己的某一列复制当时稿件和已完成对话，在试教页编辑候选并选择模型。新组各模型从同一个明确的来源节点开始，之后各自延续；原测试保持原样。此入口属于对话操作，不恢复调用记录面板，不开放给真实学生作业。

第一版用这一能力检查中途更新的效果。它不能只用新提示词重新跑一次空白初读来代替，因为真实学生已经有旧反馈和修改历史。

从真实学生反馈一键带入可留在第二版。若实施中选择提前加入，只能取教师已有权限查看的已提交冻结过程，不能借试教读取原本不可见的未提交正文。缺少的旧参数、稿件或消息不能猜补；应明确其为不完整情境。

测试配置、样稿、对话、结果和失败保存在教师私有范围。首次发布后的准备稿可标记已发布并保留关联，不自动删除用于追溯的试教记录。

### 3.4 多模型对比的执行规则

- 同一组使用一份题目、要求、完整提示词和初稿；每个模型分别绑定自己的能力、思考和有效生成配置。修改提示词后运行新组，可比较不同轮结果；本轮不增加“每列分别编辑另一份提示词”的复杂交互。
- 第一轮各列上下文相同，模型及其对应设置除外。后续“一起发送”共享本轮教师输入和当前稿，但各列历史随各自回答变化；界面明确显示为“各自对话继续”，不声称后续请求上下文完全一致。
- 同组一轮最多同时运行 3 个模型；服务端限制与前端一致，并沿用资源限流。只在各目标列上一轮结束后接纳下一轮，避免并发写坏历史；可选择仅向一个已完成列继续，其他列停留在原节点并显示进度差异。
- 每列可以单独停止或重试，失败列不清除其他列结果。批次网络重发不重复创建子请求；主动重新生成是新尝试。重试沿用该列原输入和历史边界；后续想补齐落后列时从明确节点另开组，不自动重放并收费。
- 所有子请求在派发前固定输入，逐个校验模型授权；已知无效选择在开始前提示调整，运行中单个模型失败只影响该列。分别返回运行状态和流式结果，不把它们合成为一条“AI 回答”。

### 3.5 保留满意组合与再次采用

每个已有完整有效回复的模型列都能点击“保留此方案”，无需结束对话、填写评价或先正式布置。没有有效输出的组合仍可保存为工作稿，但不伪称满意结果。名称默认用“作业题目 · 模型名称”，允许教师修改；同一请求重发只保留一次，已保留结果显示“已保留”。

保留内容是所选结果实际使用的题目、要求、完整提示词、单个模型、思考、非秘密生成配置及来源测试节点。即使上方编辑框已经改成另一份提示词，也保存结果所用的旧快照，并在确认区明确展示。各模型使用相同提示词时，也分别保留单模型组合，不保存一个含多个模型的正式配置。

“已保留方案”独立持久保存，可保留多个命名方案，刷新、离开试教或发布作业后仍可找回。“加载继续试教”复制所选方案到试教工作稿；已有未保存输入时先提示保存或放弃，不能直接覆盖。再修改得到新候选，不回写已保留方案；重新保留产生新快照。

“采用到准备稿”可从当前结果列直接操作，也可从已保留列表操作；均先按第 2.3 节核对目标和差异，并显式选择一个组合。保留、加载、采用均不发布作业，不发学生通知，不改变正式模型。正式布置或应用新版仍在作业准备页完成。

## 4. 学生开始后怎样修改提示词

### 4.1 教师操作

1. 在作业“设置 → AI 辅导”看到当前生效版本、模型、最近更新时间和试教事实。
2. 点击“调整辅导方案”，从生效版本建立编辑草稿。页面始终区分“正在使用”和“修改草稿”。自动保存草稿不改变学生体验。
3. 修改完整提示词；如需要，也可更换模型或思考，使用相同版本流程。
4. 在试教页调整输入、同时比较模型；可保留多个满意组合，再选一个采用到本次 AI 准备稿。建议既检查初读，又从已有测试对话继续，验证旧反馈存在时的表现；不把这些检查强制成发布关卡。题目要求在试教页的变化仅属测试情境，按第 2.3 节处理与正式任务的差异。
5. 点击“应用新版本”，展示与当前版的差异、模型／思考变化、试教覆盖，以及生效说明。填写简短的“调整说明”，作为教师记录和学生可见说明的来源。
6. 应用成功生成 v2，并显示“已应用，之后的新交流使用新设置”。草稿保存、试教、应用必须是三个不同动作。

第一版固定一种作用范围：本作业所有学生之后的新请求。不开“只对新学生生效”、按个人灰度或定时切换，以免同一作业出现难以解释的配置分组。多个班级对应不同作业，更新只影响当前作业；不偷偷同步其他班级副本。

回退同样通过发布新版本完成：选择历史版本的内容生成草稿，应用后形成 v3。不得把当前指针直接倒回并抹去 v2 的发生事实。

### 4.2 生效边界

“新请求”指服务端完成权限与状态校验、在与配置发布共用的锁下捕获配置并建立调用记录的请求。按这个时点确定版本，不按浏览器点击时间、模型开始吐字时间或完成时间判断。

| 应用新版本时的状态 | 处理 |
| --- | --- |
| 学生尚未确认初稿 | 之后初读使用新版本 |
| 学生已有历史对话，当前空闲 | 下一次交流或复看使用新版本，保留历史 |
| 旧版本请求已被服务端接纳，正在生成或重试 | 该次调用及其内部重试始终使用旧快照，回复标记旧版本；下一次新请求用新版 |
| 页面尚未刷新，仍显示旧模型 | 服务端按最新生效配置调用并返回实际摘要，前端同步；不相信客户端模型值 |
| 已提交但按原规则仍可修改 | 旧提交快照不动；后续合法交流用新版，重交形成新的冻结证据 |
| 已批改、已过有效截止等不可写状态 | 仍按原规则只读；发布新提示词不解锁作业，也不触发模型 |
| 同时存在学生保存、提交和教师切换 | 通过既有作业／会话锁与版本检查确定次序；不能把同一调用的提示词取自 v1、模型取自 v2 |

示例：20:00:00 请求 A 已捕获 v1；20:00:02 教师应用 v2；20:00:05 A 返回，仍记录 v1；20:00:08 请求 B 被接纳，使用 v2。整个过程不主动打断 A、不删除消息、不重置初稿。

### 4.3 历史对话和学生提示

- 每次新调用只装配当前生效版本的教学 system 内容；旧 system 不通过历史消息再次混入。
- 旧的学生和助手交流保留为历史事实，不能从真实记录中删掉或改写。旧助手说法不是新版本的教学指令；必要的版本边界说明属于流程元信息，不附加新的教学偏好。
- 保留当前稿只注入一次、不自动附旧稿、不按关键词推断复看的最新规则。更新提示词不重新运行初读，不自动发送消息，不清空持续对话。
- 学生在下一次进入或交流时看到轻量提示：“老师更新了 AI 辅导方式，接下来的交流将使用新设置。已有内容保留。”可查看教师调整说明。该提示不计作学生提问，不伪造成 AI 回复。
- 教师过程回放显示每条反馈实际使用的提示词版本和模型；同一次提交可能跨多个版本，不能用提交时最新提示词代表所有历史调用。
- 新提示词不能保证模型完全摆脱旧回答的影响。因此中途切换测试保留历史，并把这种影响作为老师需要观察的教学效果。

## 5. 试教与正式使用保持一致的验收定义

相同业务输入经过相同核心执行流程：作业类型、题目要求、完整提示词、已保存当前稿件、有效对话历史、阶段、模型、思考、生成参数、输出处理和学生可见渲染均遵循同一套逻辑。多模型比较只是调度多个隔离的试教会话，每一列都使用该共享服务。允许认证主体和存储目的地不同，不允许教师账号的个人提示词、记忆、知识库或额外工具进入模拟学生的请求。

不能把“同一接口”当作充分证明，也不能仅复用提示词字符串。必须核对供应商请求发送前的最终消息及有效参数；初读的 JSON 输出处理、格式失败重试、流式交流、保存改稿后继续交流与重试都在范围内。试教移除整段复看入口不改变学生正式页已有功能，也不影响其底层共享执行。模型生成不保证逐字相同，验收比较请求和处理规则，不要求两次真实回答文字相等。

### 5.1 三类标识

| 标识 | 用途和内容 |
| --- | --- |
| 配置指纹 | 类型、题目和要求、完整提示词、模型绑定、有效生成配置、执行规则版本；判断某次试教是否仍对应当前配置 |
| 样例指纹 | 确认初稿、当前稿、历史与阶段；区分同配置下不同测试情境，不为了计算指纹自动附旧稿 |
| 调用记录 | 本次采用的业务版本、服务端最终请求快照、实际模型与参数、响应及校验结果；解释实际发生了什么 |

班级、截止、评分、反思在当前段落论证模型上下文之外，不使 AI 配置指纹变化；这些字段变化仍要求更新提交预览。若以后把某字段加入 AI 上下文，必须同时加入指纹和一致性验证。

试教覆盖情况由服务端按匹配指纹与成功完成的阶段推导。只做了中途切换测试不能声称新版初读已测试。修改提示词、模型、思考、题目要求，或本地可检测的模型运行配置／执行规则变化后，旧测试保留，当前提示变为需要重新试教。

模型名称背后的服务商权重升级可能不可检测；平台只能记录可获得的模型版本／响应元信息。不要宣传“固定模型名即可永久复现”。

### 5.2 记录与可查看范围

每次调用至少记录：调用 id、阶段、辅导版本、题目要求版本、稿件快照／版本、历史引用或实际消息快照、配置指纹、模型 id 与底模解析信息、请求与有效思考、有效生成参数、执行规则版本、开始与完成时间、结果状态。供应商有返回时记录请求标识、用量等；无数据时留空。

格式校验重试与暂时性错误重试沿用同一配置快照并保留尝试记录。模型完成前释放数据库事务。不能在重试途中重新读取最新提示词或全局模型选择。

试教页移除“调用记录”“本次 AI 收到的内容”、原始输出及参数调试展示，日常对比只呈现学生会看到的反馈和教师输入配置。服务端仍保留定位失败、幂等、模型归属和版本追溯所需的实际请求证据，自动化验收在供应商边界核对；不新增面向教师的审计页面作为替代。密钥、认证头、内部凭据不得落入快照或页面。正式提交的冻结证据及教师已有过程回放保持原边界，不因精简试教界面而删除。

## 6. 后端结构与数据设计

字段与文件名可按实施时现有约定调整，职责与不变量必须保留。业务逻辑放在 `services/education/`，路由负责身份、资源权限、严格输入和事务边界。

### 6.1 建议实体

| 实体 | 必要信息 | 不变量 |
| --- | --- | --- |
| 作业准备稿 `TeachingPreparation` | owner、用途 `create_assignment/update_ai`、可选 assignment_id、严格类型 payload、草稿 revision、时间、发布结果关联 | 教师私有；新建用途保存完整作业草稿，更新用途只保存 AI 候选和所依据的作业配置版本；不能污染正式表 |
| 试教工作稿 `TeachingTrialDraft`（拟新增） | owner、目标准备稿、可编辑题目／要求／完整提示词、模型及思考候选列表、样稿、revision | 可恢复；与准备稿、生效作业及运行快照分离；保存不启动调用、不自动采用 |
| 作业辅导版本 `AssignmentAiRevision` | assignment_id、递增 revision、prompt、模型绑定及非秘密参数快照、思考、模板来源、作者、调整说明、时间、相关试教依据 | 追加后不可修改；同一作业版本唯一；正文提示词是运行时唯一教学来源 |
| 对比组 `TeachingTrialComparison`（拟新增） | owner、工作稿 revision、共用输入快照、来源节点、1—3 个子会话、批次幂等键 | 每列独立状态与模型绑定，不混合历史；不以批次统一成败覆盖各列实际结果 |
| 试教会话 `TeachingTrialSession` | owner、准备稿／对比组关联、单模型配置快照、起始样稿／历史、来源试教节点、会话状态 | 测试配置不可覆盖；新方案建立新会话，支持从已有试教节点继续；新版不再接受教师评价字段 |
| 试教过程记录 `TeachingTrialEvent` | 会话序号、操作／稿件版本、调用记录、响应、重试、状态、时间 | 有序、可回放；去重请求与主动重新测试分开；不进入正式教学统计 |
| 已保留方案 `SavedTeachingPlan`（拟新增） | owner、名称、题目／要求、完整提示词、单模型绑定／思考／非秘密参数、来源测试节点、配置指纹、时间 | 内容为不可变私有快照；不是原工作稿的动态引用；可再次加载或采用，不具备发布副作用 |

正式 Assignment 增加当前辅导版本引用；段落论证正式请求必须解析到合法版本。`config_revision` 继续承担整个作业的并发修改检测，与 AI 的递增版本各司其职。更新辅导时同步推进作业配置 revision。

管理员 `teaching_configuration` 继续作为推荐模板来源。现有作业 `teaching_config` 中的模板信息可保留为来源快照，但对本功能覆盖类型，不再从里面取运行时提示词，也不允许与 `AssignmentAiRevision.prompt` 两处独立编辑。模板版本与作业辅导版本须使用不同字段名。

目标类型的 `model_params` 也不再与新版模型／思考配置各自生效；保留字段只能服务其他类型或作为明确的来源记录。原 `adopt_latest_teaching_config` 对目标类型应改为取模板进入候选草稿的操作，不能绕过新版发布流程直接改变实际教学提示词。

正式阅读和聊天沿用各自现有存储，扩展实际调用上下文，不另建第二套正式对话历史。提交时冻结实际使用的全部辅导版本和已完成调用上下文；不要只存一个“最后版本”。证据 schema 变更按仓库规则提升版本及严格类型，不修改已冻结历史正文与判断。

### 6.2 共享执行服务

建议提取一个教学运行服务，职责包括：解析已经授权的运行配置、捕获稿件和上下文、构造阶段请求、执行模型调用、校验／呈现结果、生成调用证据。正式与试教入口使用不同的资源和保存适配器，共享上述逻辑。

- 正式适配器验证学生、作业、所属会话、截止及定稿状态，从真实保存稿和当前生效版本捕获输入。
- 试教适配器验证教师、准备稿／试教所有权和类型权限，从隔离测试资源捕获输入，使用学生能力范围构造上下文。
- 对比调度层只负责冻结共用输入、派发子会话和汇总状态；每列仍调用共享教学运行服务。不同模型上下文及流式通道隔离，不引入新的教学提示词拼装路径。
- 不创建假学生、假班级或隐藏的真实作业来试教；不使用教师个人写作会话模拟学生；不把真实写入接口加一个客户端 `is_test` 参数当作隔离措施。
- 复用阶段登记 `ai_steps.py`，试教是运行场景，不另造一套平行教学阶段。初读与交流可保留各自响应形式，模型和教学配置解析必须统一。
- 当前普通聊天入口在教学上下文解析前已有模型权限检查和底模回落逻辑。实施时必须调整执行顺序：先识别可信的作业上下文，再解析其绑定模型与授权；避免学生没有普通聊天模型权限时先被错误拒绝，或先被切换到底模回落配置。
- 不用宽泛的 `bypass_filter=True` 代替全部权限判断。任务限定的模型授权须绑定真实资源；普通聊天和其他作业不能通过伪造 assignment、folder、trial 或 revision id 获取它。
- 模型默认系统提示、知识库、技能和自动工具的现有隔离继续有效。若全局过滤器必须运行，两种场景必须采用相同处理与能力，最终请求快照应在其处理后捕获；不能因为教师角色不同产生隐藏的上下文差异。

### 6.3 权限与模型绑定

增加明确的教学模型可用清单及推荐模型，复用现有模型实体与管理员配置入口，不建立第二套连接和密钥管理。服务端在试教、发布和实际调用时检查教学授权、模型存在与绑定有效性；安全撤权即时生效，但不自动选择替代模型。

区分“教师创建某类型作业的授权”和“模型教学使用授权”。前者按当前规则只约束新建、复制与跨类型切换；撤销后不剥夺教师管理既有作业、为其调整方案及试教的能力，也不停止已有学生作业。后者撤销才阻止相应模型的后续调用。现有作业调整草稿的试教凭该作业管理权限，新建准备稿的试教检查类型创建权限。

捕获非秘密的模型路由标识、底模、能力与生成配置，避免运行时重新合并全局参数而覆盖已发布设置。连接凭据保持在原管理位置，仅在发送时读取。模型连接或适配规则变化需要可检测的配置版本／指纹，旧试教不得继续显示为当前配置的验证依据。

对比组、每个子会话、工作稿和已保留方案均检查本人所有权；已有作业入口还检查作业管理权，不能凭对比组 id 或已保留方案 id 越权读取。已保留方案可以本人跨准备稿取用，但在目标用途重新检查类型和模型权限。模型后来不可用时仍可查看原方案，不能据旧的成功结果绕过新运行或发布时的授权检查。

### 6.4 并发与缓存

采用既有 `lock_assignment` 顺序串行化发布、调用配置捕获、基线和提交等临界操作；每个会话的新调用也须避免并发交叉修改历史。完整调用快照在释放锁前固定，长时间模型生成不占用作业写事务。

结果写回以原调用 id、捕获快照及会话操作序号为依据，不能仅因当前生效版本已升到 v2 就拒绝合法 v1 结果或给它改标 v2。继续遵守现有停止、失败、定稿和冻结提交的边界，迟到回复不能追加到已经冻结的提交证据。

教师保存、应用和多标签页发布携带期望草稿及作业版本；冲突返回 409 并保留输入，禁止旧页面覆盖。发布操作带幂等键；多人或多标签同时应用，只能有一个按旧版本成功。

阅读去重键必须包含有效 AI 配置、阶段、实际稿件和相关上下文。同稿件切换 v2 不得读到 v1 缓存。已被接纳的 v1 请求在 v2 发布后的内部重试不另选版本；用户之后主动重试是新的调用，可使用 v2，并保留原失败记录。

对比组创建与子会话登记在短事务内完成，随后并行派发，不持有数据库事务等待模型。一组每个目标列有独立请求键和序号，整组及单列网络重发均去重；刷新后从持久状态恢复已有输出，不重新发起调用。多标签页编辑工作稿、保留和采用也检查各自 revision／幂等键；长时间运行的列不能阻塞查看或保留已完成列。

## 7. 接口行为建议

下表说明下一轮接口职责，包含已有能力和拟新增调整，不表示列出的 URL 已全部实现。沿用当前准备稿 `/publish`、`/adopt` 等实际路由组织，不恢复旧的直接创建段落论证作业路径；不得省略权限、版本和幂等行为。

| 操作 | 建议入口或既有入口调整 | 关键要求 |
| --- | --- | --- |
