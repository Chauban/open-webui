# DeepSeek low / 官方 high 教学对照

## 结论与适用范围

2026-11-07 用户要求比较两档，并表达优先使用 high 的偏好。本轮结果支持优先试用 **DeepSeek 官方 `high`**：主要论证判断与 low 持平，在一个来源核对细节上更稳定，本轮也没有更慢。没有足够证据声称 high 的整体准确率显著更高，或在长稿、高峰与课堂并发下始终更快。

平台档位映射为「低→low、中→high、高→max」。这里比较的是官方 low 与 high，**未测试 max**。若正式采用本轮 high 条件，当前平台应显式选择「中」；「模型默认」目前也对应官方 high，但会随服务商默认改变。

本轮只新增对照脚本与验证记录；未调整本地或正式实例的教学配置，未部署。

## 方法

- 北京时间 18:28—18:31 完成主试验，随后完成两次格式修正调用。实际响应模型均为 `deepseek-flash`。
- 复用此前网站试用的虚构课堂材料、v4 教学提示词和初读请求。四种初读为证据不足、推理跳跃、论证成立、仍有问题的稿件；每种每档独立调用三次，共 24 次。
- 再做有效改稿、未改稿、自主结束三种对话，每种每档两次，共 12 次。对话历史固定，使用保存的教学 system、初读反馈与稿件，并复用当前代码的正文附加函数；结束场景还使用相同的历史复看回复。这是受控对话重放，并非逐档重新生成整段历史。
- 主试验共 36 次，每档 18 次。每个场景两档输入的 SHA-256 完全相同，只有 `reasoning_effort` 不同；明确开启思考，不指定温度或 token 上限。固定种子打乱顺序，最多四个请求并行，单次超时 240 秒，不自动重试。
- 只读隔离 SQLite 配置取得现有官方连接，在本机直接调用服务商；不经过网站登录、保存、提交和中间件。初读使用已保存的真实网站请求，不把此次重放称为网站端到端验收。
- 内容由本次执行助手逐条检查，知道档位，不是盲评或独立教师评分。结构与引文校验复用当前应用的 Pydantic 模型和引文定位函数；凭稿件可定位，不等于该引文的外部来源已经核实。
- 主试验未包含文献综述、长文、多模型或课堂负载；也没有全站前后端回归。

## 结果

以下耗时和 token 均为主试验，不含后续两次格式修正。

| 项目 | low | 官方 high |
| --- | ---: | ---: |
| HTTP 成功 | 18/18 | 18/18 |
| 有问题初稿识别至少一处核心缺口（人工检查原始内容） | 9/9 | 9/9 |
| 成立初稿不制造实质问题 | 3/3 | 3/3 |
| 未改稿如实说明没有变化 | 2/2 | 2/2 |
| 自主结束时未要求新任务或阻止提交 | 2/2 | 2/2 |
| 有效改稿中发现“走廊”未见于给定材料 | 1/2 | 2/2 |
| 初读首发结构及引文校验通过 | 11/12 | 11/12 |
| 全部调用耗时中位数 | 13.96 秒 | 13.36 秒 |
| 全部调用平均耗时 | 18.72 秒 | 13.48 秒 |
| 最长调用 | 57.69 秒 | 37.20 秒 |

初读单独统计的耗时中位数为 low 15.64 秒、high 13.84 秒。本轮 high 用时与 token 更少，是实际观察，不构成档位越高越省时或越省钱的规律；样本、请求排队、缓存和生成随机性均会影响结果。未按价格换算费用。

### 内容差异及仍存在的缺陷

1. **核心判断基本持平。** 两档都抓住了“三个人觉得方便不能推出多数学生成绩提高”“一次邀请不能证明公共性质促成自主性”等主要缺口。9/9 只表示识别了至少一个核心问题，不表示逐项找全，也不表示每句话均准确。
2. **成立样本没有被强行挑错。** 两档三次初读均 `focus=[]`，未改稿的两次复看也未虚构修改或新增任务。
3. **high 的一个具体优势是来源核对。** 有效改稿保留了“无需再在宿舍走廊寻找讨论空间”，但任务材料 A 只说小组讨论更方便。high 两次都要求核对这项细节，low 仅一次发现，另一次还称它“材料直接支持”。这是合理的来源核查，不应算作无故挑刺。
4. **来源核对仍不稳定。** 在同一材料的初读场景，两档都各有两次肯定“走廊”细节而未核对任务材料。不能因为 high 在复看中表现较好就声称已解决来源真实性问题。
5. **表达仍可改进。** 两档的部分初读使用“作者认为”而非直接对学生说话；low 有一条把“老师未分配排序工作”称为“可能削弱判断的材料”，与同条后文的解释不一致。两档的结束回复都可能简短重申原疑问，但未要求继续修改。
6. **结构错误两档都有。** low 的 `initial-3 / repetition=2` 与 high 的 `initial-3 / repetition=3` 都把额外 `focus` 放入 observation 对象。应用严格校验会拒绝，不能把 HTTP 200 当成学生已收到有效初读。另有个别 JSON 重复同名 `focus` 字段，现有解析器采用末值；这不等于模型输出始终规范。

## 格式修正复核

对两条无效输出分别追加应用现有的纠错提示与相同 JSON schema，仍保持原档位，各调用一次：

- low：3.42 秒后结构和引文校验通过，核心判断保持。
- high：2.84 秒后结构和引文校验通过，核心判断保持。

因此两档 12 次初读在应用同等的一次格式修正后均可通过。累计实际调用 38 次。此处复核的是服务商对纠错消息的响应，未实际触发网站重试流程。原始错误完整保留，没有以修正结果覆盖。
