# 图文稿件统一编辑与 Word 下载优化方案

日期：2026-11-09。状态：本地第一版实现与验证完成；未经授权不得部署 HIT 或其他实例。

## 1. 问题与目标

目前文档导入把正文转换成纯文本，将图片等移入“随附材料”。初稿确认使用 textarea，确认后才切换富文本编辑器，造成格式丢失、图文割裂和前后编辑能力不一致。学生端醒目的“下载原文件”容易被误认为下载修改后的稿件。

目标是让同一份连续的结构化图文稿件贯穿导入、初稿核对、确认、修改、提交、教师查看及 Word 导出。原件、当前稿、提交稿明确区分；在线修改不回写原件。

HIT 现状核实：2026-11-09 只读检查实际部署及构建版本 `7910eae6a`。教师批改详情的稿件上方已有“文件名 · 随附材料”折叠区，展开可下载原文件，入口使用该轮 `stats_json.materials` 并校验教师提交权限。没有材料记录的旧提交不显示。此核查未代教师登录点击下载，也未修改线上数据。

## 2. 范围与排版原则

- 适用于从零写作、文献综述修订和段落论证修订。
- Word、PDF、独立图片、TXT、Markdown 统一上传入口。
- 编辑区连续排版，不模拟纸张分页，不维护原文页面坐标。
- 保留阅读顺序、段落、标题、列表、链接、基本表格、图注、脚注及引用关系；尽量保留加粗、斜体、下划线、上下标等有意义的格式。
- 图片采用正文独立块，上下排列，居中、保持纵横比、可调整显示宽度。不提供文字环绕、任意坐标拖放和左右浮动排版。
- “原位置”指阅读顺序及上下文关系。浮动图片放到对应段落附近；图注与图片关联，移动时不失联。
- 原分页与复杂版式通过原件查看；在线稿件和新 Word 不承诺复刻原件版式或页数。

## 3. 各格式导入

| 输入 | 处理 |
| --- | --- |
| DOCX | 解析结构、基本格式、表格、图片、图注、脚注和尾注，按阅读顺序组成稿件 |
| 旧 DOC | 能读取的内容明确呈现；不能可靠解析的对象提示转换 DOCX/PDF，不静默丢弃 |
| 原生文字 PDF | 恢复自然段、阅读顺序及图文关系，不按每个视觉行机械断段 |
| 扫描 PDF、照片 | 原页作为图片保留；开识图后提供识别结果，学生明确确认后可转入正文 |
| 混合 PDF | 分别处理文字、图片及扫描区域，避免同一文字重复插入 |
| TXT、Markdown | 转为正文与支持的格式结构 |
| 复杂或不支持对象 | 能可靠预览时保留图像；否则在对应位置提示并保留原件核对入口 |

PDF 多栏和复杂对象不承诺完全还原。不可靠的阅读顺序需要可核对和调整；无法读取要明确提示。所有独立上传照片保存原件及顺序，不只留下转录文字。既有文件容量与数量限制继续执行。

## 4. 统一编辑器与初稿确认

- 确认前后共用富文本编辑器，支持上传、粘贴、文字选择浮动工具栏及撤销/重做。
- 工具栏优先提供标题、加粗、斜体、下划线、列表、引用、链接；图片支持查看大图、宽度、移动和删除。
- 稿件单一主要滚动区，初稿确认栏固定在底部；去除正文 textarea 与附件表单的嵌套滚动。
- 确认只固定修改起点，不重新转换内容，不丢格式和图片。
- 确认前核对形成最终初稿，不误算为确认后的修订成果。刷新后恢复已保存的待确认稿/正式稿。
- 保留至少 200 个非空白字符的初稿要求。图片、占位符、未转入正文的识别结果不计入；正文不足显示具体原因和下一步操作。

## 5. AI 识图与材料上下文

- 开关不影响上传、图文显示、原件保存、教师查看或 Word 导出。
- 关闭时不调识图、不自动传入图片或图片识别附件；仍读取原生文字及学生已写入正文的内容。
- 开启时，识别结果在对应图片旁按需查看和校对，默认折叠；不自动替换原图或插入正文。
- 已导入未识别图片可显式识别，开关变化不后台重读，普通聊天不重复识别。
- 学生主动将识别文字转入正文后保留来源标识；随后关闭识图不删除正文或改写历史。
- 图片识别失败保留原图和具体提示；有足够正文时不阻止确认/提交。
- 当前稿移动、删除和替换图片后，后续 AI 请求使用对应位置和当前资源，不继续附带已删除材料。
- 区分原图、自动识别文字、学生校订文字；识别文字不自动算作学生键入正文。
- 不追加隐形辅导评价规则，不修改教师维护的辅导提示词。

## 6. 提交、教师查看与版本

- 提交固定完整结构、格式、图片引用及顺序、宽度、图注、表格、脚注和材料状态。
- 学生提交详情、教师批改页、该轮 Word 导出读取同一版本；后续改稿和开关变化不改写旧提交。
- 不同屏幕可改变换行与显示尺寸，但不改变顺序。
- 图片移动/删除/替换进入版本变化记录；初稿、过程稿、提交稿使用各自的资源和结构，不能历史文字配最新图片。
- 教师默认直接阅读完整提交稿，图片可放大；原件为核对资料，保留在清楚命名的“上传原件”入口。
- 教师可“下载已提交稿（Word）”或下载对应原件；批改不直接修改学生正文。
- 来源高亮和版本对照不能丢掉非文字节点。所有查看/下载继续校验归属和提交权限。

## 7. 学生下载与 Word 输出

- 学生主编辑区移除常驻“下载原文件”，原件放在上传记录/更多中，标明不包含在线修改。
- 修改时“下载当前稿（Word）”；提交详情“下载已提交稿（Word）”。待确认稿可导出，但不触发确认或提交。
- 第一版提供 DOCX；PDF 导出以后再做，Markdown 不作为学生默认下载格式。
- 新 Word 从结构化稿件生成，包含基本格式、图片、图注、表格和脚注。图片嵌入文件，不依赖临时链接或登录。
- 默认不附加聊天、AI 反馈、识别详情、过程记录或教师评分。
- 当前稿先保存，再导出明确版本；失败时不悄悄下载旧稿。提交稿只用选定提交版本。
- 文件名区分当前稿、提交稿和轮次。缺图、保存失败或导出失败明确反馈，不以不完整文件冒充成功。

## 8. 工程边界与实施顺序

结构化稿件为共同依据，原件/图片作为独立不可变资源，通过稳定标识引用；文字投影服务于字数、文本比较和模型输入。需要严格校验文档节点、资源归属、图片宽度和输入大小。不要通过多个内容字段各自编辑造成分歧。

1. 文档结构、资源引用及文字投影。
2. 各格式导入、待确认稿持久化与统一编辑器。
3. 跟随当前稿的识图结果和模型上下文。
4. 冻结初稿/版本/提交与师生查看。
5. 当前稿/提交稿的 Word 下载。
6. 回归、两种数据库（涉及 SQL/迁移时）、类型检查、构建与浏览器验收。

整条链路完成验收才算本次优化完成。历史已丢失的排版不猜补，不增加兼容接口或自动修复机制，不自动清理真实作业。可能涉及的历史数据处置单独列入上线计划。实现后同步 PRD、Userflow、架构说明、任务清单。本轮只本地开发测试，不部署 HIT。

不包含：自由排版、精确分页、多人协作、批量下载、Word 双向同步、PDF 导出。

## 9. 验收矩阵

- [x] Word 多图、图注、表格、脚注和基本格式完整，确认前后不变。
- [x] 原生 PDF、扫描 PDF、混合 PDF、多栏样例不静默漏项或重复正文。
- [x] 开关不改变图文显示；关闭时无视觉调用和自动识别附件。
- [x] 纯图片/不足 200 字解释清楚；识别失败不丢原图。
- [x] 图片移动、删除、替换、撤销后的保存、模型上下文、提交、导出一致。
- [x] 已保存稿件刷新/身份权限回读、桌面和手机保持结构（真实账号重新登录未另做浏览器验收）。
- [x] 旧提交和教师导出不受后续修改影响。
- [x] Word 文件离线读取、内嵌图像/表格/脚注及版本一致性验证通过（未做桌面 Word 全版式验收）。
- [x] 越权用户不能访问原件、图片或稿件下载。
- [x] 保存、图片加载、导出失败不静默降级为成功。

### 本地实现结果

已完成结构化图文导入、统一编辑器、确认前暂存、初稿/过程/提交的完整图文保存、师生只读展示、原件查看与下载，以及当前稿和提交稿的 DOCX 下载。没有新增数据库迁移，复用现有 JSON 字段；没有部署 HIT、提交 Git 或清理真实作业。

关键实现位于 `services/education/writing_document.py`、`document_layout.py`、`document_workflow.py`，前端共用 `WritingEditor.svelte` 和图文节点扩展。已删除旧的分项材料表单。图片采用上下排列；识别结果按需展开，明确插入才成为正文。图片和图注共同移动，旧版本引用的资源继续保留。

补充的边界处理包括：确认暂存稿及下载提交稿时核对所见版本；图片启用与正文保存同一事务，修复 SQLite 连接互锁；图片剪贴板先走导入核对，不提前把后续键入记为粘贴；混合剪贴板缺失图文关系时提示上传原文档；失败重读不冒用旧识别结果；扫描页已有文字层时不重复插入；Word 导出保留列表层级/编号起点，长图缩放到纸面内。

### 验证范围与后续使用

- 浏览器检查是组件隔离样例，后端流程与权限由真实 API/数据库集成测试覆盖；未操作 HIT 真实师生账号或代学生提交。
