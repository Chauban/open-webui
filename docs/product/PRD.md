## 1. 产品定位、目标与用户

Right Write 是基于 Open WebUI v0.11.2 的大学写作教学平台，服务教师组织任务、学生与 AI 协同写作、教师基于过程证据评阅和复盘的完整教学闭环。

适用对象是大学本科生与任课教师，任务包括学术论证写作、课程论文、文献评析、文献综述、研究计划和个人陈述。产品文案与样例使用大学课程语境。

| 用户   | 核心任务                                                   |
| ------ | ---------------------------------------------------------- |
| 教师   | 建班、布置作业、追踪提交、批改反馈、查看学生成长与教学分析 |
| 学生   | 加入课程班、写作与对话、提交反思、查看反馈、维护成长目标   |
| 管理员 | 管理平台身份和权限、模型及教学配置、跨教师调班和教研导出   |

产品目标是让师生能够独立完成任务与反馈循环，使正文、对话、修改和反思可回看。平台以教学任务与证据支持教师判断，不自动给出作弊结论或替代教师评分。

当前范围包含教学身份、班级、作业、写作工作区、提交批改、成长画像及教研导出。家长端、复杂排课、全量 LMS 替代和教务结算不属于当前核心范围。

## 2. 身份、班籍与权限

- 平台角色 `user.role` 与教学身份分开。教师和学生身份由 `education-teacher`、`education-student` 用户组承载；平台管理员通过管理员角色获权。
- 学生注册必须提交有效班级邀请码；正常配置下校验通过后入班，pending 学生提升为 user。教师注册不要求邀请码，其平台角色跟随实例默认新用户角色；默认 pending 时需管理员批准，已经为 user 时不再等待审批。空库首位管理员的创建适用其专用规则。
- 一个学生只能加入一个班；教师可管理多个本人班级。
- 教师可在本人班级之间转移学生；跨教师调班由管理员处理。既有提交保留在原班，成长画像跟随学生。
- 教师只能访问权限范围内的班级、作业和提交；个人写作空间对教师不可见。
- 学生的任何对话禁止读写记忆，作业对话还禁用检索聊天记录与记忆的内置工具。
- 作业写作区里学生不能改模型参数、不能加自己的系统提示，无论权限怎么配；对话按老师的作业说明和管理员的模型设定进行。唯一例外是老师允许时学生可以关闭辅导对话的思考（见 6.3）。作业项目文件夹由平台维护，学生不能改写或伪造。其余对话按 `chat.controls` / `chat.params` / `chat.system_prompt` 权限由服务端执行。
- 仍拥有班级的教师不能撤销教学身份。当前没有班级所有权转交工作流，不能把学生调班接口当成班级转交能力。

## 3. 页面与工作流程

教师顶栏为“总览 / 班级 / 作业 / 批改”。班级子标签为“总览 / 学生”，作业子标签为“概况 / 提交与批改 / 本次分析 / 设置”。班级中的作业入口进入全局作业列表并带班级筛选，不维护独立班级作业子页面。

| 使用场景     | 当前入口与结果                                                           |
| ------------ | ------------------------------------------------------------------------ |
| 教师日常处理 | `/teacher` 展示待批改、临近截止、逾期未交、跟进作业和最近提交            |
| 教师批改队列 | `/teacher/review` 与作业内提交页共用 `SubmissionQueue`，使用教师队列接口 |
| 学生作业写作 | `/me/writing` 查找任务，`/assignments/[assignmentId]/write` 编辑和提交   |
| 学生个人写作 | 2026-11-07 起暂时关闭；既有内容保留，学生访问返回 403                |
| 长期成长     | 学生 `/me/writing/growth`，教师班级下学生详情页                          |
| 教研导出     | 管理员 `/admin/education`                                                |

教师流程为建班、管理学生、创建作业、跟进提交、评阅、反馈和复盘。学生流程由作业形式决定：从零写作直接进入编辑；修订初稿先确认基线，再进行诊断、修改、反思和提交。只有实例开启退回且教师执行退回后，才开放下一轮重交。

## 4. 班级管理与导出

- 班级创建后生成邀请码，教师可重新生成。
- 学生页支持添加已注册学生、按用户 ID 或邮箱批量导入、批量移除及在本人班级之间转移。导入返回成功、已存在和失败反馈，不创建不存在的学生账号。
- 班级总览显示作业和学生的提交、批改进度，可进一步查看未提交学生。
- 教师可导出班级 CSV，包含学生姓名、邮箱、作业标题、提交时间、批改状态、分数和总评。该导出服务班级教学管理，允许身份明文，不是管理员教研假名化导出。
- 当前已提供 CSV；旧任务中的“CSV 或 XLSX”需求已由 CSV 满足，不能据此自动新增 XLSX 待办。

## 5. 作业配置与编辑边界

作业包含题目、要求、班级、截止时间、满分、评分维度、作业形式、辅导档位、反思题和适用的读者试读配置。

- 向多个本人班级发布时为各班建立对应作业；支持从已有作业复制创建新作业。
- 列表支持班级、关键词和派生状态筛选，并按截止、待批改或最近活动排序。“进行中 / 已截止 / 待批改”是列表展示条件，不是作业数据库状态。
- 作业归档字段、接口和页面操作已删除，不恢复 `status`、`archived_at` 或归档入口。
- 教师可编辑题目、要求和截止时间；满分及评分维度在首次提交后锁定。
- 已有初稿基线或已有提交时作业形式锁定，前后端均校验。
- 分项模式中维度满分之和等于作业满分，批改总分等于分项和；仅总分模式不要求虚构分项。首次提交后评分模式也锁定。
- 对无提交且无学生写作会话的作业提供删除；有业务记录时后端拒绝删除，不以恢复归档替代此边界。
- 教师可催交、为单个学生设置或撤销延期。有效截止时间优先使用个人延期，再使用适用的退回截止，最后使用作业截止。

## 6. 作业形式与 AI 辅导

`task_mode` 集中登记为 `from_scratch`（从零写作）、`revise_draft`（修订初稿：文献综述）、`revise_argument`（修订初稿：段落论证）。管理员逐教师设置可布置类型及默认类型，可全部取消；创建、复制与跨类型更新都校验授权，撤权不影响管理既有作业。新教师默认仅从零写作，段落论证必须显式授权。

三类分别维护版本化教学标准、完整辅导提示词、默认说明、默认评分和默认反思。作业保存教学配置快照；尚无基线与提交时可主动采用最新版本，开始后固定。评分模式支持分项与仅总分总评；分项可改名、改分和增删，单项也可。评分设置和反思不进入修订模型上下文。

### 6.1 从零写作

学生直接进入正文编辑与辅导对话。教师可按评分维度配置提交前 AI 读者试读，未开启时不进入该环节。学生可在编辑器里导入 Word / 文本 / PDF 文件或照片，预览核对后插入或替换正文；导入的文字记为外部粘贴，教师在过程时间线上看得到来自导入。

### 6.2 两类自主修订作业

- 保留文件/图片导入、核对及至少 200 个非空白字符的初稿确认，基线冻结后可直接编辑、讨论与提交。导入格式说明按需悬停、聚焦或点击查看；确认栏固定在面板底部，内容单独滚动。AI 阅读期间显示等待动画，不影响编辑与提交。
- 左侧为连续对话，初读、历史阅读和聊天按时间展示，已有内容不折叠替换；右侧保持稿件编辑与提交。删除讨论跳转、展开完整反馈及独立阅读历史入口，来源稿件收进对应阅读消息的更多菜单。
- 初次阅读使用确认稿和独立教学标准，一句话复述核心判断，具体肯定成立之处，优先一处、必要时两处疑问及动作；以直接对学生说话的方式呈现，不再拆成摘要和完整反馈。
- 稿件相对上次已完成的 AI 阅读发生变化后，输入框附近出现“改好了，请看看”；有消息说明时显示“发送说明，请看修改”。点击后先保存，再把说明与修改请求发送到同一会话，回复追加在末尾。普通发送继续交流；不自动发送、不要求复看才能提交。保存失败保留输入并停止发送。
- 学生无需逐项处理建议，不修改、不采纳、不等待初读成功或不做复看都可正常提交。学生表达结束后，助手停止推进新任务。
- 两类修订使用各自完整提示词，不叠加通用辅导档位，不启用提交前 AI 读者试读；文献综述保留综述标准，段落论证采用课堂批注提炼的读法。
- 作业说明提供题目、材料与完成要求，不得覆盖禁止成段代写、一次一两处和自主结束规则。
- 历史清单按冻结事实只读展示，不补造新版阅读记录。尚未提交可主动撤回初稿重来；重交保留最初基线。

### 6.3 当前正文与辅导档位

发送对话前等待正文保存，最多 5 秒，保存失败时提示学生。后端从最近保存正文注入每轮上下文与改动说明，不依赖静态文件夹提示词或模型自发取稿。

写作过程记录正文版本、来源、编辑操作与对话，AI 插入和带来源标记的复制可以进入正文。作业写作中的来源构成比例不常驻展示，只在工作区只读时显示；个人写作可显示构成。AI 澄清追问问答可作为过程证据回看，回答次数不替代教师对提问或反思质量的评分。

辅导档位为 `socratic / balanced / hands_off`，由管理员维护措辞。实例可关闭档位；关闭后只注入任务说明。诊断与辅导不承担教师的正式评分职责。

教学模块每处调用模型都登记为一个 AI 步骤：辅导对话、初次阅读、修改复看、整段复看、读者试读、初稿图片识别、班级论证归纳。思考档位为模型默认 / 关 / 低 / 中 / 高，平台步骤只由管理员设定，图片识别默认关闭；只有辅导对话的档位可由管理员下放给教师按作业设定，再由教师决定是否允许学生逐轮关闭。各班的通读、试读结果因此可比，试跑中关掉通读的思考会明显增加漏判误判。实际档位在提交时冻存，学生可开关时逐条回复记录；模型未标明支持思考控制时按模型默认。管理员还可为每个平台步骤指定模型：不指定时通读、试读用学生所选模型，班级论证归纳用老师所选模型，图片识别必须指定；指定的模型即使学生或老师在聊天里无权使用也照常调用，被删除时回落并在管理员页提示。辅导对话的模型始终由学生选择。各步骤实际用的模型随轮次冻存，批改页可见。

## 7. 提交、反思与教师批改

- 教师按作业配置单选、多选和文本反思题；必答、可见条件和选项边界由服务端校验。
- 提交冻结作业配置、题目、答案、正文版本、辅导配置，以及已完成的阅读记录或适用的读者试读事实。迟到的模型回复不会改写已交证据。后来修改题目或提示词不改变已交轮次。
- 修订初稿不再询问必然为“是”的 AI 使用题。
- 当前轮未批改时允许截止前修改提交；正式批改后定稿。历史轮保留稿件、反思、批改和差异。
- 正式批改后，服务端同时拒绝自动保存、版本、来源、编辑操作、修订处理与对话生成；超过有效截止时间也禁止写入。退回后，或尚未定稿时获得个人延期，按有效截止规则开放写作；已批改稿不会仅因延期解锁。个人写作不受作业定稿限制。
- 教师查看终稿、来源、对话时间线、版本、相邻轮差异及适用的初稿对比，并保存维度评分、总评和过程质量评分。
- 反思质量仅在本轮有实际回答时由教师给 1—5 分；仅有空选答或无反思时不适用。本轮有实际学生提问才评提问质量，平台自动消息不计入。未评分保持空值，不用反思字数或提问条数生成假分。
- 保存批改须同时匹配查看时的稿件版本和评阅版本；学生重交或另一标签更正后拒绝旧页面覆盖。已发布批改只能保存更正或显式退回，不能降回草稿。每次保存追加评阅事件，正式成绩、画像和导出使用同一已发布版本；未发布草稿不进入成绩。
- `pending / reviewed / returned` 为提交批改状态。退回由 `education.enable_return` 控制，默认关闭；前端隐藏相关操作和统计，后端在关闭时拒绝请求。
- 启用退回时必须填写未来的重交截止时间；学生修改后提交新轮，原轮记录继续保留。
- 作业发布、提交、批改、退回和催交经站内通知形成闭环。

## 8. 提交前 AI 读者试读

辅导助手与读者试读分开呈现。辅导助手提供写作帮助，其内容可经插入或复制进入正文；读者只引用原文提出疑问，让学生自己回应，不代改正文、不预测成绩。

- 教师只对从零写作作业启用试读，设置 2 或 3 轮，并从评分维度选择 1—2 个焦点。
- 提交流程为契约声明、有限回合问答、收尾清单、返回修改或继续提交、反思、提交。
- 回合、顺序和并发状态由服务端约束；学生可跳过，开始前和开始后的跳过均留痕。
- 质疑必须引用原文片段，学生可回看完整往来，清单可定位正文；不在编辑区设置常驻高亮。
- 教师并排查看被引用的原文、学生回应及终稿中的对应内容。片段变化只是一项核查线索，等效修改可能发生在别处，不能自动判断对错。
- 质疑文本与正文快照由服务端冻结；学生回应是学生输入，来源采集的完整度说明与这两类事实应区分解释。
- 不引入 AI 判断“学生是否真正回应了质疑”的结论字段。既有否决继续有效：读者承担提问，教师作评价，避免把可争议判断固化成学生不能答辩的结论。
- 在实例启用退回且作业适用试读时，教师可要求下一轮就退回意见追问，意见在本轮试读开始时冻结。

自适应焦点仍属于待课堂观察的假设，不进入实现排期。应先观察轮转是否足够、学生是否愿意回应、质疑是否落在选定维度；不能借此引入已否决的自动质量判定。

## 9. 本次分析、成长画像与教研

### 9.1 本次分析

提交列表读取教师队列。教师逐份查看来源、编辑突增、对话与修订事实；不在班级或作业层面加总风险，不显示消化度或平均改写率。

作业分析可以聚合读者试读维度与修订初稿的首轮通读处理情况。教师主动触发的未解决论证类型归纳使用输入哈希缓存、最小样本门槛和无直接身份字段的模型输入；只用于教学讲评，不评价班级“好坏”。抽样核对模型问题是否确实落在所选维度，偏离时先调整提示词。

### 9.2 学生成长

教师和学生复用成长画像组件，呈现产出、过程投入、修订深度、AI 协作、教师评分、趋势与轮次进步。成绩保留原分和满分，也提供用于比较的百分比；不能把不同作业满分的原分直接混作同一量纲。

提问与反思质量依赖教师评分，提问数量只作参考。学生可维护成长目标，教师可维护私有观察笔记及修订记录。公式、阈值和内部算法口径信息只在适用的教师视图展示，不把它们作为学生刷数路标。

画像事实证据冻结保存，指标与聚合结果按算法版本形成投影。普通 GET 读取投影，不扫描原始历史或偷偷重算；改算法提升版本，重算走显式入口。首轮过程从声明初稿起算，重交轮从上一轮终稿起算，不把整份初稿当作一次大段突增。

### 9.3 管理员教研导出

按班级和提交时间范围导出 ZIP，包含提交指标、轮次进步、反思题与回答记录及口径说明。学生 ID 使用服务端密钥 HMAC 假名，不导出账号的姓名邮箱字段；不能把假名化误写成彻底匿名化。

指标记录携带算法版本与代码校验和，反思回答的自由文本默认不导出，显式开启 `include_text` 后才带文本；题目快照与选项用于统计。反思记录按提交时冻结的自定义题目输出，已经不使用固定四段反思 schema。空值保持为空，区分未评分、缺失和不适用。

## 10. 管理员实例配置

管理员逐教师维护类型授权与默认类型，并为三种类型分别维护版本化教学配置、默认说明、评分与反思；从零写作保留辅导档位，平台统一维护退回开关、读者试读提示词和各 AI 步骤模型及思考档位。修订核心规则固定在作业快照中，教师评分不进入模型。

已有默认维度、复制作业和复用既有反思题的能力，不等同于已经提供独立评分模板或量纲库。模型可见性、直连、工具权限及角色能力也属于实例配置；排障先检查这些条件，再判断实现缺陷。

## 11. 数据边界与非功能要求

| 数据范围                                       | 责任                                               |
| ---------------------------------------------- | -------------------------------------------------- |
| 班级、成员、作业与个人延期                     | 教学对象、权限与有效截止                           |
| 写作会话、初稿基线、版本、来源、编辑操作与对话 | 正文和过程事实；客户端发生时间与服务端接收时间分开 |
| 阅读记录、历史清单、试读及其回合                         | 本轮诊断、学生处理与回应                           |
| 提交、反思快照、批改与通知                     | 冻结轮次事实、教师反馈和送达                       |
| 画像证据、评阅事件、版本投影和聚合投影         | 不可变事实与可版本化计算结果分离                   |
| 成长目标、教师观察笔记及修订                   | 学生自我管理与教师私有观察                         |

字段、类型和数据库约束以 [数据模型](../../backend/open_webui/models/education.py) 为准，PRD 不复制一份容易漂移的字段清单。实现分层及投影细节见 [架构说明](education.md) 和 [画像投影](../../backend/open_webui/services/education/PROFILE_PROJECTIONS.md)。

- 身份、班籍、资源访问、基线、提交和评分边界均需后端校验。
- 数据结构由 Alembic 管理，不运行时补建表、列或历史证据。需要清理的迁移按具体要求显式执行，不在读取时自动修复。
- 采集告知说明记录范围和可见边界；来源数据可能不完整或被绕过，不能作为学术诚信的唯一判据。
- 保留有解释价值的版本、提交和评阅历史，目前不设置教学过程的自动清理期限，并控制存储与查询成本；不声称已有统一运营指标或自动保留期治理工具。
- 前后端配置与凭据分开，教学界面走国际化文案；桌面写作优先，并保证基础移动端可访问。

## 12. 产品验收与后续范围

基础验收覆盖注册入班、建作业、两种写作形式、保存与对话、冻结提交、评分反馈、权限隔离、通知、画像和导出。退回和试读须分别在适用开关与作业形式下验收；关闭功能时拒绝请求也是正确行为。

产品与教研关注完整教学闭环数、提交和批改情况、质量评分覆盖率、修订及试读响应和数据完整度。计数与比例反映过程，不能替代学习质量评价。

当前待办及代码核查结果见 [开发任务清单](教学模块开发任务清单.md)，已完成与废弃条目的依据见 [开发记录](../archive/教学模块开发记录.md)。以下方向保留为待确认候选，不承诺排期：

- 班级所有权转交，解决仍有班级的教师不能撤销身份的管理限制。
- 同一班级跨作业的试读维度趋势；现有学生跨作业画像不等于该报表。
- 独立评分模板与量纲库，须先明确其与实例默认维度、作业复制的差异。
- 课堂观察后的自适应焦点，维持第 8 节的前置条件与否决边界。
- 教师协同评阅和校内系统集成，属于较远期方向，不在当前基础功能内。

本轮文档校准不授权实施这些候选功能，不把已下线的作业归档、写作前评析、风险汇总和旧评分算法转回待办。

## 2026-11-07 配置变更与一致性补充

教师修改已开始作业的标题或要求时须填写变更说明；保存前核对差异与受影响人数。要求、截止、评分或反思更新通知学生；后续修订调用使用最新说明并标记版本。提交弹窗刷新配置，携带配置版本，遇到变更需重新核对；只保留题干、选项和要求仍相同的答案。更新、确认基线、提交与批改按作业串行校验，避免并发绕过锁定。

退回开关继续默认关闭。本次实现与迁移不自动开启真实实例。隔离环境开启时，已发布退回意见及评阅版本进入修订上下文，私人笔记与未发布草稿不进入；更正意见通知学生，重交仍自主决定。

实施与验证状态见 [本轮验证记录](../development/2026-11-07-revision-validation.md)。
