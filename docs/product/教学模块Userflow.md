## 0. 全局前提：身份体系与通知

### 0.1 注册与身份

- 注册页 `/auth`：填写姓名/邮箱/密码，并在下拉框选择教学身份 **Student / Teacher**（默认 Student），随 `userSignUp` 的 `education_role` 参数写入。
- **学生注册必须填班级邀请码**（2026-09-09 起）：选 Student 时邀请码为必填项，随 `userSignUp` 的 `classroom_invite_code` 一并提交。后端在建号前校验——未填返回 400 `Classroom invite code is required`，码无效或班级已归档返回 404 `Invalid classroom invite code`，两种情况都不会留下用户记录。
- **邀请码即审批**：有效邀请码学生注册后入班；正常默认新用户角色为 `pending` 时，学生被提升为 `user`，不进入管理员待激活队列。教师不需要邀请码，其平台角色跟随实例的 `ui.default_user_role`；默认 `pending` 时需管理员批准，配置为 `user` 时已激活，不能把审批写成与实例配置无关的强制步骤。空库首位管理员另适用初始化规则；管理员可在用户编辑弹窗调整教学身份。
- 例外：空库时的首个注册者会成为管理员，此时还不存在任何班级，故不施加邀请码要求。
- **登录邮箱与密码**（2026-10-06 起可自助改邮箱）：用户在「设置 → 账户」的「邮箱」栏改登录邮箱（`POST /api/v1/auths/update/email`，须验证当前密码，校验格式与占用，同步 `auth` 与 `user` 两表，不强制重新登录），「密码」栏改密码（`POST /api/v1/auths/update/password`，改完吊销全部会话并退出）。两栏都受 `ENABLE_LOGIN_FORM` 与 `ENABLE_PASSWORD_CHANGE_FORM` 控制（均默认开）。没有「忘记密码」/邮件重置：忘了密码由管理员在用户编辑弹窗直接填新密码（同样吊销该用户全部会话），管理员也可在那里改邮箱。
- **教学身份 = 权限组成员关系**（2026-09-03 起）：`education-teacher` / `education-student` 两个固定 id 的组，常量与唯一读写入口都在 `services/education/identity.py`（`get_education_role` / `set_education_role`）。给某一类身份统一开放模型、工具或功能，直接给对应的组配权限即可。
- **唯一写入口**：身份只能通过「编辑用户」弹窗（`/users/{id}/update`）或注册时写入。用户组页面对这两个组不开放成员增删（`/groups/id/{id}/users/add|remove` 返回 400），也不能删除该组；前端相应隐藏「用户」标签页与删除按钮，用户编辑弹窗里也不再重复列出这两个组。
- 约束：`admin` 角色不持有教学身份（`get_education_role` 由 `user.role` 直接派生为 `admin`，且 `set_education_role` 对管理员整体豁免，不动其组与班籍）；教学账号应设置有效 `education_role`；普通平台角色 `user` 本身不等于教学学生身份；只有学生能被分配进班级，且**一个学生至多在一个班**（见 S2、S2.5）。
- **班籍随身份走**：`classroom_member.member_role` 必须与账号当前身份一致。`set_education_role` 在换组后会删掉与新身份不符的全部班籍（跨班级，不止第一条）；反过来，教师名下仍有班级时禁止改身份（返回 400），避免 `classroom.teacher_id` 悬空。

### 0.2 首次引导 `/education/setup`

| 身份 | 引导内容                                                                             | 完成后跳转    |
| ---- | ------------------------------------------------------------------------------------ | ------------- |
| 教师 | 输入并创建**第一个班级**（自动生成邀请码）                                           | `/teacher`    |
| 学生 | 注册时已入班，此页不再出现；仅管理员直接建号的学生会走到这里（输入邀请码，也可跳过） | `/me/writing` |

- **守卫**：教学身份在注册时选定、仅管理员可改（后端 `/users/user/info/update` 拒绝非管理员修改 `education_role`）；引导页不再提供自助改身份。已完成初始化的用户（教师已有班级 / 学生已入班 / admin / 无教学身份）访问此页会被直接重定向。

### 0.3 通知闭环（贯穿双端）

- 存储：`education_notification` 表（user_id / type / payload_json / read_at）；实时推送走 Socket.IO 事件 `education:notification`；离线不丢，登录后由未读接口补齐。
- 前端：`(app)/+layout.svelte` 监听 socket → toast + 更新未读 store；侧边栏入口显示未读角标。
- API：`GET /api/v1/me/notifications/summary`（未读数）、`POST /api/v1/me/notifications/mark-read`（按类型/作业批量已读）。

| 通知类型                       | 触发                             | 接收方       | 自动已读时机               |
| ------------------------------ | -------------------------------- | ------------ | -------------------------- |
| `assignment_published`         | 教师创建作业                     | 班级全体学生 | 学生打开该作业工作区       |
| `assignment_updated`           | 教师修改作业截止时间             | 班级全体学生 | 学生打开该作业工作区       |
| `assignment_reminder`          | 教师催交（全部或指定未提交学生） | 未提交学生   | 学生打开该作业工作区       |
| `assignment_extension_granted` | 教师给该生设个人截止时间         | 被延期的学生 | 学生打开该作业工作区       |
| `assignment_extension_revoked` | 教师撤销该生的个人截止时间       | 该学生       | 学生打开该作业工作区       |
| `submission_created`           | 学生提交（任意轮）               | 该班教师     | 教师打开 Review / 提交列表 |
| `review_completed`             | 教师保存批改（reviewed）         | 学生         | 学生打开该作业工作区       |
| `submission_returned`          | 教师退回（returned）             | 学生         | 学生打开该作业工作区       |

- **教师端实时刷新**：教师首页 / Review 队列 / 提交列表 / 看板在收到教学通知时自动重拉数据（与学生端首页同一订阅机制），Review 与提交列表页同时把 `submission_created` 标记已读。

## 一、学生端 Userflow

### S1 注册进入

`/auth` 选 Student 注册 → **填班级邀请码**（必填）→ 注册成功即 active 且已入班 → 直接落地 `/me/writing`。不经管理员审批，也不经 `/education/setup`。

### S2 加入班级

- 入口①（主路径）：注册页的邀请码输入框——学生的第一个班级在这里就定了。
- 入口①b：setup 引导页邀请码输入框，只对管理员直接建号、尚未入班的学生有意义。
- **一个学生只能在一个班**（2026-09-23 起）：数据库部分唯一索引 `classroom_member_single_student_idx`（`UNIQUE(user_id) WHERE member_role='student'`，迁移 `a9c2e4f6b8d0` 建立，建索引前只保留每人最早加入的那个班、其余班籍直接删除）。教师可以带多个班，不受约束。
- 入口②：写作首页 `/me/writing` 的 Assignment Writing 区，邀请码输入框**只在未入班时出现**；已入班则显示「我的班级」+ 提示「每位学生只能加入一个班级，如需换班请联系老师或管理员」。未加入任何班级的学生进入首页后默认停在 Assignment Writing tab，保证一眼看到入口。
- 入口③：**邀请链接** `/join?code=XXX`（教师在班级页复制）。已登录学生打开后预填邀请码一键加入；**已在某个班的学生打开时只显示「你已在「X」班级中……如需换班请联系老师或管理员」，不给加入按钮**（页面先调 `GET /api/v1/me/classroom` 判断）；非学生身份访问会被提示并引导返回。
  - **未登录打开邀请链接**：被守卫重定向到 `/auth?redirect=%2Fjoin%3Fcode%3DXXX`，auth 页从 `redirect`（或自身 `?code=`）里取回邀请码，自动切到注册模式、身份锁为 Student 并预填邀请码——学生全程不用手抄码。注册成功时已由 signup 接口入班，直接落地 `/me/writing`，不再回 `/join` 二次提交（重复调 join 接口会 400 `Student has already joined this classroom`）。
- **加入按钮上方常驻一段采集告知**（`EduDataNotice`，`scope="classroom"`）：写作区记录哪些内容、任课老师能看到作业写作区的哪些、个人写作区老师看不到。只说采集范围，不含任何阈值或判定规则。非学生身份看不到（那条分支只显示「只有学生能加入」）。
- API：`POST /api/v1/classrooms/join`（`{ invite_code }`）→ 创建 `ClassroomMember`；加入后首页出现班级名与该班作业列表。已在另一个班时返回 **409** `You are already in a classroom. Ask your teacher or an administrator to change classes.`。注册路径不走这个接口，由 `POST /api/v1/auths/signup` 内部完成入班。
- 邀请码查询（`get_classroom_by_invite_code`）只认 `status = 'active'` 的班级，注册与加入两条路径共用，归档班的旧码在两边同时失效。

### S2.5 换班

学生自己不能换班，只有两条路：

| 谁       | 怎么换                                                                                                                   | 入口                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 原班老师 | 把学生**移出**本班 → 学生再凭新班邀请码自助加入；或在**自己名下的班级之间**直接调班                                      | `/teacher/classrooms/[id]/students`（`DELETE .../members/{id}`、`POST .../members/transfer`，目标班须是本人的班） |
| 管理员   | **跨老师调班**：在 `/admin/users` 编辑用户弹窗改「班级」下拉，保存即删旧班籍、建新班籍；改前改后不同时弹窗内有琥珀色提示 | `POST /api/v1/users/{id}/update`（`classroom_id`）                                                                |

不给老师跨班调人：原班老师不该决定学生进谁的班，新班老师也不该从别人班里拉人；管理员能看到全部班级、立场中立。

换班（含移出）之后：

- **提交记录跟着作业留在原班**：原班老师在作业提交列表、批改页照常能看、能批；学生的作业列表和写作入口只剩新班的作业。原班的「学生画像」入口关闭（`.../students/{id}/profile` 返回 404，学生已不在该班）。
- **成长画像跟着学生走**：画像的作业范围 = 当前班的作业 ∪ 学生交过的全部作业（`Education.get_profile_assignments_by_student`），学生端 `/me/writing/growth`、新班老师的学生画像、画像聚合物化三处共用。每次班籍变化（加入、移出、调班、管理员改班级）都会重新物化画像聚合（`refresh_profile_aggregates_after_scope_change`）。
- 新班老师在画像里看得到原班的作业与分数，但那些提交**不给「打开 / 查看证据」入口**，改显示「在其他班级提交」——批改页只对原作业所属班的老师开放。
- 成长目标、教师私人笔记仍按班级归属，不随学生迁移。

### S3 写作首页 `/me/writing`

`GET /api/v1/me/writing/home` 返回三组：最近写作、**班级作业列表**、个人写作（时间戳统一为秒；笔记表的纳秒时间在后端换算）。页面用通用页头 `EduPageShell`，标题「写作」，右侧「我的成长」。自上而下：

- **接着上次写**：只取最近写作里第一条**未提交**的，一行横条，点了直达对应工作区；没有就不显示（原来 12 张最近写作卡片已删除）。
- **作业写作 / 个人写作**两个分段（作业写作带待完成数）；同一行右端以小字显示「我的班级：…」，悬停提示一人一班的规则。未入班时作业写作页顶部是邀请码输入卡。
- **待完成**（未提交 + 被退回，且没过有效截止）按有效截止**升序**（无截止的垫底）；**已截止未交**（没交又过了有效截止，交不了了，只剩回看）单独一组、截止近的在前、**默认折叠**——混在待完成里会排在最前头，把真正要做的作业挤下去（2026-10-03 学生视角走查）；**已提交**（其余）按更新时间倒序，**默认折叠**。作业写作分段上的待完成数、学生默认落在哪个分段，都只算没过截止的。
- 每张作业卡片：修订初稿作业标题旁先有一枚灰色「修订初稿」标签（要先交初稿才能开始，进门前就该知道；从零写作是常态，不标）；再是状态标签——`returned`（红·已退回）/ `reviewed`（绿·已批改+**分数**）/ `pending`（灰；未过有效截止「已提交·截止前可修改」，过了「待批改」）/ `draft`（蓝·进行中）；说明最多两行；截止行显示「截止时间 / 重交截止（红）」，待完成的再跟剩余时间（与工作区共用 `getDueCountdown`：<24h 琥珀、<1h 玫红、已过「已截止」）。
- 卡片按钮按状态说下一步：开始写作 / 继续写作 / 修改后重交（主按钮），查看批改 / 查看提交（次按钮），都进入 `/assignments/{assignmentId}/write`。
- **实时刷新**：收到 `education:notification` 时首页列表自动重新拉取（不切换用户当前标签页）

（个人写作：`POST /api/v1/me/writing/personal` 新建、`DELETE /api/v1/me/writing/personal/{id}` 删除（需确认；连带删掉对应项目文件夹与对话，删完侧边栏对话列表与置顶整页重拉 —— 列表 store 自 0.11 起只读，不能就地剔除），落地 `/writing/{sessionId}`，用同一个 `WritingWorkspaceShell`，不进提交/批改流程。）

学生端另有 `GET /api/v1/me/writing/workspaces`（作业工作区状态列表）与 `GET /api/v1/me/writing/profile`（**个人成长画像**，见 S11）。

### S4 打开作业写作工作区 `/assignments/[assignmentId]/write`

- 作业工作区由 `GET /api/v1/assignments/{assignmentId}/workspace` 装配，首次打开时创建或取得该学生的 `WritingSession(scope=assignment)`、Note 和 Folder；`GET /api/v1/writing/{sessionId}/workspace` 用于按会话打开工作区，包括个人写作，不能把 assignmentId 当成 sessionId。
- 布局（`WritingWorkspaceShell.svelte`）：**左栏 AI 聊天，右栏富文本编辑器**（窗口宽 ≥1024px 时并排；更窄——平板、和 Word 左右分屏——改用底部浮条「作业内容 / 提交」+ 正文抽屉。断点不用全站的 768px：768～1023 之间右栏被 `lg:flex` 藏掉、浮条又不出，学生看不到正文也交不了，2026-10-03 走查发现）；右栏顶部依次是保存状态徽章（Saved/Saving/Retrying/Failed，**只反映自动保存，不掺提交状态**——提交与否由旁边的绿色「已提交」徽标单独表示）、**批改结果卡片**（`ReviewResultCard`，见 S8）、**本次写作构成**（`WritingComposition`，仅作业定稿后显示，见 S5）、提交按钮。
- 右栏可拖拽改宽（`ResizableSidePanel`，`storageKey=writingRightPanelSize`），**默认约占视口 48%**（不小于 600），下限 560（保证头部标题不被右侧按钮组挤没），**不设上限**；正文行长改由面板内部的居中栏控制（头部与正文都在 `max-w-[46rem]` 的一栏里，一行四十来个汉字——编辑器根节点的 `min-w-full` 会盖掉 prose 自带的 65ch，只能在外面限宽）；聊天侧另有 `minSiblingWidth=360` 保底，窗口不够宽时下限自动让位。
- 左侧还没选中对话时显示写作区专用的空态（`Placeholder` 的 `writingWorkspace` 模式）：「和 AI 聊聊你的稿子」+ 写作场景的输入提示，不再重复显示项目文件夹标题；下方仍是本项目的历史对话列表（时间按中文「今天 15:06 / 昨天 …」显示）。
- 头部：作业标题（写作中不再附说明行；提交后/定稿/过截止才有一行状态说明）+ **有效截止时间 + 倒计时**（每分钟刷新；<24h 琥珀、<1h 玫红、超期显示「已截止」；退回状态标注为重交截止；与写作首页共用 `getDueCountdown`）；下方 **作业简报**（`AssignmentBrief.svelte`）**默认收成一行**（「作业要求」+ 首行要求 + 展开），展开后是要求原文 + 评分维度胶囊（各维度名称·分值）+ 满分，移动端抽屉同步展示。
- **作业上下文自动注入对话**：`_ensure_assignment_project` 每次装配工作区时，把「作业标题 / 要求 / 评分维度 / 截止」+ **按作业形式的任务说明**（config `education.task_prompts`，见 T3）+ 辅导风格写进项目文件夹的 `folder.data.system_prompt`，由 `utils/middleware.py` 的 Project 逻辑注入该文件夹下所有对话，学生不用再手动复述作业。老师改了作业信息、管理员改了措辞，学生下次打开工作区即同步覆盖。
- **每轮注入当前正文**（作业写作区与个人写作区都生效）：文件夹提示词是静态的，装不下实时正文；靠模型自己调 `view_note` 工具，国产模型又调不可靠。所以 `utils/middleware.py` 在注入文件夹提示词之后，若该文件夹是写作会话的项目文件夹且会话属于本人，就用 `services/education/writing_context.build_current_text_context` 读出笔记**最近一次保存**的 `md`，以「【学生当前正文】…<<< 正文 >>>」追加到系统提示末尾（措辞里明确告诉模型：之前回复里引用过的句子可能是旧版本，一律以这一版为准。验收时发现不这样写，模型会相信自己历史回复里的旧引文，回答「我这边看到的还是旧版本」）（不走提示词模板变量解析）。笔记用自己的短会话读，读完即释放，不把数据库事务带进模型调用。约 1000 字的正文每轮多 1–2k token。修订初稿作业只注入当前正文，不注入初稿基线全文。
  - **改没改由后端算好写成状态行**（正文上方），不让模型拿自己引用过的句子去猜——学生不一定每轮都改，原措辞「每轮都会更新」会诱导模型把没改的地方说成改了。两行：①「与初稿相比：还没有改动 / 已有改动」，仅修订初稿作业（有基线）；②有上一条 AI 回复时才有：没改就写「自你上一次回复以来：没有新的改动」，改了就**逐条列出改了什么**（`describe_text_changes`：段落级对齐，相近的段（相似度 ≥ 0.5）配成「改了」、其余算删去/新增，连续删去的段合成一条；段内按**整句**比，写成「「……前一句末尾」之后把「旧句」改成了「新句」」/「加了」/「删去了」；每条截 150 字，最多 8 条）。只写「有改动」不够：模型看不到上一版，只能自己猜改了哪里，2026-10-02 实测学生删了参考文献、在结尾加了字，模型找不到它要的那 5 句，就连说三次「我这边没看到新的改动」。段内逐字比也不行，「把『初稿』改成了『改过的』」模型看不懂，所以按句。②的「上一次回复」= 当前提问消息的 `parentId`；取 `chat_message.created_at` 不晚于它的最后一个 `writing_version`，与当前正文按 `normalize_draft_paragraphs` 逐段比（只差空白不算改）；那之前没有版本就以初稿基线（从零写作为空稿）为准。两边时间都是后端时钟：AI 回复占位由后端在发起请求时写入（`main.py`），版本时间也是服务端写的，不受学生电脑时钟影响。措辞同时交代：学生说改好了、状态却显示没有新的改动，多半是还没保存，请他看到「已保存」再发。
  - **发送前先存盘**：编辑器停手 1.2 秒才自动保存，原先改完马上发消息 AI 看到的是旧稿。`Chat` 新增 `beforeSend` 钩子（`sendMessage` 开头、`continueResponse` 发请求前调用），写作区传入 `flushDraftBeforeChat`：有防抖中的修改或正在保存就立即强制存一次，与试读前落盘同理。最多等 5 秒（断网时保存要重试 2/4/8 秒，不能让发送一直卡着）；没存上照常发，AI 看到的是上一次存成功的稿子，同时弹出警告「你最近的修改还没保存上，AI 这一轮看到的是上一次保存的稿子」。2026-10-02 浏览器实测：改一句后 108ms 内发送，AI 准确说出改了哪句；拦截保存请求后约 5.9 秒弹出警告并发出。必须在 AI 回复占位写入之前存完，否则这一版的时间晚于回复，下一轮会被误报成「有新的改动」。
- **修订初稿作业的首轮开场分两步**：确认初稿后，前端先调用 `POST /api/v1/writing-sessions/{id}/revision-items`，服务端按每个评分维度生成结构化通读结论；没有现成对话时，这段期间正文与对话锁定并显示进度。通读返回 `ready` 后才通过 `Chat.svelte` 的 `prefillPrompt / autoSendPrefill` 自动发出首轮通读消息，回复依据已生成的结论表展开。`meta.auto_started` 标记的平台消息在教师时间线显示「平台自动发起」，不计入学生提问数；只有平台首轮或补看消息时，不要求也不接受提问质量分。模型尚未选定时等待选择，通读失败显示重试；已有对话的会话不会因刷新重复自动开场。任务说明负责评分维度、诊断规则与当前正文上下文，辅导档位负责之后提供帮助的程度。
- 简报下方常驻**采集告知**（`EduDataNotice`，按 `scope` 变文案）：作业写作区说「任课老师能看到这些记录」并补一句「个人写作区老师看不到」，个人写作区只说「这里老师看不到里面的任何内容」。写作区里用 `collapsible`：每个 scope **第一次进入完整展示三行**并在本地记下（`education:data-notice-seen:{scope}`），之后收成一行摘要（「这里会记录你的写作过程，老师可以看到 / 只有你自己能看到」+「详情」）。告知始终在场，只是不再每次压低编辑区。桌面端与移动端抽屉各渲染一次。
- 有过提交后头部出现**「提交记录」按钮** → `SubmissionHistoryModal` 弹窗查看自己全部轮次（每轮正文快照 + 该轮批改结果），API：`GET /api/v1/assignments/{id}/me/submissions`（仅学生本人）。
- 打开时自动把该作业相关通知标记已读。
- **侧边栏切项目会重新装配工作区**：`/assignments/[assignmentId]/write` 与 `/writing/[sessionId]` 都在页面里用 `{#key 路由参数}` 包住 Shell。SvelteKit 同路由跳转只换参数、不重挂组件，而 Shell 只在 `onMount` 里拉工作区，不加 key 时从一个写作项目点到另一个只会改地址栏、内容纹丝不动。重挂载同时会走 `onDestroy` 的草稿补交（见 S5），不会把上一个项目的编辑写进新项目。
- **学生记忆与作业检索边界**：学生的作业写作、个人写作和普通对话都禁止读写记忆；`utils/access_control` 收回学生的记忆权限，记忆接口拒绝访问，中间件关闭记忆注入和回复后的记忆整理。作业写作会话还在模型配置副本中禁用检索历史聊天与记忆的内置工具，防止把作业外内容带进教师可见留痕；不修改管理员原模型配置。个人写作的聊天检索另受其工具配置与权限控制，不因此获得记忆权限。教师的记忆权限按平台设置处理。
- **新对话留在工作区地址并立刻出现在侧栏**：0.11 起新对话由后端在发第一条消息时建好、随响应返回 `chat_id`，前端原先一律把地址改成 `/c/{id}`，工作区因此不知道当前对话（不记活跃对话、侧栏点回去会卡）。现在有 `projectBaseUrl` 时改为 `goto(工作区?chat={id})`（先记为已加载，不打断正在生成的回复），随后通知侧栏：写作分组（独立的 `writingProjectRegistry`）收到新对话时**自动展开**并重拉列表，标题生成后（`chat:title`）再刷新一次。首轮自动诊断走同一路径。生成中/结束（`chat:active`）、已读等事件也同时发给写作分组，否则列表在生成中拉取后行首的转圈不会消失。
- **切换对话不卡**：Chat 加载对话时会卸掉再重挂右栏，右栏编辑器的 `bind:editor` 曾把已销毁的实例交给新编辑器，`getHTML` 抛错后界面停在转圈；`RichTextInput` 销毁时清空 `editor`。视图回到新对话（`initNewChat`）时清掉「已加载对话」记录，否则再点刚才那个对话地址变了内容不变。

- **切到别的页面再回来，回复照常显示**（2026-10-03 修）：上游消息列表和 Markdown 在流式输出时都把重绘排进 `requestAnimationFrame`，浏览器在后台标签页整个暂停它；Markdown 还只依赖 `content`，最后一段内容在 `done` 仍为假时排进动画帧，`done` 变真时内容没变就不再解析。学生等第一次通读（20～50 秒）时切去别处，回复写完了左栏却是空白、要刷新才出来。现在 `Messages.svelte` 与 `Messages/Markdown.svelte` 在 `document.hidden` 时直接重建/解析，Markdown 同时依赖 `done`。

### S4.5 修订初稿作业：先交初稿（`task_mode=revise_draft`）

作业形式为「修订初稿」时（见 T3），学生在课外写好初稿（可借助自己的 AI），平台负责之后的修订过程。

- 写作会话还没有初稿基线（`writing_session.draft_baseline_at` 为空）时，右栏**只显示初稿步骤**（`DraftBaselineStep.svelte`，桌面与移动端抽屉各一份）：说明文字 + 「从文件导入」按钮 + 纯文本框 + 「确认这是我的初稿」按钮；去掉空白后不足 **200 字**（前后端同一常量 `DRAFT_BASELINE_MIN_CHARS`）时按钮禁用。左侧对话只读并提示「先在右侧提交初稿」，提交按钮隐藏。
- 初稿可以粘贴，也可以**上传或拖进文本框**（.docx / .doc / .txt / .md）→ `POST /api/v1/writing-sessions/{id}/draft-baseline/extract`（multipart `file`）：与交初稿同一组前置校验，后端解析成纯文本后按同样规则切段，返回 `{text}` 填回文本框，学生核对、改完再点确认。Word 文件**按内容而不是扩展名分派**（改错扩展名的照样能读）：.docx 用 python-docx，旧版 .doc 用 olefile 读 WordDocument 流、按 piece table 拼回正文；两者都按文档顺序取正文段落和表格（每个单元格一行），页眉页脚、脚注、文本框不取，域只留显示结果（如超链接文字）——已有配对测试样本的 .doc 与 .docx 提取结果一致，复杂文档仍以学生核对后的正文为准。txt 依次按 UTF-8、GB18030 解码。设了打开密码的文件提示去掉密码。**只解析不保存**：文件不落盘、不进文件库、不冻结基线；上限 10MB。PDF 不收（抽出来每个视觉行断成一段），提示复制文字或另存为 .docx。从文件导入与粘贴一样记为 `declared_draft`。
- 确认 → `POST /api/v1/writing-sessions/{id}/draft-baseline {text}`：校验作业形式、会话归属、未过有效截止、长度；按行切段（去首尾空白含全角空格、丢空行），**同一事务**里写基线（条件更新：基线为空才写，并发重复提交只有一次生效，其余 409）、把正文写进笔记（每行一个段落，`md` 为各段 `\n` 相连，与编辑器 `getText({blockSeparator:'\n'})` 逐字一致）、写一条覆盖全文的 `declared_draft` source map。只写笔记不写来源的话，整段初稿会落成「来源未记录」。
- 之后编辑器载入初稿并先进入第一次通读的等待状态；无现成对话时通读完成才解锁编辑和首轮对话。再出现的大段粘贴照常记 `external_paste`，不能覆盖已确认基线或把新粘贴冒充声明初稿。
- 基线确认后学生和老师都不能再改；老师退回重交时基线仍是最初那份。
- **撤回初稿重新开始**（唯一的例外）：从没提交过、没过截止时，右栏头部「⋯」（桌面与移动端抽屉各一份）里有「撤回初稿，重新开始」，二次确认后 → `DELETE /api/v1/writing-sessions/{id}/draft-baseline`：同一事务里清空基线、正文、写作版本、来源记录、编辑操作，并把 `chat_id`/`active_chat_id` 置空（条件更新里同时查提交表，与并发提交只有一方生效；交过一次〔含退回重交〕即 409）；提交后再停掉生成中的回复、删掉项目文件夹里本作业的全部对话。删掉的不留痕，老师也看不到。右栏回到交初稿那一步，重新确认初稿时首轮诊断照样自动发出（`Chat.svelte` 在预填撤掉时复位「已预填」记录）。撤回时前端先清掉「替学生发首轮」、通读结论和补看状态再跳转——不清的话跳回作业页、重新加载完之前开场白会被当成新对话自动发出，留下一段没有初稿的空对话，它还被记成 active_chat_id，重交初稿后首轮反而不自动发了（2026-10-03 走查发现）。通读要半分钟，期间撤回又交了另一份时，旧初稿那次的结论不落库（`store_revision_items` 按初稿原文核对），前端也丢掉那次结果、按新初稿重新通读。没有做成「对话删光就自动重置」：确认初稿时等不到模型、或只改正文还没开口问时项目里同样没有对话，系统分不清。学生单独删对话不受限制，删了就是没了。
- **第一次通读与修改清单**（2026-10-03 定型，`services/education/revision_items.py`；取代原先「采纳 / 不采纳哪些建议」那道反思题）：学生交了初稿后、和 AI 说第一句之前，服务端先让模型把初稿在作业的**每一个评分维度**上逐项下结论，首轮回复再按这张结论表写。这张表就是修改清单。
  - **为什么先下结论再写**：此前让 AI 直接写首轮回复、再从回复里整理清单。首轮谈哪几项是 AI 自己定的（「定位出问题只谈这一条」「最多五条」「没问题的不说」），没被提到的维度分不清是达标、没看还是被截掉，清单只是「AI 这次碰巧说了的」，和老师的评分维度对不上。2026-10-03 用 8 份样稿试跑验证（见 `哈工深批注/试跑/README.md` 第四、五轮）。
  - **四档**（`revision_item.status`）：`problem` 要改（提交时必须交代）、`minor` 可改进（可交代可不交代）、`ok` 达标、`deferred` 暂缓（任务说明规定「某项出问题时哪几项先不谈」且该项确实出了问题时，那几项填暂缓；该项记 `is_blocking`，模型输出里用顶层 `blocking` 点名，点不出或它不是「要改」就算格式不合格重来）。只分「有问题 / 达标」时写得好的稿子也被判七八项有问题，所以分出可改进。哈工深的提示词（v10 起）规定：定位有问题时只暂缓「文献的相关性与充分性」「按一定原则分类」「每篇文献的介绍」三项，其余照常下结论——和她当年对这类稿子照样批结尾、引言、出处的做法一致。
  - **补看**（2026-10-03）：还有暂缓项时，右栏作业简报下方出现一行（`FollowUpBar.svelte`）：「还有 3 项等「综述只写已有的研究」改好后再看：……［改好了，接着看］」。学生点了 → 先把编辑器里没存的改动存掉 → `POST /api/v1/writing-sessions/{id}/revision-items/follow-up {model_id}`：平台按**当前正文**先判那一项改到位没有（`FOLLOW_UP_PROMPT`，按任务说明里这一项的判定规则），没改到位返回 `not_ready` + 一句还差在哪（引一句正文），暂缓项不动，学生改完可以再点；改到位就给暂缓的几项补上结论（只能是要改 / 可改进 / 达标），这几条和那一项都记 `follow_up_at`，然后前端经 `Chat.svelte` 的 `platformMessage` 替学生发一句「我把「……」改好了，请接着看先前暂缓的几项」（带 `auto_started`），AI 按补全后的结论表回复。补看期间对话锁着。**只补暂缓的格子、不重看整张表**：允许随时重看全表，学生可以反复点到「要改」变少（同一份稿子两次诊断约 1/8 的项会在要改和可改进之间跳），清单就失去了交代的意义。与第一次通读共用 `revision_items_claimed_at` 占位。试跑见 `哈工深批注/试跑/README.md` 第六轮。
  - **通读**：`POST /api/v1/writing-sessions/{id}/revision-items {model_id}`（取或通读）。用学生选的对话模型、按模型默认思考设置调一次（试跑里关思考的漏判误判明显多），系统提示 = 平台的 `DIAGNOSIS_PROMPT` + 作业的任务说明（取其中的批改标准和判定规则）+ 评分维度（key：名称），用户消息是初稿。输出 JSON 必须每个维度各一条、档位合法、暂缓只能跟在「要改」后面，否则当场重试一次，两次都不行返回 `failed`。原句用 `locate_quoted_span` 对回初稿，对不回去留空；达标、暂缓不留原句。通读前在 `writing_session.revision_items_claimed_at` 单独提交占位（300 秒过期），模型调用不夹在未提交事务里，出任何错都放掉占位；完成写 `revision_items_generated_at`，之后不再通读。同步做完才返回（实测 20～50 秒，生产反向代理读超时 3600 秒）。
  - **首轮怎么用这张表**：`utils/middleware.py` 在写作区对话的系统提示里，先附【第一次通读结论】（要改的带一句结论和原句，可改进一句话，达标、暂缓只列名称），再附【学生当前正文】；每轮都附，之后的对话也知道第一次通读说过什么。任务说明的「通读」一节要求首轮只展开「要改」、可改进合起来带过、结尾说哪些达标暂缓，不新增也不漏掉表里的项。
  - **学生端**：确认初稿后对话先锁着，右栏作业简报下方出现进度卡片（`FirstReadProgress.svelte`：「正在按 N 项评分标准逐项看你的初稿……」，列出各维度名称），左栏提示同样的话；通读完成后自动发出首轮那句话（页面中途刷新也会接着通读、完成后自动发）。没通读成时卡片给「再试一次」。之前已经聊过的会话不锁对话，通读在后台补上。
  - **提交时**（`RevisionList.svelte`，只在提交弹窗顶部出现，写作过程中不显示——对话管「怎么改」，清单管「最后交代」）：分组列出「要改」（每项选改了 / 改了一部分 / 没改，后两种写为什么，必填）、「可改进（可不填）」（同样三个按钮，再点一下已选的可撤回）、达标与暂缓各一行。选处理方式立即存（`PATCH .../revision-items/{item_no}`，只接受要改、可改进两档），理由失焦时存；提交请求带上全部处理（`revision_decisions`）。「要改」没标完或没写理由时拦下并标红（前端先查，后端 `_prepare_revision_decisions` 再查，400）。通读没做成（`generated_at` 为空）时**不拦提交**——这一步学生控制不了。
  - **撤回初稿**时结论表一并清空，新初稿重新通读。
- **后端门槛**（不只靠前端）：没有基线时 autosave / versions / provenance / operations / 写作区聊天消息 / 提交一律 409；`utils/middleware.py` 在注入文件夹系统提示前检查，该写作会话文件夹下的模型请求同样 409。客户端上报 `declared_draft` 来源时会话必须已有基线，否则 400。

### S5 写作过程（全程留痕）

停止输入 1.2 秒后自动保存，一次落四类数据：

1. `POST .../autosave` — 内容快照；
2. `POST .../versions` — 版本（`trigger_type=autosave|manual|submit_preflight`，submit 版由后端提交接口自建，version_no 递增）；
3. `POST .../provenance` — **溯源段落**，来源四类：`user_typed`（手打）/ `ai_inserted`（点 AI 回复的 "Insert to Writing"）/ `ai_pasted`（点 AI 回复复制按钮后粘贴）/ `external_paste`（外部粘贴）；修订初稿作业另有服务端写入的 `declared_draft`（已声明初稿，见 S4.5），前端 source map 原样保留这一类，学生改动其中的字照常转为对应来源；
4. `POST .../operations` — 编辑操作日志（keyboard_input / delete_text / replace / ai_insert_clicked / paste_detected 等），每条必带 `occurred_at_ms`（客户端发生时刻）与 `client_sequence`；过程指标一律按发生时刻计算，服务端接收时间只做采集审计，避免批量上报把多次编辑压成同一时刻。

第五类留痕**不经前端上报**：AI 用内置工具 `ask_user` 中途停下来向学生提问时，问答由后端写进 assistant 消息的 `output`，提交时随 `get_prompt_timeline` 一并冻进 evidence snapshot。教师端看到的是从中派生的结果（见 T6），不需要学生端做任何事；该内置工具在模型设置里关掉时，`output` 里没有这一项，派生结果自然为空。

**留痕在作业定稿后对学生自己可见**（`WritingComposition`）：作业**已批改或已截止**（工作区只读）后，右栏正文上方显示「本次写作构成」，按当前正文字符给出 自己敲的 / AI 插入 / AI 粘贴 / 外部粘贴 / 来源未记录 的占比，外加**已回答澄清追问数**（`GET /api/v1/writing/{sessionId}/process-summary`）。该计数与教师端过程摘要共用 `count_clarifications`，同一份稿子两端必须报同一个数。面板只呈现、不评判、不预警——做成警告条会把学生逼去绕开留痕，反而先毁掉数据本身。**写作过程中（含提交后、截止前仍可改稿重交的阶段）不显示**：实时看到比例，学生会重敲粘贴内容来刷「自己敲的」占比，同样毁数据（2026-09-23 定）。个人写作区教师看不到、没有刷数动机，照常实时显示。

另有 `POST /api/v1/writing-sessions/{id}/active-chat`（切换当前对话时回写会话的 active_chat_id；chat 不存在 404，chat 不属于该作业 folder 400）。

两条保留内容真实性的规则（写在 `WritingWorkspaceShell`）：

- **正文没变就不开新版本**（autosave / manual / submit_preflight 一视同仁；提交接口另存的 submit 版是终稿锚点，不受此限）。以前试读前、提交前强制存版，一次提交叠出两三个一模一样的版本。编辑器在选区/格式变化时也会触发 onChange，照存的话一篇稿子能攒出两百多个一模一样的版本，版本历史没法看，「改了几版」也失去意义。
- **只认学生自己造成的编辑**。`RichTextInput` 每次 onChange 带两个标志：`docChanged`（正文有没有真的变）和 `programmatic`（是不是组件自己把正文灌进编辑器）。两者任一不满足就直接返回。编辑器挂载时正文还没灌回来、此时是空文档，ProseMirror 照样报 `docChanged=true`，只看这一个标志会把它当成学生清空全文：整篇记一次删除、source map 被清掉，回填后又整体标成 `user_typed`，还会喂出假的「疑似未标注导入」。挡掉这两类之后，剩下的空文档就真是**全选删光**，如实留痕、构成占比即时清零。

保存可靠性：失败后**指数退避自动重试**（2s/4s/8s 共 3 次，徽章显示 Retrying…，全部失败才落 Save failed）；一个保存周期只创建一个版本（重试复用）；存在未保存变更时刷新/关闭页面会弹 **beforeunload 确认**；**客户端路由跳转**（切到别的会话/页面）时 beforeunload 不触发，改由组件销毁前补发一次 autosave 兜底。

### S5.5 提交前 AI 读者试读

仅当作业 `challenge_enabled=true` 时存在（修订初稿作业结构上没有这一环节，提交按钮直接进反思，见 T3）。这是与左侧辅导助手相反的另一个角色：**质疑读者只提问，不给可粘贴的文本**，且不进入聊天框，两边口吻不互相渗透。设计依据见 `PRD.md` 12.9。

流程 `点提交 → 契约声明 → 质疑 2~3 轮 → 收尾清单 → 回去修改 或 继续提交 → 反思 → 提交`。

界面上（`ChallengeDialog.svelte`）：

- 点「提交作业」后先强制落盘一次草稿（`manual`；试读针对服务端最新那一稿，正文没变时最新版就是当前稿，不再另开版本），再弹出试读。未选模型会提示先选模型。
- **首屏是契约声明，不是第一条质疑**：「我是一个不同意你的读者 / 我不会帮你改任何一句话，我只说哪里说服不了我 / 一共 N 轮」。不先亮契约，学生会一直向它求助然后判定这 AI 很笨。
- 正文是**卡片式单轮推进，不是聊天流**：一条质疑 + 一个回应输入框 + 一个「提交回应」。顶部常显「第 N 轮 / 共 M 轮」，让学生看得到终点；已答回合折在上方可回看。
- 「这次跳过」常驻但弱化（link 样式），任何阶段可点。**契约页上还没开始就跳过，同样会落一条 `skipped`**——连开都不开的那批学生才是最该被教师看到的，不落库的话他们反而在质疑维度上完全空白。
- 收尾页给「站得住的 / 还需要改的」两栏，出口有两个：**「回去修改」**（关弹窗回编辑器，这是试读能真正作用于正文的唯一入口）与「继续提交」（进反思弹窗）。
- 未答满时「提交回应」按钮禁用；刷新页面会通过 `challenge/current` 恢复到原轮次，已答内容不丢。
- 收尾清单回流到写作面板（`ChallengeChecklist.svelte`，桌面面板与移动抽屉都在 `AssignmentBrief` 下方），每条可勾选，状态经 `PATCH .../checklist` 存服务端。
- 清单下面挂着**本轮完整往来的折叠区**（默认收起，`ChallengeTranscript.svelte` 与教师端共用）。此前关掉弹窗就只剩三条摘要，而真正要拿这份记录去改文章的是学生——教师端反倒一直有完整记录，方向是反的。数据用写作面板已持有的那份，不额外请求。
- **每一轮质疑都引用原文里的一句**，界面上以琥珀色竖线标出。引用是修订判定的锚点，格式要求写在服务端拼的消息里，不在管理员可编辑的提示词里。

界面措辞一律回避「对抗」「挑战」「找茬」——那会让学生进入防御姿态；用「AI 读者试读」，学生的心理位置才是「我在准备」而不是「我在被考」。对外一律写全「AI 读者」，不简称「读者试读」：学生要知道问他的是谁。

- `POST /api/v1/assignments/{id}/challenge/start`（body: `writing_session_id` + `model`）→ 冻结当前最新版本为 `source_version_id`，返回 `{session, turns}`，含第 1 轮质疑。正文短于 100 字符返回 400（空白页上来被问三个问题只会让学生关页面）；本轮已有质疑记录也返回 400（一轮只质疑一次）。
- `GET /api/v1/assignments/{id}/challenge/current?writing_session_id=` → 恢复未完成的质疑，刷新页面不丢已答回合；本轮没有则返回 `null`。
- `POST /api/v1/challenge/{sessionId}/respond`（body: `turn_no` + `response_text` + `model`）→ 未答满就返回下一轮，答满 `planned_rounds` 就转收尾并把 `closing_summary_json`（`{stood, unresolved}`）写进 session、status 置 `completed`。**回合上限由服务端代码兜死**，跳答、重复答、超轮一律 400。
- `POST /api/v1/challenge/{sessionId}/skip` → status 置 `skipped`。允许跳过但跳过留痕，教师可见；强制不可跳过只会逼出敷衍答案。
- `POST /api/v1/assignments/{id}/challenge/skip`（body: `writing_session_id`）→ 契约页尚未开始就跳过时走这条，直接落一条 `skipped`（无回合）。本轮已有记录返回 400。
- `PATCH /api/v1/challenge/{sessionId}/checklist`（body: `checked_indexes`）→ 收尾清单的勾选状态持久化（完成后才可用）。
- `GET /api/v1/submissions/{submissionId}/challenge` → 教师读本轮质疑往来；本轮没做过质疑返回 `null`。

焦点维度取自作业的 `challenge_focus_keys`，必须是本作业 `rubric_schema.criteria` 里已有的 key（1~2 个），按轮次轮转（`focus_keys[(turn_no-1) % len]`）。未配置评分维度的作业不允许启用质疑——学生被追问的点就是最后被扣分的点。

**上一轮被教师退回、且教师勾了「让读者就这条意见追问」时**，那条退回意见会在发起本轮质疑时冻进 `challenge_session.followup_comment`，作为每一轮的首要指向。焦点维度仍照旧轮转（不替换，否则班级层面的维度聚合会塌），教师那句话叠在上面。

收尾清单的每条「还需要改的」都带 `turn_no` 与由它映射出的 `focus_key`——让模型报维度它会瞎编，报轮次错不了。归属不上的条目照样展示给学生，只是不进班级统计。

措辞由管理员维护在 `education.challenge_prompts`（`turn` / `closing` / `insight` 三段），与三档辅导风格同一机制。输出格式（引用原文、JSON 结构）由服务端拼的消息强制，管理员改措辞改不掉格式——格式是判定的地基。

### S6 提交作业

点 Submit Assignment 弹出**提交前反思弹窗**（`ReflectionAnswerForm.svelte`）。题目来自作业上教师自定的 `reflection_questions`（见 T3.6）：

- 第一题固定是「本次提交是否使用了 AI？」（`ai_used`），**不归教师改**；**修订初稿作业不问这道题**（2026-10-02 起）：首轮通读是平台替学生发起的，一定用了；让学生自报只会多一个和对话记录矛盾的口子。前端不显示、按「用了」显示其余题，后端提交时一律记 `ai_used = True`、不看客户端；
- 其余题按作业设定渲染（单选 / 多选 / 填空），并按每题的「给谁看」随第一题的答案出现或隐藏（例如「AI 在哪些方面帮助了你」只给选了「使用了 AI」的学生）；
- 必答题没答、选了「其他」却没写说明，提交时 toast 提示对应的题目；选填题标「选填」；
- **修订初稿作业**：修改清单漏标时，除了 toast 和漏标条目的红框，还会把弹窗滚到第一条漏标的位置（清单长时那条常在下面看不到）；正文和初稿还一模一样时，弹窗顶部一行灰字提醒「正文和你交的初稿还一模一样。仍然可以提交，老师会看到这一点。」——只提醒、不拦（学生可能真认为不用改，理由写在清单里由老师判断）。
- 弹窗高度卡在视口内：标题与「取消 / 提交作业」固定，只有中间题目区滚动（题目数量由教师定，矮屏上按钮不能被挤出屏幕）；
- 回答按题目 id 存 **localStorage 草稿**（按作业隔离，关弹窗再开仍在，提交成功后清除）；教师中途改了题，对不上的旧答案提交时自然丢弃；
- 未超过**有效截止时间**（见 S9 规则），超期按钮禁用、工作区只读；
- 提交请求期间按钮禁用并显示「提交中」（防重复提交）。

通过后：先 `submit_preflight` 保存（正文没变则不开新版本），再调用 `POST /api/v1/assignments/{id}/submit`，提交 `writing_session_id`、终稿内容、`ai_used`、`reflection_answers` 和适用的 `revision_decisions`。后端校验教学权限、班籍、会话归属和作业匹配、已确认初稿、当前轮是否已批改及有效截止；作业已没有 `status=active/archived` 校验。反思按当前题目严格校验并冻结题目与回答；修订初稿的「要改」项须有处理，其中选 `partly / kept` 时必须说明原因，「可改进」项可选。随后创建 submit 版本，保存当前轮提交、反思和 `stats_json.coaching / challenge / revision_items` 快照，冻结画像事实证据并生成版本化投影、聚合及提交分析，最后发 `submission_created` 通知。通读未成功时清单快照为 `missing`，不因平台未生成清单而阻止学生提交；已生成清单的处理校验不能绕过。前端成功后回到 `/me/writing`。

### S7 提交后与轮次规则

- `WritingSession.status = submitted`。
- **重要：提交 ≠ 锁定。** 提交后、老师批改前，只要没过有效截止，工作区照常可编辑，提交按钮变为「重新提交」，学生可以反复改稿重交。首页卡片因此不写「待批改」而写「已提交·截止前可修改」，避免学生以为已经交死、或以为还能改是 bug。教师端此时看到的始终是学生最近一次提交的版本。
- 当前轮 review 为 `pending`（或不存在）时再次提交 = **覆盖当前轮**（截止前改错别字不产生新轮）；
- 当前轮已 `returned`（退回）后再次提交 = **开新轮**（round_no+1，旧轮 `is_current=0`，旧稿/反思/评语/分数全部保留可追溯）；
- 当前轮保持 `reviewed`（已批改）时禁止再交（后端 409，工作区只读）；正常重交流程由教师在实例允许时显式退回。教师若将当前评阅重新存成 `pending`（「存草稿」，见 T7），它就不再处于已批改状态，截止前按 pending 的覆盖当前轮规则处理，并不会因此产生新轮次。
- 学生可随时通过工作区**「提交记录」**弹窗回看自己各轮快照与评语（见 S4），与教师端轮次视图对称。

### S8 收到批改反馈

Socket 通知 + 首页卡片 + 工作区批改卡片三处同步：

- **reviewed**：绿色卡片 — 轮次号、**分数/满分**、按作业 `rubric_schema` 展开的**各维度名称 + 得分/该维度满分**（未评的维度显示 —）、总评、批改时间。同一张卡片也用在「提交记录」弹窗里，历史轮次同样按维度名称展示。**该轮已定稿：编辑器转只读、提交按钮消失**，提示「如需修改，请让老师退回作业」——仅在管理员开着「退回重写」时这样说；关着时老师没有退回入口，改为「已批改，作业只能查看。」。定稿（已批改或已截止）后工作区收成「只读回看」形态：顶部徽标改为「已批改 + 分数」，去掉保存状态和截止倒计时；作业要求、试读待改项（勾选框禁用）、留痕告知收进「查看作业要求与试读记录」（作业没开试读时只叫「查看作业要求」，修订初稿作业一律如此），批改卡片因此排在最前；左栏若该作业用过 AI 对话则自动载入上次的对话供回看，没用过则提示「这份作业没有 AI 对话记录」。**修订初稿作业写作中**也一样：进来时地址里没指定对话、会话有 active_chat_id 就直接载入那段（首轮通读那段对话是改稿主线，落在空白新对话里学生看不到之前的讨论）；载入前先确认对话还在，学生删掉了就照旧停在新对话（载入不存在的对话会被带回首页）。
- **returned**：红色退回横幅 — 退回评语 + **新截止时间 `resubmit_due_at`** + "修改后重新提交"引导；后端把 `WritingSession.status` 打回 `draft`，**编辑器解锁**。

### S9 修改重交（有效截止规则）

学生该作业的**有效截止时间**按优先级取第一条命中的：

1. **个人延期** `assignment_extension.due_at`（教师单独给这个学生设的，最具体，压过下面两条）；
2. 最近一次退回的 `resubmit_due_at`（多次退回以最新为准）；
3. 作业原始 `due_at`。

个人延期只影响被授予的学生，同班其他人仍按全班 `due_at` 关闭；教师授予和撤销都会发通知，学生不会按错的时间写。截止前、且当前轮未被批改时，可修改并重新提交（走 S6 流程；待批改时重交覆盖当前轮、退回后重交才 round_no+1，见 S7；教师再收 `submission_created`）。工作区锁定只读、禁止提交的两种情况：**超过有效截止**，或**当前轮已批改**。

### S10 学生端状态机小结

```
not_started ──打开作业──▶ draft ──提交──▶ submitted(pending)
                            ▲                    │
                            │        ┌───────────┴───────────┐
                            │   reviewed(当前状态只读)      returned(退回)
                            │      正常重交由老师退回          │
                            └────── session 回到 draft ◀─────┘
                                     (新截止 = resubmit_due_at, 重交开新轮)
```

### S10.5 成长画像里的「面对质疑」

写作过程维底部多一块「面对质疑」（只在该学生至少有一轮做过试读时渲染）：做过试读的轮次数、最近一次的回应完成度、试读后回去改了的轮次数；有跳过的轮次会单列一行说明。

放在过程维而不是 AI 协作维是有意的：质疑读者不是帮手，并进「AI 协作」会把两个刻意分开的角色又混回去。

数据来自提交时冻结的 `stats_json.challenge`，画像层不回读 `challenge_session` / `challenge_turn` 原表。作业没开试读的轮次这几项是 `null`，表示**不适用**而不是表现差，不进任何分母。

### S11 我的成长 `/me/writing/growth`

- 「轮次之间的修改」一页只有退回重交才有数据：管理员关了退回、该学生也没有旧的重交记录时，学生端和教师端都不显示这一页（2026-10-03 起）。教师端「最近一次数据完整度」不再显示 `metric 2026-10-01.1 · aggregate r11` 这类内部版本号，只在看的不是当前指标口径时写「历史算法」，版本号放进悬停提示。
  写作首页页头右侧「我的成长」进入（面包屑「写作」返回），`GET /api/v1/me/writing/profile`。与教师端学生画像页共用 `StudentGrowthProfile` 组件（`variant` 区分），**指标值与趋势两端一致**，但**指数公式只发给教师端**：`index_formula` 在 `TeacherStudentProfileResponse` 上，学生端响应里没有这个字段，页面上「这些指数是怎么算的」折叠块也只在 `variant="teacher"` 渲染。学生看得见自己的分和变化，看不见及格线在哪 —— 阈值（改够三成、写满三天）一公开就是一份刷分说明书。三维：

- **产出**：三张趋势图。标准化得分（教师分 ÷ 作业满分的得分率，跨作业才可比）；成文篇幅（提交稿字符数，单位「字」）；评分维度（每条线一个维度，得分 ÷ 该维度满分；维度按键名+名称跨作业对齐，某次作业没有该维度时折线在那里断开，图上有副标题说明）。只折算得分率，不合成指数。每张图下的数据表默认收起
- **过程**：过程投入指数、**修订深度**（回头删改字数 / 写入字数，30% 记满分）、有效写作时长、临交突击占比、开工提前量。
  刻意不用版本数：一个版本只是一次自动保存，数量只反映打字时长
- **AI 协作**：AI 协作指数 = (提问质量 + 反思质量) / 2，本轮没有有效学生提问的提交只看反思质量；AI 占比；**提问质量**、**反思质量**（都是教师批改时给的 1—5 分折算到 0—100，**未批改为空**；本轮有有效学生提问时「已批改」必须给提问分，无有效提问则不能给；平台自动发起的消息不算）。提问数只作参考、不计入。曾按反思字数、提问条数计分，以及「消化度 / 平均改写率」（AI 片段改写比例平均），都已废弃

另有轮次进步（退回→重交之间的改写幅度/字数/分差/响应时长）、规则生成的结论（`insights`，后端只给 code + 参数，文案走前端 i18n）。突发插入、疑似未标注导入等**风险信号不参与任何成长指数**。

> 2026-09-14 起反思题由教师按作业自定，「AI 帮了你什么」不再是全站统一的选项，**AI 用途分布、生成→打磨迁移比例及其洞察已下线**（`PROFILE_METRIC_VERSION` 2026-09-14.1）。

## 二、教师端 Userflow

### T1 注册进入

`/auth` 选 Teacher 注册（不填邀请码）→ 按实例 `ui.default_user_role` 取得平台角色；默认 `pending` 时等待管理员批准，已为 `user` 时进入初始化 → `/education/setup` 创建第一个班级 → `/teacher`。教学教师组身份与平台激活状态分别校验，不在本次文档校准中修改审批配置。
教师侧边栏只有「教学」入口：「写作」入口与「写作项目」区只对学生和管理员显示（2026-10-01 起，写作对教师无实际用途）。路由 `/me/writing` 与个人写作接口未对教师封禁，只是不给入口。

### T3 布置作业

教师进入 `/teacher/assignments/new`，经 `POST /api/v1/assignments` 向一个或多个本人班级发布，各班生成对应作业并通知学生。表单支持标题、要求、班级、截止、评分维度、满分、作业形式、辅导档位、反思题和适用的读者试读配置；也可经 `?from=` 复制作业。

- 新建时先调 `GET /api/v1/teacher/assignment-defaults`，读取管理员为本实例配置的 `task_mode / coaching_style / rubrics`。代码默认作业形式为 `from_scratch`、档位为 `balanced`；维度按作业形式分别配置，不能把哈工深课程的 8 项维度写成所有实例的固定默认值。
- `task_mode` 仅为 `from_scratch / revise_draft`。修订初稿先确认基线，再通读与修订，结构上不能启用读者试读，数据库 CHECK、后端表单和前端共同约束。
- 每个评分维度有名称和分值，满分为维度配分之和，前后端校验一致。首次提交后满分和维度锁定；已有基线或提交后作业形式锁定。
- 辅导档位为 `socratic / balanced / hands_off`，措辞由管理员维护。`education.enable_coaching_styles` 关闭时表单不提供档位选择，对话只使用任务说明，提交快照的 `style` 为 `null`、档位 `prompt` 为空。
- 任务说明、辅导提示词及读者试读提示词分别由管理员配置，教师配置教学对象与参数，不维护全实例提示词。
- 反思题支持沿用教师最近作业、导入以往题组和恢复推荐题组，具体规则见 T3.6；复制时仍按当前作业形式与锁定边界校验。

### T3.5 配置提交前 AI 读者试读（可选）

作业创建页与作业详情页的评分维度下方是 `ChallengeSettings.svelte`，**只有三个控件**：

- 开关（拨杆式，右侧显示「开启/关闭」；未配置评分维度时置灰，并提示先配置维度）
- 追问轮次：2 或 3，不提供无限
- 追问维度：从本作业的评分维度里勾 1~2 个

这一项**单独框成一块面板**（圆形问号图标 + 标题 + 「交出去之前的最后一道关」标签），开启时整块描边转黑/暗色转白，选好维度后底部给一条生效摘要（「交卷前，学生要就「立意 · 论据」接受 3 轮追问。」）。平铺在普通表单项里教师会直接划过去——它开了就会在交卷那一步拦人，不是一个普通选项。面板里还常驻一句与辅导风格的分工说明：辅导风格管写的过程，这一项只在点提交那一刻起作用。

焦点直接复用评分维度，教师不用学新概念；学生被追问的点就是最后被扣分的点，质疑方向与评分标准天然对齐。维度被改名或删除后，界面会自动剪掉失效的焦点 key（不剪的话保存会 422，教师看不懂那个报错）。关掉开关时焦点一并清空。「复制为新作业」会沿用这三个字段。

措辞不归教师管：`turn`（单轮质疑）与 `closing`（收尾）两段提示词由管理员在 `education.challenge_prompts` 维护，与三档辅导风格同一机制。

### T3.6 设定提交前反思题

作业创建页与详情页最下方是 `ReflectionQuestionsEditor.svelte`，该节**默认展开**（折成一行摘要时老师以为题没了）。不同作业要问的反思不一样，所以题目归教师定；只有「本次是否使用了 AI」由系统固定先问（它是来源留痕的一部分），编辑器顶部说明这一点。

**修订初稿作业的反思题另有一套**（2026-10-02 起，`reflection-questions.ts` 的 `defaultFor` / `hiddenFor`）。起因：走查时学生提交要答「修改清单 + 是否用了 AI + 5 道默认题」，其中「改了什么、改在哪、为什么这样判断」和修改清单问的是同一件事（测试提交里「为什么这样判断」答的就是「见修改清单」），「AI 在哪些方面帮助了你」对话记录里一清二楚。所以：

- 不问「用了 AI 吗」（见 S6），编辑器里也不显示「给谁看」（只给没用 AI 的学生的题会标黄提醒「不会出现」）；
- 默认题只有一道，问对话、清单、初稿终稿对比都看不到的东西：「除了修改清单里那几条，你自己觉得这份稿子还有哪里没写好？为什么？」（2026-10-03 学生视角走查后换掉原来的「对照评分维度，最弱的是哪一项」——学生照抄清单上没改完的那一条；旧题留在题库里，只对从零写作显示）。「文中引用的每一篇文献，你都亲自查到原文了吗？」（全部查到 / 部分查到 / 没有查）原本也是默认题，同日移出默认、留在推荐题库一键可加：AI 在对话里按「出处与参考文献」追问出处是否真实、有没有查到原文，修改清单里也有这一项，学生会被问三遍；老师想要一份可统计的自述时自己加；
- 推荐题库不列和清单重复的题（AI 帮了什么、改了什么、改在哪、为什么这样判断、哪条 AI 建议没采纳、AI 塑造了多少、为什么没用 AI）；
- 编辑器顶部换成一段说明：对话里 AI 按评分维度追问、提交时先交代修改清单、改动看对比，这里只问这些都看不到的——教师自拟题目时不用去猜 AI 会问什么；
- 切换作业形式、或新建作业沿用上一份作业的题时，若题目还是另一种形式的默认题（没动过，按 `reflectionQuestionsFingerprint` 比），自动换成这种形式的默认题；动过就不碰；
- 作业概览和表单折叠摘要写「N 道反思题，另有修改清单」。

- **题型**：单选 / 多选 / 填空。选择题可勾「加一个『其他』选项，选了要写说明」；填空题可写答题框提示语（编辑器里题目下方单独一栏，标「答题框提示」、灰字，学生作答前在输入框里看到，一打字就消失）。每题可设「必答」与「给谁看」（所有学生 / 仅用了 AI 的学生 / 仅没用 AI 的学生）。可上移、下移、复制、删除；选项框里回车直接新增下一项。上限 20 题、每题 12 个选项。
- **不从零写**：
  - 教师**第一次**出题：预填推荐默认题组（AI 在哪些方面帮助了你〔仅用了 AI 的学生〕、你具体修改了什么、修改了哪个位置、为什么这样判断、下一次准备怎么做），删改即可；
  - **之后新建作业**：默认沿用该教师**最近一份作业**的题，顶部蓝条注明来自哪份作业；
  - 「从以往作业导入…」下拉列出该教师以往用过的题组（`GET /api/v1/teacher/reflection-question-sets`，新的在前、内容相同的只留一份——一次发布到多个班会建出多份相同作业；比较时忽略题目 id），「恢复默认」回到推荐题组；整套替换前若当前已有题目会弹确认；

- **学生视角预览**：用与学生弹窗同一个组件渲染，可以点「使用了 AI / 未使用 AI」看题目的显隐。
- **改题时机**：随时可改（有提交后也可以），详情页会提示「修改只影响之后的提交」。已交反思存的是提交当时的题目快照。
- 保存前前端先整理（去空白、丢空选项）并校验，后端 `ReflectionQuestion` / `validate_reflection_questions` 再严格校验一遍（选择题至少两个选择、选项不重复、填空题不能带选项、题目 id 不重复）。

### T4 作业编辑、截止与删除

作业没有归档功能、`status` 或 `archived_at` 字段，也没有归档接口。列表的「进行中 / 已截止 / 待批改」由截止和提交情况派生，不能按旧接口改变存储状态。

- 设置入口 `/teacher/assignments/[id]/settings`，保存使用 `PATCH /api/v1/assignments/{id}`。可编辑标题、要求、截止及允许修改的配置；已有提交时禁止改变所属班级。
- 首次提交后满分与评分维度锁定；已有初稿基线或提交后作业形式锁定。作业更新前后都验证「修订初稿不能开读者试读」的组合。
- 辅导档位和反思题可按当前配置规则修改，工作区下次装配读取最新设置；已提交轮次仍读取当时冻结的提示词、题目与答案。关闭档位时不注入档位提示词。
- 修改截止会通知班级学生；单个学生延期在「提交与批改」的未提交名单中单独设置，不影响其他学生。
- 删除使用 `DELETE /api/v1/assignments/{id}`，前端确认后提交；仅无提交且无学生写作会话时允许，后端拒绝有业务记录的作业。删除时清理对应作业通知，不提示改用不存在的归档功能。
- 达到有效截止的学生工作区只读，作业本身仍可由教师查看、批改和分析；延期或退回期限的具体优先级见 S9。

> **教师端页头**：所有教师页共用 `TeacherPageShell`，导航只在顶栏一处（定义在 `teacher-nav.ts`）。页头内容与正文**共用同一栏宽**（壳的 `width`：默认 6xl，新建作业 5xl，批改工作台铺满），自上而下：**四个分区**分段控件（总览 / 班级 / 作业 / 批改；批改工作台归「批改」）、**面包屑**（第一级「教学」可点回总览，由壳统一补上）、**唯一 H1（当前对象）**与同一行右端的页面主操作（「+ 创建班级 / + 新建作业 / + 添加学生」，总览页在已有班级时也有「+ 新建作业」），对象页下方再有一条**子标签**（作业 4 个、班级 2 个；同一对象的各标签页栏宽一致，切换时页头不跳）。原来放在正文里、一滚就看不见的分区胶囊导航和各页的「返回 X」按钮都已删除。

- **Prompt Timeline**：学生与 AI 的完整对话记录；AI 回复按 Markdown 渲染（`marked` + `DOMPurify`，标题压成小号），修订初稿作业里一条诊断动辄上千字，原样显示 `##`、`**` 读起来很吃力；
- **AI 澄清追问**（过程证据内）：AI 中途问了什么、学生怎么答的，由 `collect_clarification_exchanges` 从聊天消息的 `output` 纯派生，顶部四个计数（提问 / 回答 / **自由作答** / 跳过），自由作答绿底突出——点选项回传虽然带得回选项文字，但学生自己写的那句才看得出他在想什么。模型拼错参数被后端拒掉的调用记为 `invalid`，不计数也不展示。**只展示不进画像口径**（该工具是按模型配的开关，跨班不可比）；
- **AI 辅导风格**（反思 tab 内，这一轮没有档位生效时不显示）：教师读取提交时冻结的 `stats_json.coaching`，含 `style / prompt / task_mode / task_prompt`，可展开看当时的提示词原文。管理员关闭档位时 `style=null`、档位 `prompt` 为空；之后修改作业或管理员措辞不改写已提交轮次。证据 schema 变化应提升版本并走正式迁移，不能在读取时补写或修复历史证据。
- **第一次通读**（反思 tab 最上方，`RevisionItemsReview.svelte`，仅修订初稿作业）：每个评分维度一行——通读的档位（要改 / 可改进 / 达标 / 暂缓）、一句话结论、原句、学生的处理和说明，读提交时冻存的 `stats_json.revision_items`；补看补上的标「补看」，挡住暂缓项的那一项补看时确认改到位的标「补看时已改到位」，提交时仍是暂缓的说明学生没改好那一项（或没点补看）。评分 tab 里每一行维度下面也有一行小字：「第一次通读：要改 · 学生：改了一部分 · 原句一字未动」（补看补上的写「补看：……」）。学生说改了（或改了一部分）而那句原句一字未动时标红——只说明动没动，可能是在别处做了等效修改，由老师判断。这一轮没通读成时说明原因。
- **提交前反思**（反思 tab）：先显示固定题「是否使用了 AI」（修订初稿作业不显示，学生没被问过），再按提交时冻结的题目快照逐题显示学生的回答（选项以标签呈现，「其他」带说明，未答的选填题标「未作答」）。教师后来改了作业的题，这里仍是学生当时回答的题；
- **来源统计行下方的信任口径**：来源占比由学生浏览器在写作过程中记录，可能不完整也可能被绕过，界面明说它用于和学生讨论过程、不作为学术不端的证据；「过程关注点」标注为启发式指路而非判定。同一句口径也出现在看板的高风险提交列表上方；
- **分析摘要**：疑似未标注导入、大段突增、手打 / AI / 外部粘贴与声明初稿等逐份过程事实，不含平均改写率或消化度。GET 分析接口只读已物化结果，缺少可用分析返回 409，不扫描原始历史或自动补建。显式 `POST /api/v1/teacher/submissions/{id}/analysis` 从该提交冻结的 evidence 构建分析并保存，不再按「历史轮一律拒绝」处理；没有冻结证据时返回 409。当前 UI 的历史轮操作仍只读，不能据此把接口的证据校验误写为仅限当前轮。
- **片段详情 / 写作过程时间线的中文化**：后端时间线条目里的 `label` / `message` 是拼好的英文串（`Version 7`、`ai_pasted:paste_detected`），前端不显示它们，一律按 `event_type` 与 `source_type` / `op_type` / `trigger_type` / `rewrite_level` 经 `$lib/utils/education.ts` 的 `getWritingSourceLabel` 等函数翻译；疑似导入的 `suspicion_reason` 是后端固定英文句，直接作 i18n 键；
- **连续手动改稿合并成一段「修改正文」**（`analysis.py` 的 `_build_operation_timeline`，事件 `typing_run`）：编辑器每次输入都记一条操作，输入法每上屏一个词就是一条，逐条列出时改一句话就刷出几十行「手动输入 +1 字」，把对话和版本淹没（2026-10-02 走查实测一句 21 行）。现在连续的手动输入/删除/替换并成一段，遇到对话消息、粘贴或 AI 插入（这些仍单独成行），或停笔超过 10 分钟才另起；每段显示时间范围、「+N 字 · −M 字 · K 次编辑」，点「看改了什么」展开写入与删去的原文（各截 400 字；退格是从后往前删，按原顺序拼回）。按学生端发生时间 `occurred_at_ms` 切段，不用入库时间——操作是攒到自动保存或发送前才上传的，入库时间会和对话消息挤在同一秒。当前 `_ANALYSIS_LOGIC_VERSION` 为 `7`；GET 不会自动重算，不可用时需经显式分析 POST 从冻结证据生成；
- **轮次切换器 + 前后稿 diff**（`GET .../diff`）：当前轮 vs 上一轮红绿标注；历史轮（is_current=0）整页只读。
- **修订初稿作业：初稿 → 终稿**（`GET .../draft-diff`，过程 tab，仅 `task_mode=revise_draft` 显示）：从学生声明的初稿（`writing_session.draft_baseline_text`）到本轮终稿的完整修改，红绿标注与「与上一轮对比」共用 `TextDiffBlocks.svelte`。**按句对比**（句末标点或换行断句）：初稿到终稿常整段重写，逐字对比会把新旧两版绞成碎片，按句对比时删掉的旧句与写进的新句各自完整。退回重交后起点仍是最初那份初稿。修订初稿作业没有试读三栏，学生「接受/拒绝了哪些建议」靠这里和 Prompt Timeline 对照核实。
- **source map 片段不做文本清洗**：`NormalizedSegment` 原先对所有片段 `strip()` 并在文本变化时丢弃偏移量，从段落换行处开始的片段（如 `
三、…`）因此整段落成「来源未知」；source map 片段本就是编辑器原文、偏移量已逐字核对，现在原样保留。这个问题所有作业都有，修订初稿作业最明显（未动的初稿段落都从换行处开始）。
- **已声明初稿**（`declared_draft`）：来源比例条单独一行「已声明初稿」（紫色，非风险色，其他作业不出现），正文高亮同色；不计入外部粘贴、疑似导入或过程关注点。分析摘要多 `declared_draft_chars / ratio`。
- **过程指标的起点**：版本差异、大段突增与画像修订深度从本轮起点计算——重交轮是上一轮终稿，修订初稿首轮是已确认初稿，不能把整份初稿算成大段写入。初稿随证据冻结，当前证据 schema 与 `PROFILE_METRIC_VERSION` 为 `2026-10-01.1`；分析逻辑版本独立为 `7`。历史迁移 `e8a0c2d4f6b7` 的空表守卫及显式重算属于对应部署步骤，不是普通读取时的自动清表、补建或重算。

分析结果提供六个只读接口，都是同一份缓存 payload 的字段切片：`GET .../analysis`、`.../analysis/summary`、`.../analysis/timeline`、`.../analysis/highlights`、`.../analysis/segments`、`.../analysis/segments/{segmentId}`。

### T6.5 看这一轮的 AI 读者试读

提交详情里，AI 澄清追问块之后是 `ChallengeRounds.svelte`（本轮没做过试读则整块不渲染）：

- 顶部一行结论：完成 / 学生跳过、答了几轮，以及**被质疑的几处里改了几处**
- 逐轮三栏并排：**被质疑的那句原文 → 质疑与学生回应 → 该句在最终稿里的样子**；某轮没答会显式标出，某句没动会明确写「没有变化」，被整段删掉会写「已经不在了」
- 末尾给读者的收尾结论（站得住的 / 还需要改的）

**判的是位置不是字数。** 老口径用全文改动量加最小字符阈值，方向是反的：被质疑之后最理想的修改往往最小（删掉一个站不住的例子、把「所有人都认为」限缩为「我采访的 12 个同学里有 9 个」），那些都过不了阈值；而在结尾补一句无关套话稳过。现在只看被引用的那句在最终正文里还在不在。

**这里只呈现「那处变没变」，不判「改得对不对、是不是真回应了质疑」**。引入 AI 自动裁定的方案已在 2026-09-09 否决，不再作为待定项；可能在别处作了等效修改，最终由教师结合正文与回应判断。

**信任层级与来源占比那一块不同**：质疑文本、引用的原文片段、回合数、收尾清单都是服务端生成的权威数据；学生回应是他自己敲的字（等同 typed）；「那句变没变」由发起质疑时冻结的 `source_version` 快照与最终提交正文直接比对得出，同样是服务端权威数据，不依赖客户端上报、也不受客户端时钟影响。因此这一块**不挂** `EduEvidenceDisclaimer`——那句免责说的是客户端上报口径，挂在这里会把权威数据错误降级。

这一块的价值在于：其它块给的都是量化占比，教师看完不知道该说什么；这里给的是「他被问到论据不足，回答说我觉得够了，然后一个字没改」——能直接拿到课堂上讲。

### T7 批改（闭环核心）

批改区自上而下是：**评分维度 → 总分 → 反思质量 → 提问质量 → 总体评语 → 操作按钮 →「退回修改」折叠区（退回说明 / 读者追问勾选 / 重交截止 / 退回给学生）**，保存走 `POST /api/v1/teacher/submissions/{id}/review`。

**退回重写是实例级开关，默认关**（2026-10-02 定）：多数课程批完就结束，学生看批改结果即可。管理员在「设置 → 写作辅导」顶部「允许教师退回重写」打开（config 键 `education.enable_return`，经 `/api/config` 的 `features.enable_education_return` 下发给前端）。关着时批改页没有「退回修改」折叠区，教师总览/作业概况/班级页的「已退回」卡片与列、审阅队列的「已退回」标签都隐藏，后端对 `review_status=returned` 返回 403。下文退回相关的流程都以开关打开为前提。

- **评分维度**排在最前，每个维度一个下拉，选项按该维度满分生成、**从高到低**排列（批改时命中的多是接近满分的档位），首项 `—` 表示未评。
- **总分只读**，由各维度分求和派生；评完全部维度才出数，否则显示破折号并在同一行提示还没评完。总分因此不可能越界、也不可能与维度之和不一致，前端不再做这两项校验。
- **反思质量 1—5 分**（`reflection_score`），由教师评价，是画像该维度唯一来源；不按反思字数自动计分，未评分时保持空值。「完成批改」时必填。**提问质量 1—5 分**（`prompt_score`）依据冻结证据中的本轮有效学生提问是否存在：有提问时完成批改必填，无提问时不显示、不要求且后端拒绝提交该分数；平台自动首轮与补看消息不计入学生提问数。
- **维度分后端存不了半份**（`rubric_scores` 要么全给要么不给），只评了一半去保存会提示「保存前请评完全部维度」，而不是悄悄丢掉已选的几档。
- **批改状态不再由教师手选**（原来的三档按钮组已删除，状态只在页面顶部以徽标展示），一律由按下的按钮决定：

按钮分主次：主按钮「完成批改，下一份」（队列里没有下一份时显示「完成批改」）；有下一份时旁边多一个次按钮「完成批改」（停在本份）；「存草稿」是文字按钮。退回是另一条路：点「退回修改」展开后才出现退回说明、追问勾选、重交截止和「退回给学生」按钮（已退回的提交打开时默认展开）。

| 按钮                                   | 存成的状态      | 必填                                                               | 结果                                                                                                                                                                                            |
| -------------------------------------- | --------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **存草稿**                             | pending 待批改  | 无（评语可单独暂存）                                               | 仅暂存；已批改的作业按此键会退回成待批改                                                                                                                                                        |
| **完成批改**（停在本份）               | reviewed 已批改 | **总分 + 全部维度分 + 反思质量**，有本轮有效学生提问时还须提问质量 | 学生收 `review_completed`（含分数）；**该轮就此定稿，学生不能再交**（工作区转只读），教师可继续修改本轮评语分数（不新建轮次）；正常重交通过 returned；重新存为 pending 的状态变化见「存草稿」行 |
| **退回给学生**（「退回修改」展开区内） | returned 已退回 | 退回评语 + **`resubmit_due_at`（必须晚于当前时间）**               | 学生收 `submission_returned`（含评语与新截止）；学生 `WritingSession` 回到 draft 解锁                                                                                                           |
| **完成批改，下一份**                   | reviewed 已批改 | 同「完成批改」                                                     | 保存成功后自动跳到 pending 队列的下一份；队列清空时提示并回到 `/teacher/review`                                                                                                                 |

退回说明下方多一个勾选：**「让读者下一轮就着这条意见追问」**（`challenge_followup`，仅当作业启用了 AI 读者试读时显示）。勾上之后，学生下一轮提交前的质疑会围绕这条退回意见展开。此前退回意见写完就没下文了，学生看不看、改不改全凭自觉——这是产品里第一处 AI 直接执行教师教学意图而不是执行配置预设的交互。未启用试读、非退回状态、或没写退回意见时勾选会被后端拒（400）：不在这里替教师悄悄打开试读，也不在没有内容可追问时硬造一轮。

对历史轮（is_current=0）保存批改会被后端拒绝（400）。

### T8 多轮循环

新轮只由**退回**触发：教师退回 → 学生重交 → 新轮 `submission_created` 通知 → 教师在同一批改页切到最新轮、看前后稿 diff → 再次批改。提交列表 / dashboard / overview 的统计口径均为**当前轮**（待批改数 = 当前轮 pending 数）。

### T9 本次分析 `/teacher/assignments/[id]/dashboard`

作业的「本次分析」标签（原名「班级概览」，实际是单份作业的分析）。提交列表管「批到哪了」，这里管「这份作业大家是怎么写出来的」。

- 不再有全班风险合计卡（见 T2 末段）；还没有提交时整页只显示空状态；
- **全班第一次通读**（修订初稿作业，`distributions.first_read`，`revision_items.build_first_read_distribution`；没有带清单的提交则整块不显示）：每个评分维度一行——要改 / 可改进 / 达标各多少人，「要改」的人提交时改了 / 部分 / 没改各多少、几处说改了却原句未动、几人暂缓项一直没补看；要改人数多的维度排前面。按人数，每个学生只取最新一轮；头部写「N 份提交带修改清单 · K 份终稿与初稿相同」。修订初稿作业的逐份表格去掉永远是 0 的「AI 插入 / AI 粘贴」，换成「外部粘贴」和「修改清单」两列（修改清单列按终稿未改、说改了原句未动、要改项数排序）；改写分布为空时整张卡不显示。
- 改写分布：基本未改 / 少量修改 / 部分改写 / 大幅改写（unchanged / lightly_edited / moderately_rewritten / deeply_rewritten，经 `getRewriteLevelLabel` 翻译）段落占比条形，条长按真实占比（原来有 8% 保底，计数为 0 也画一段）；全为 0 时显示空状态；
- **全班在哪些维度上站不住**（`distributions.challenge`，本次作业没人做过试读则整块不渲染）：每个评分维度一行，给一句能直接拿去讲评的话——「论据支撑：28 人被质疑，21 人没答住，其中 15 人被质疑的那句一字未动」，按没答住人数排序。同一行还有一个**「以此为下次的质疑焦点」**——点了跳到新建作业页并预填该维度（复用 `?from=` 复制流程，连 rubric 一起带过去，焦点才说得通）。完成试读少于 3 人时明确标注只能当个案看。这一层是纯内存聚合，不调模型、不落表；
- **归纳成论证类型**（该区块底部按钮，教师点了才生成，不随看板自动加载——这是唯一会调模型的班级分析）：把全班没答住的点归纳成 3~5 类「普遍站不住的论证」，每类给类型名、命中人次、两条脱敏样例、一句课堂讲评建议。四条约束缺一不可：按输入哈希缓存（内容没变不重算）、完成试读少于 5 人直接拒绝出结论且一次模型都不调、送模型的载荷里只有维度名和条目文本（没有姓名学号提交 id，有断言守着）、只报频次不给班级下评价性结论。未传身份字段不等于原文彻底匿名，教师讲评使用样例前仍需按具体内容核对；
- **「建议先看」**：只列有疑似导入或大段突增的提交（按疑似导入优先，最多 5 份），一份都没有时整块不显示；上方写明留痕的信任口径；
- **「每份提交是怎么写出来的」表格**：学生 / 手打 / AI 插入 / AI 粘贴 / 提问次数 / 过程信号 / 有无反思（按微反思存在性计算），点表头排序（默认按过程信号），**整行直达该生批改页**；
- 收到教学通知自动刷新（手动刷新按钮已去掉）。
- 班级维度：班级概况 + CSV 导出（T2）；学生维度：**学生成长画像**（T10）。

### T10 学生成长画像 `/teacher/classrooms/[id]/students/[userId]`

班级学生名单点入（页面挂在班级的「学生」子标签下，面包屑 班级 / 班名），`GET .../students/{userId}/profile`。筛选放在画像分区标签下面、改了即生效：默认只露「时间范围」，作业 / 轮次 / 指标版本收在「更多筛选」里（有生效中的条件时自动展开）；「指标版本」只在教师端、且出现多个版本时显示。与学生端 `/me/writing/growth` **共用 `StudentGrowthProfile` 组件、同一套指标** —— 指标值和趋势两端看到的是同一份，才能拿着这页跟学生讲。比 S11 多四处：

- **「这些指数是怎么算的」折叠块**（`variant="teacher"` 专有）：展示对应算法版本返回的 `index_formula`，教师可核对过程投入与 AI 协作的构成。提问质量和反思质量来自教师评分，不再把「提问 10 条」当作质量阈值；没有本轮学生提问时提问质量不适用。学生端响应没有该字段，不展示公式、阈值与内部版本说明。
- 作业卡片可点入该次批改页（仅限本班作业；学生换班前在原班交的作业只展示、标「在其他班级提交」，见 S2.5）；
- 顶部显示学生姓名与邮箱。
- **口径核对信息**：洞察条目下的样本数 / 数据完整度 / 置信度 / 优先级、洞察与指标版本号（`insight …`、`metric … · aggregate r…`）、「最新一次数据完整度」卡、其他指标版本被排除的提示，都只在教师端显示；学生端只看结论和下一步建议。

时间线含**全部轮次**（历史轮 `is_current=0` 也在），而作业统计与平均分只算当前轮。

### T11 教研数据导出（管理员）`/admin/education`

`GET /api/v1/research/export`（挂 `get_admin_user`，**教师够不到**），返回 zip：

| 文件                 | 内容                                                                                                                                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `submissions.csv`    | 每份提交一行，当前算法下的最新投影（最新证据 × 最新批改），含全部过程/协作/质疑指标与四项数据完整度                                                                                                                          |
| `round_progress.csv` | 退回—重交之间的改动幅度、分数变化、响应时长                                                                                                                                                                                  |
| `reflections.csv`    | **每道反思题一行**（题目快照：位置/id/题型/题干/是否必答 + 选中选项、是否选了「其他」、回答字数 + ai_used + 教师给的反思质量）；一道题都没设的提交也留一行保住 ai_used。学生写的**原文默认不导出**，`include_text=true` 才带 |
| `README.txt`         | 导出时间、算法版本与校验和、班级范围、行数，以及各指标的信任口径                                                                                                                                                             |

两条硬约束：

- **假名化**：`pseudo_id = HMAC(WEBUI_SECRET_KEY, user_id)[:16]`，在同一密钥下稳定，导出不含账号姓名与邮箱字段；假名化不等于彻底匿名化，自由文本仍按实际内容处理。
- **指标 CSV 携带版本口径**：`submissions.csv` 和 `round_progress.csv` 含 `metric_version / algorithm_checksum`；`reflections.csv` 不逐行重复这两个字段，它按 `pseudo_id + assignment_id + round_no` 对应提交，导出 `README.txt` 说明版本、校验和与范围。不能把三份 CSV 都描述为每行带版本字段。

可选筛选：`classroom_id`、`start_at`、`end_at`。与 T2 的班级进度 CSV 是两回事——那份是给教师看谁交了没交的七列名单（姓名邮箱明文、零过程指标），这份是拿去做前后测和统计分析的。
