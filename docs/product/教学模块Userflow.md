## 0. 全局前提：身份体系与通知

### 模型显示名称（2026-11-09）

管理员在「设置 → 模型」编辑顶部模型名称；下方模型 ID 继续用于调用。段落论证学生输入框的固定模型名称由工作区的 `initial_state.teaching_summary` 读取当前保存名称，后续刷新共用本人写作会话的 `teaching-summary` 接口，不受普通聊天模型列表权限影响。管理员保存改名后，学生刷新工作区即可看到新名称，无需重新发布作业辅导版本；未自定义名称时使用模型目录名称，目录也无名称时使用 ID。此处仅控制界面显示，不承诺隐藏接口中的模型 ID。

### 0.1 注册与身份

- 注册页 `/auth`：填写姓名/邮箱/密码，并在下拉框选择教学身份 **Student / Teacher**（默认 Student），随 `userSignUp` 的 `education_role` 参数写入。
- **学生注册必须填班级邀请码**（2026-09-09 起）：选 Student 时邀请码为必填项，随 `userSignUp` 的 `classroom_invite_code` 一并提交。后端在建号前校验——未填返回 400 `Classroom invite code is required`，码无效或班级已归档返回 404 `Invalid classroom invite code`，两种情况都不会留下用户记录。
- **邀请码即审批**：有效邀请码学生注册后入班；正常默认新用户角色为 `pending` 时，学生被提升为 `user`，不进入管理员待激活队列。教师不需要邀请码，其平台角色跟随实例的 `ui.default_user_role`；默认 `pending` 时需管理员批准，配置为 `user` 时已激活，不能把审批写成与实例配置无关的强制步骤。空库首位管理员另适用初始化规则；管理员可在用户编辑弹窗调整教学身份。
- 例外：空库时的首个注册者会成为管理员，此时还不存在任何班级，故不施加邀请码要求。
- **登录邮箱与密码**（2026-10-06 起可自助改邮箱）：用户在「设置 → 账户」的「邮箱」栏改登录邮箱（`POST /api/v1/auths/update/email`，须验证当前密码，校验格式与占用，同步 `auth` 与 `user` 两表，不强制重新登录），「密码」栏改密码（`POST /api/v1/auths/update/password`，改完吊销全部会话并退出）。两栏都受 `ENABLE_LOGIN_FORM` 与 `ENABLE_PASSWORD_CHANGE_FORM` 控制（均默认开）。没有「忘记密码」/邮件重置：忘了密码由管理员在用户编辑弹窗直接填新密码（同样吊销该用户全部会话），管理员也可在那里改邮箱。
- **教学身份 = 权限组成员关系**（2026-09-03 起）：`education-teacher` / `education-student` 两个固定 id 的组，常量与唯一读写入口都在 `services/education/identity.py`（`get_education_role` / `set_education_role`）。给某一类身份统一开放模型、工具或功能，直接给对应的组配权限即可。
- **唯一写入口**：身份只能通过「编辑用户」弹窗（`/users/{id}/update`）或注册时写入。用户组页面对这两个组不开放成员增删（`/groups/id/{id}/users/add|remove` 返回 400），也不能删除该组；前端相应隐藏「用户」标签页与删除按钮，用户编辑弹窗里也不再重复列出这两个组。
- 约束：`admin` 角色不持有教学身份（`get_education_role` 由 `user.role` 直接派生为 `admin`，且 `set_education_role` 对管理员整体豁免，不动其组与班籍）；教学账号应设置有效 `education_role`；普通平台角色 `user` 本身不等于教学学生身份；只有学生能被分配进班级，且**一个学生至多在一个班**（见 S2、S2.5）。
- **班籍随身份走**：`classroom_member.member_role` 必须与账号当前身份一致。`set_education_role` 在换组后会删掉与新身份不符的全部班籍（跨班级，不止第一条）；反过来，教师名下仍有班级时禁止改身份（返回 400），避免 `classroom.teacher_id` 悬空。

### 0.2 首次引导 `/education/setup`

| 身份 | 引导内容                                                                             | 完成后跳转    |
| ---- | ------------------------------------------------------------------------------------ | ------------- |
| 教师 | 输入并创建**第一个班级**（自动生成邀请码）                                           | `/teacher`    |
| 学生 | 注册时已入班，此页不再出现；仅管理员直接建号的学生会走到这里（输入邀请码，也可跳过） | `/me/writing` |

- **守卫**：教学身份在注册时选定、仅管理员可改（后端 `/users/user/info/update` 拒绝非管理员修改 `education_role`）；引导页不再提供自助改身份。已完成初始化的用户（教师已有班级 / 学生已入班 / admin / 无教学身份）访问此页会被直接重定向。

### 0.3 课程课件（2026-11-07）

- 配置了 `COURSEWARE_DIR` 且目录内有 `index.html` 的实例，所有已激活学生、教师与管理员的侧边栏固定显示「课程课件」，展开和收起状态都可进入 `/courseware`；不受个人固定菜单设置影响。
- 未登录进入时先登录并返回课件。页面顶部可展开侧边栏或「返回 Right Write」主页，课件保留原互动与视频播放器。
- HTML、图片和每次视频请求（含拖动播放的 Range 请求）均复用服务端登录校验；待审核账号不可访问。未配置的实例不显示入口，文件接口返回 404。
- 课件由运维发布到实例私有目录，不上传知识库、不进入代码仓库。课件的勾选记录仍仅存在当前浏览器，不视为账号同步的学习进度。
- 发布方法见 [课件发布](../../deploy/README.md#课程课件发布)。

### 0.4 通知闭环（贯穿双端）

- 学生写作首页在对应作业卡片显示红色「新批改」或「退回通知未读」及条数，与侧边栏统计使用同一份未读通知。包含提醒的已提交、已截止分组自动展开；只进入首页不会清除提醒，打开对应作业后按作业标记已读。

- 存储：`education_notification` 表（user_id / type / payload_json / read_at）；实时推送走 Socket.IO 事件 `education:notification`；离线不丢，登录后由未读接口补齐。
- 前端：`(app)/+layout.svelte` 监听 socket → toast + 更新未读 store；侧边栏入口显示未读角标：展开时位于菜单文字右侧，收起时位于对应图标右上角；零条隐藏，超过 99 条显示 `99+`。教师「教学」统计未读提交通知，学生「写作」统计未读批改与退回通知，不等同于待批改作业数量。
- API：`GET /api/v1/me/notifications/summary`（未读数）、`POST /api/v1/me/notifications/mark-read`（按类型/作业批量已读）。

| 通知类型                       | 触发                             | 接收方       | 自动已读时机               |
| ------------------------------ | -------------------------------- | ------------ | -------------------------- |
| `assignment_published`         | 教师创建作业                     | 班级全体学生 | 学生打开该作业工作区       |
| `assignment_updated`           | 教师修改要求、截止、评分或反思配置             | 班级全体学生 | 学生打开该作业工作区       |
| `assignment_reminder`          | 教师催交（全部或指定未提交学生） | 未提交学生   | 学生打开该作业工作区       |
| `assignment_extension_granted` | 教师给该生设个人截止时间         | 被延期的学生 | 学生打开该作业工作区       |
| `assignment_extension_revoked` | 教师撤销该生的个人截止时间       | 该学生       | 学生打开该作业工作区       |
| `submission_created`           | 学生提交（任意轮）               | 该班教师     | 教师打开 Review / 提交列表 |
| `review_completed`             | 教师保存批改（reviewed）         | 学生         | 学生打开该作业工作区       |
| `submission_returned`          | 教师退回（returned）             | 学生         | 学生打开该作业工作区       |

- **教师端实时刷新**：教师首页 / Review 队列 / 提交列表 / 看板在收到教学通知时自动重拉数据（与学生端首页同一订阅机制），Review 与提交列表页同时把 `submission_created` 标记已读。

## 一、学生端 Userflow

### S1 注册进入

`/auth` 选 Student 注册 → **填班级邀请码**（必填）→ 注册成功即 active 且已入班 → 直接落地 `/me/writing`。不经管理员审批，也不经 `/education/setup`。

### S2 加入班级

- 入口①（主路径）：注册页的邀请码输入框——学生的第一个班级在这里就定了。
- 入口①b：setup 引导页邀请码输入框，只对管理员直接建号、尚未入班的学生有意义。
- **一个学生只能在一个班**（2026-09-23 起）：数据库部分唯一索引 `classroom_member_single_student_idx`（`UNIQUE(user_id) WHERE member_role='student'`，迁移 `a9c2e4f6b8d0` 建立，建索引前只保留每人最早加入的那个班、其余班籍直接删除）。教师可以带多个班，不受约束。
- 入口②：写作首页 `/me/writing` 的 Assignment Writing 区，邀请码输入框**只在未入班时出现**；已入班则显示「我的班级」+ 提示「每位学生只能加入一个班级，如需换班请联系老师或管理员」。未加入任何班级的学生进入首页后默认停在 Assignment Writing tab，保证一眼看到入口。
- 入口③：**邀请链接** `/join?code=XXX`（教师在班级页复制）。已登录学生打开后预填邀请码一键加入；**已在某个班的学生打开时只显示「你已在「X」班级中……如需换班请联系老师或管理员」，不给加入按钮**（页面先调 `GET /api/v1/me/classroom` 判断）；非学生身份访问会被提示并引导返回。
  - **未登录打开邀请链接**：被守卫重定向到 `/auth?redirect=%2Fjoin%3Fcode%3DXXX`，auth 页从 `redirect`（或自身 `?code=`）里取回邀请码，自动切到注册模式、身份锁为 Student 并预填邀请码——学生全程不用手抄码。注册成功时已由 signup 接口入班，直接落地 `/me/writing`，不再回 `/join` 二次提交（重复调 join 接口会 400 `Student has already joined this classroom`）。
- **加入按钮上方常驻一段采集告知**（`EduDataNotice`，`scope="classroom"`）：写作区记录哪些内容、任课老师能看到作业写作区的哪些、个人写作区老师看不到。只说采集范围，不含任何阈值或判定规则。非学生身份看不到（那条分支只显示「只有学生能加入」）。
- API：`POST /api/v1/classrooms/join`（`{ invite_code }`）→ 创建 `ClassroomMember`；加入后首页出现班级名与该班作业列表。已在另一个班时返回 **409** `You are already in a classroom. Ask your teacher or an administrator to change classes.`。注册路径不走这个接口，由 `POST /api/v1/auths/signup` 内部完成入班。
- 邀请码查询（`get_classroom_by_invite_code`）只认 `status = 'active'` 的班级，注册与加入两条路径共用，归档班的旧码在两边同时失效。

### S2.5 换班

学生自己不能换班，只有两条路：

| 谁       | 怎么换                                                                                                                   | 入口                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 原班老师 | 把学生**移出**本班 → 学生再凭新班邀请码自助加入；或在**自己名下的班级之间**直接调班                                      | `/teacher/classrooms/[id]/students`（`DELETE .../members/{id}`、`POST .../members/transfer`，目标班须是本人的班） |
| 管理员   | **跨老师调班**：在 `/admin/users` 编辑用户弹窗改「班级」下拉，保存即删旧班籍、建新班籍；改前改后不同时弹窗内有琥珀色提示 | `POST /api/v1/users/{id}/update`（`classroom_id`）                                                                |

不给老师跨班调人：原班老师不该决定学生进谁的班，新班老师也不该从别人班里拉人；管理员能看到全部班级、立场中立。

换班（含移出）之后：

- **提交记录跟着作业留在原班**：原班老师在作业提交列表、批改页照常能看、能批；学生的作业列表和写作入口只剩新班的作业。原班的「学生画像」入口关闭（`.../students/{id}/profile` 返回 404，学生已不在该班）。
- **成长画像跟着学生走**：画像的作业范围 = 当前班的作业 ∪ 学生交过的全部作业（`Education.get_profile_assignments_by_student`），学生端 `/me/writing/growth`、新班老师的学生画像、画像聚合物化三处共用。每次班籍变化（加入、移出、调班、管理员改班级）都会重新物化画像聚合（`refresh_profile_aggregates_after_scope_change`）。
- 新班老师在画像里看得到原班的作业与分数，但那些提交**不给「打开 / 查看证据」入口**，改显示「在其他班级提交」——批改页只对原作业所属班的老师开放。
- 成长目标、教师私人笔记仍按班级归属，不随学生迁移。

### S3 写作首页 `/me/writing`

- 学生侧栏顶部固定「我的作业」，原可排序菜单中的「写作」不再重复展示；首页标题为「我的作业」。登录没有指定目的地或仅返回 `/` 时进入本页；已有作业、聊天和邀请链接仍返回指定页面。点击平台名称或标志同样回到本页。
- 普通聊天保留为「自由交流」，位于教学入口和写作项目下方、普通聊天记录上方，以分隔线区分。桌面收起状态保留同名图标提示，手机侧栏顺序一致。点击进入 `/`，新对话按钮及快捷键继续创建普通聊天。
- 「我的作业」「自由交流」的普通点击使用应用内路由，不整页重载或重现启动页；收起侧栏点击不额外展开侧栏。Ctrl／Command／Shift 等修饰点击保留浏览器原生打开行为，不重置当前聊天。
- 自由交流顶部显示用途名称；新对话与已有聊天的输入框上方常驻「此处对话不计入课程作业。完成作业请前往我的作业。」，其中「我的作业」链接本页。提示不可关闭，已有消息滚动时仍留在输入区；作业与个人写作工作区不显示此提示。

`GET /api/v1/me/writing/home` 对学生返回最近作业写作、**班级作业列表**，个人写作按管理员角色开关返回，另附 `personal_writing_enabled`（时间戳统一为秒；笔记表的纳秒时间在后端换算）。页面用通用页头 `EduPageShell`，学生标题「我的作业」（其他身份仍为「写作」），右侧「我的成长」。自上而下：

- **接着上次写**：只取最近写作里第一条**未提交**的，一行横条，点了直达对应工作区；没有就不显示（原来 12 张最近写作卡片已删除）。
- 默认显示**作业写作**（带待完成数），管理员开启学生个人写作后增加个人写作分段；同一行右端以小字显示「我的班级：…」，悬停提示一人一班的规则。未入班时作业写作页顶部是邀请码输入卡。
- **待完成**（未提交 + 被退回，且没过有效截止）按有效截止**升序**（无截止的垫底）；**已超时，仍可提交**（没交或被退回且已过有效截止，仍能继续作答和提交，使用系统已有玫红卡片与文字标签）单独一组、截止近的在前、**默认展开**，可点击标题手动收起或展开；**已提交**（其余）按更新时间倒序，**默认展开**，可点击标题手动收起或展开。作业写作分段上的待完成数包含超时未交，学生默认进入作业分段。
- 每张作业卡片：修订初稿作业标题旁先有一枚灰色「修订初稿」标签（要先交初稿才能开始，进门前就该知道；从零写作是常态，不标）；再是状态标签——`returned`（红·已退回）/ `reviewed`（绿·已批改+**分数**）/ `pending`（灰·已提交·批改前可修改）/ `draft`（蓝·进行中）；说明最多两行；截止行显示「截止时间 / 重交截止（红）」，待完成的再跟剩余时间（与工作区共用 `getDueCountdown`：<24h 琥珀、<1h 玫红、已过「已截止」）。
- 卡片按钮按状态说下一步：开始写作 / 继续写作 / 修改后重交（主按钮），查看批改 / 查看提交（次按钮），都进入 `/assignments/{assignmentId}/write`。
- **实时刷新与短时返回**：首页每次进入均校验服务器列表，不展示未经校验的作业内容缓存；点击侧栏“我的作业”即发起只读列表请求，与旧编辑器销毁并行，页面挂载共享该在途请求，不在悬停时请求工作区；只在同账号、身份和班级范围内保留 15 秒的分段与分组状态。相同身份的在途请求共享，读取期间收到业务通知会在结束后合并补刷；通知角标赋值本身不触发重复列表请求。身份切换立即清空旧数据，Socket 重连、窗口重新可见及业务事件重新校验；隐藏或撤权后的旧响应不能覆盖新列表。

（个人写作默认对学生关闭，以下接口按管理员角色开关开放：`POST /api/v1/me/writing/personal` 新建、`DELETE /api/v1/me/writing/personal/{id}` 删除（需确认；连带删掉对应项目文件夹与对话，删完侧边栏对话列表与置顶整页重拉 —— 列表 store 自 0.11 起只读，不能就地剔除），落地 `/writing/{sessionId}`，用同一个 `WritingWorkspaceShell`，不进提交/批改流程。）

学生端另有 `GET /api/v1/me/writing/workspaces`（作业工作区状态列表）与 `GET /api/v1/me/writing/profile`（**个人成长画像**，见 S11）。

### S4 打开作业写作工作区 `/assignments/[assignmentId]/write`

- 点击“继续写作”时，工作区响应一次带回保存稿、适用的辅导摘要、阅读／试读状态，以及尚未确认的初稿暂存（完整结构、材料和 revision）。必要状态读取失败不会当作空记录；恢复期间显示普通加载提示，不冒充 AI 正在阅读。修订工作区直接载入原活动对话，显式选择的对话须属于当前写作项目；聊天历史与运行任务只需下一批并行读取。
- 通知已读／角标、标签及侧栏刷新进入有界后台队列，不占满连接阻塞正文或立即返回首页。已恢复的初读消息不重复获取，只补取后续真实新增的阅读消息；恢复期间收到的实时事件在历史装载后应用。对话切换保持已挂载的稿件编辑器和未发送输入，旧账号、旧页面的迟到结果被忽略。
- 普通重入只恢复阅读事实；即使没有初读记录也不会自动调用模型或消费排队消息。只有学生刚确认初稿的流程会自动开始初读，失败仍可手动重试。真实初读／聊天生成继续锁定正文与提交；任务状态读取失败不能当成空任务解锁。初稿组件只消费一次工作区暂存，不再次 GET 后覆盖正在输入的内容。本地备份仍由学生明确选择恢复。
- 侧边栏写作项目的「关闭」只隐藏该入口，保留稿件、对话和提交。点击后立即移除侧栏项目，后台保存，不显示等待状态、不跳转页面；保存期间列表刷新也不让该入口重新出现。保存失败时恢复该入口并给出轻提示，可重新关闭；其他项目的关闭和刷新结果不回滚。仅发送隐藏状态，不回写侧栏缓存的作业配置。
- 打开作业后立即同步侧边栏“写作”项目，无需先发送消息；此前在侧栏关闭的项目再次打开后恢复显示。段落论证沿用“作业 → 对话”的结构，初读生成唯一对话后立即展示，刷新或重进仍可查看。点击作业标题或其唯一对话均进入该作业的持续对话工作区；已批改时同样显示并以只读方式查看。
- 两类修订作业固定使用一个持续对话：重新打开时接续当前对话，讨论别处、再次改稿都继续往下交流。作业内隐藏新建对话、复制/分支、对话菜单及侧栏拖拽；仍可重试回复、查看之前的往来。不能通过独立聊天接口创建第二条、导入或移动其他对话进来。
- 已有多条时按显式维护计划保留当前且有内容的一条，否则保留最近更新的有内容对话；没有正文内容时优先当前或最近一条。多余活动对话删除，已提交的冻结记录不改写。维护前须备份，不在学生打开页面时清理。


- 作业工作区由 `GET /api/v1/assignments/{assignmentId}/workspace` 装配，首次打开时创建或取得该学生的 `WritingSession(scope=assignment)`、Note 和 Folder；`GET /api/v1/writing/{sessionId}/workspace` 用于按会话打开工作区，包括个人写作，不能把 assignmentId 当成 sessionId。
- 布局（`WritingWorkspaceShell.svelte`）：**左栏 AI 聊天，右栏富文本编辑器**（窗口宽 ≥1024px 时并排；更窄——平板、和 Word 左右分屏——改用底部浮条「作业内容 / 提交」+ 正文抽屉。断点不用全站的 768px：768～1023 之间右栏被 `lg:flex` 藏掉、浮条又不出，学生看不到正文也交不了，2026-10-03 走查发现）；右栏顶部依次是保存状态徽章（Saved/Saving/Retrying/Failed，**只反映自动保存，不掺提交状态**——提交与否由旁边的绿色「已提交」徽标单独表示）、**批改结果卡片**（`ReviewResultCard`，见 S8）、**本次写作构成**（`WritingComposition`，仅作业定稿后显示，见 S5）、提交按钮。
- 右栏可拖拽改宽（`ResizableSidePanel`，`storageKey=writingRightPanelSize`），**默认约占视口 48%**（不小于 600），下限 560（保证头部标题不被右侧按钮组挤没），**不设上限**；正文行长改由面板内部的居中栏控制（头部与正文都在 `max-w-[46rem]` 的一栏里，一行四十来个汉字——编辑器根节点的 `min-w-full` 会盖掉 prose 自带的 65ch，只能在外面限宽）；聊天侧另有 `minSiblingWidth=360` 保底，窗口不够宽时下限自动让位。
- 左侧还没选中对话时显示写作区专用的空态（`Placeholder` 的 `writingWorkspace` 模式）：「和 AI 聊聊你的稿子」+ 写作场景的输入提示，不再重复显示项目文件夹标题；下方仍是本项目的历史对话列表（时间按中文「今天 15:06 / 昨天 …」显示）。
- 头部：作业标题（写作中不再附说明行；提交后/定稿/过截止才有一行状态说明）+ **有效截止时间 + 倒计时**（每分钟刷新；<24h 琥珀、<1h 玫红、超期显示「已截止」；退回状态标注为重交截止；与写作首页共用 `getDueCountdown`）；下方 **作业简报**（`AssignmentBrief.svelte`）**默认收成一行**（「作业要求」+ 首行要求 + 展开），展开后是要求原文 + 评分维度胶囊（各维度名称·分值）+ 满分，移动端抽屉同步展示。
- **作业上下文自动注入对话**：从零写作保持题目、要求、类型辅导提示词与适用辅导档位，不自动注入评分模式、评分维度、数值分数、反思题或截止时间；重新打开工作区时按当前规则装配。两类修订同样排除这些字段，教学目标与判断标准统一写在“辅导提示词”中，不再设置第二个字段；每轮由服务端重新读取作业的教学快照、最新题目/要求，按白名单装配，也不叠加“平衡/放手”。文件夹里的旧提示词不会盖过新要求。调用记录标注教学版本、要求版本及来源稿件。教师主动写入要求或辅导提示词的内容保持原文；独立 AI 读者试读仍使用所选维度，评分、反思提交和超时判定不变。
- **每轮注入当前正文**（作业写作区与个人写作区都生效）：文件夹提示词是静态的，装不下实时正文；靠模型自己调 `view_note` 工具，国产模型又调不可靠。所以 `utils/middleware.py` 在注入文件夹提示词之后，若该文件夹是写作会话的项目文件夹且会话属于本人，就用 `services/education/writing_context.build_current_text_context` 读出笔记**最近一次保存**的 `md`，以「【学生当前正文】…<<< 正文 >>>」追加到系统提示末尾（措辞里明确告诉模型：之前回复里引用过的句子可能是旧版本，一律以这一版为准。验收时发现不这样写，模型会相信自己历史回复里的旧引文，回答「我这边看到的还是旧版本」）（不走提示词模板变量解析）。笔记用自己的短会话读，读完即释放，不把数据库事务带进模型调用。约 1000 字的正文每轮多 1–2k token。修订初稿作业只注入当前正文，不注入初稿基线全文。
  - **改没改由后端算好写成状态行**（正文上方），不让模型拿自己引用过的句子去猜——学生不一定每轮都改，原措辞「每轮都会更新」会诱导模型把没改的地方说成改了。两行：①「与初稿相比：还没有改动 / 已有改动」，仅修订初稿作业（有基线）；②有上一条 AI 回复时才有：没改就写「自你上一次回复以来：没有新的改动」，改了就**逐条列出改了什么**（`describe_text_changes`：段落级对齐，相近的段（相似度 ≥ 0.5）配成「改了」、其余算删去/新增，连续删去的段合成一条；段内按**整句**比，写成「「……前一句末尾」之后把「旧句」改成了「新句」」/「加了」/「删去了」；每条截 150 字，最多 8 条）。只写「有改动」不够：模型看不到上一版，只能自己猜改了哪里，2026-10-02 实测学生删了参考文献、在结尾加了字，模型找不到它要的那 5 句，就连说三次「我这边没看到新的改动」。段内逐字比也不行，「把『初稿』改成了『改过的』」模型看不懂，所以按句。②的「上一次回复」= 当前提问消息的 `parentId`；取 `chat_message.created_at` 不晚于它的最后一个 `writing_version`，与当前正文按 `normalize_draft_paragraphs` 逐段比（只差空白不算改）；那之前没有版本就以初稿基线（从零写作为空稿）为准。两边时间都是后端时钟：AI 回复占位由后端在发起请求时写入（`main.py`），版本时间也是服务端写的，不受学生电脑时钟影响。措辞同时交代：学生说改好了、状态却显示没有新的改动，多半是还没保存，请他看到「已保存」再发。
  - **发送前先存盘**：编辑器停手 1.2 秒才自动保存，原先改完马上发消息 AI 看到的是旧稿。`Chat` 新增 `beforeSend` 钩子（`sendMessage` 开头、`continueResponse` 发请求前调用），写作区传入 `flushDraftBeforeChat`：有防抖中的修改或正在保存就立即强制存一次，与试读前落盘同理。最多等 5 秒（断网时保存要重试 2/4/8 秒，不能让发送一直卡着）；没存上照常发，AI 看到的是上一次存成功的稿子，同时弹出警告「你最近的修改还没保存上，AI 这一轮看到的是上一次保存的稿子」。2026-10-02 浏览器实测：改一句后 108ms 内发送，AI 准确说出改了哪句；拦截保存请求后约 5.9 秒弹出警告并发出。必须在 AI 回复占位写入之前存完，否则这一版的时间晚于回复，下一轮会被误报成「有新的改动」。
- **两类修订的初读**：确认基线后后台读取，阅读期间暂时锁定编辑与提交，不代学生发送强制首轮。阅读记录通过 `readings` 接口呈现，初读失败可重试也可直接提交；平台按钮触发的消息标记 `auto_started`，不计入学生提问质量。通用自动追问推荐在修订作业中关闭，避免诱导整段代写或重新开启已结束的讨论。
- 简报下方常驻**采集告知**（`EduDataNotice`，按 `scope` 变文案）：作业写作区说「任课老师能看到这些记录」并补一句「个人写作区老师看不到」，个人写作区只说「这里老师看不到里面的任何内容」。写作区里用 `collapsible`：每个 scope **第一次进入完整展示三行**并在本地记下（`education:data-notice-seen:{scope}`），之后收成一行摘要（「这里会记录你的写作过程，老师可以看到 / 只有你自己能看到」+「详情」）。告知始终在场，只是不再每次压低编辑区。桌面端与移动端抽屉各渲染一次。
- 有过提交后头部出现**「提交记录」按钮** → `SubmissionHistoryModal` 弹窗查看自己全部轮次（每轮正文快照 + 该轮批改结果），API：`GET /api/v1/assignments/{id}/me/submissions`（仅学生本人）。
- 打开时自动把该作业相关通知标记已读。
- **侧边栏切项目会重新装配工作区**：`/assignments/[assignmentId]/write` 与 `/writing/[sessionId]` 都在页面里用 `{#key 路由参数}` 包住 Shell。SvelteKit 同路由跳转只换参数、不重挂组件，而 Shell 只在 `onMount` 里拉工作区，不加 key 时从一个写作项目点到另一个只会改地址栏、内容纹丝不动。重挂载同时会走 `onDestroy` 的草稿补交（见 S5），不会把上一个项目的编辑写进新项目。
- **参数与系统提示**：作业写作区的聊天控制面板不显示「系统提示」「高级参数」两栏，改为一行说明它们按老师的作业说明与平台设定（`WritingWorkspaceShell` → `Chat` → `ChatControls` → `Controls` 的 `lockModelOverrides`）；文件、Valves 与其他标签照常。即使请求里带了，服务端也一律不用（`main.py` 在识别出作业写作会话后按「无覆盖」处理），对话只按文件夹里老师的作业说明与模型设定。唯一的例外是辅导对话的思考档位：由服务端按管理员的下放方式和作业设置算出（`services/education/ai_steps.resolve_coaching_thinking`），老师允许且所选模型勾了「思考控制」时，输入框上方出现「深度思考」开关（`ThinkingSwitch.svelte`，经 `Chat` 的 `extraRequestParams` 发 `thinking_level: off`），学生只能把这一轮关掉，不能调高；工作区接口的 `can_switch_thinking` 决定是否显示。所选模型关不掉思考时（模型列表里的 `thinking_support.can_turn_off` 为假，如 GLM-5.3）开关换成一行「这个模型始终开着」，不发「关」。每条回复在 `meta.thinking_level` 记下实际生效的档位（模型不支持思考控制时记 `model_default`；关不掉思考的模型上「关」记成退到的 `low`，始终思考又不分档的记 `model_default`）。作业项目文件夹的系统提示和 meta 学生也不能经文件夹接口改写（403）。个人写作和普通对话按 `chat.controls` / `chat.params` / `chat.system_prompt` 权限执行。
- **学生记忆与作业检索边界**：学生的作业写作、个人写作和普通对话都禁止读写记忆；`utils/access_control` 收回学生的记忆权限，记忆接口拒绝访问，中间件关闭记忆注入和回复后的记忆整理。作业写作会话还在模型配置副本中禁用检索历史聊天与记忆的内置工具，防止把作业外内容带进教师可见留痕；不修改管理员原模型配置。个人写作的聊天检索另受其工具配置与权限控制，不因此获得记忆权限。教师的记忆权限按平台设置处理。
- **新对话留在工作区地址并立刻出现在侧栏**：0.11 起新对话由后端在发第一条消息时建好、随响应返回 `chat_id`，前端原先一律把地址改成 `/c/{id}`，工作区因此不知道当前对话（不记活跃对话、侧栏点回去会卡）。现在有 `projectBaseUrl` 时改为 `goto(工作区?chat={id})`（先记为已加载，不打断正在生成的回复），随后通知侧栏：写作分组（独立的 `writingProjectRegistry`）收到新对话时**自动展开**并重拉列表，标题生成后（`chat:title`）再刷新一次。首轮自动诊断走同一路径。生成中/结束（`chat:active`）、已读等事件也同时发给写作分组，否则列表在生成中拉取后行首的转圈不会消失。
- **切换对话不卡**：Chat 加载对话时会卸掉再重挂右栏，右栏编辑器的 `bind:editor` 曾把已销毁的实例交给新编辑器，`getHTML` 抛错后界面停在转圈；`RichTextInput` 销毁时清空 `editor`。视图回到新对话（`initNewChat`）时清掉「已加载对话」记录，否则再点刚才那个对话地址变了内容不变。

- **切到别的页面再回来，回复照常显示**（2026-10-03 修）：上游消息列表和 Markdown 在流式输出时都把重绘排进 `requestAnimationFrame`，浏览器在后台标签页整个暂停它；Markdown 还只依赖 `content`，最后一段内容在 `done` 仍为假时排进动画帧，`done` 变真时内容没变就不再解析。学生等第一次通读（20～50 秒）时切去别处，回复写完了左栏却是空白、要刷新才出来。现在 `Messages.svelte` 与 `Messages/Markdown.svelte` 在 `document.hidden` 时直接重建/解析，Markdown 同时依赖 `done`。

### S4.5 两类修订作业：确认初稿并自主修订

作业类型为文献综述或段落论证修订时（见 T3），学生在课外写好初稿（可借助自己的 AI），平台负责之后的修订过程。

- 写作会话还没有初稿基线（`writing_session.draft_baseline_at` 为空）时，右栏**只显示初稿步骤**（`DraftBaselineStep.svelte`，桌面与移动端抽屉各一份）：简短说明 + 「↑ 上传」和「支持格式」（`TextImportActions.svelte`，与从零写作的编辑器导入共用）+ 连续图文富文本编辑器 + 「确认这是我的初稿」按钮；去掉空白后不足 **200 字**（前后端同一常量 `DRAFT_BASELINE_MIN_CHARS`）时按钮禁用。左侧对话只读并提示「先在右侧提交初稿」，提交按钮隐藏。
- 初稿可粘贴或上传 Word、PDF、文本和照片。后端返回结构化稿件、纯文字投影和原件信息；正文、标题、基本格式、表格、图片、图注与脚注在同一编辑器核对。照片明确选择“照片转正文”后直接进入编辑器，参考图片默认保持图像；原件收进“上传原件”。确认前自动暂存且不进入辅导上下文，确认时固定完整图文起点。Word/PDF 上限 50 MB，纯文本与旧版 OLE Word 10 MB；不支持对象明确提示转换或核对原件。
- **独立照片导入**：最多 8 张 JPG/PNG/WebP，单张 10 MB、合计 30 MB；默认按文件名自然排序，支持上下调整后选择“照片转正文 / 插入图片”。前者要求独立的作业开关和平台模型，最多八路并发转录，全文直接进入编辑器，已有正文保留；原图收在上传原件。后者不调用识图模型，原图插入稿件。失败保留文件和页序供重试，取消不改稿；无正文页不悄悄跳过。初稿仍须至少 200 个非空白正文字符，参考图及其未插入的识读结果不计入。
- **PDF 统一材料导入**：后端读取原生文字层，复杂图文页和扫描页保留原页图，不自动识读。原生文字层可直接查看或转入正文；开启参考图识读后，可在图旁显式读取，识别结果不自动进入正文。页码、注释及来源链接保留，真正空白页跳过。上限 50 页，无法转换的内容明确提示核对原件。
- 确认 → `POST /api/v1/writing-sessions/{id}/draft-baseline {text, materials}`：校验作业形式、会话归属、未定稿、长度；按行切段（去首尾空白含全角空格、丢空行），**同一事务**里确认所选材料并写基线（条件更新：基线为空才写，并发重复提交只有一次生效，其余 409）、把正文写进笔记（每行一个段落，`md` 为各段 `\n` 相连，与编辑器 `getText({blockSeparator:'\n'})` 逐字一致）、写一条覆盖全文的 `declared_draft` source map。只写笔记不写来源的话，整段初稿会落成「来源未记录」。
- 初稿格式、限额和撤回方法收进「支持格式」提示，鼠标悬停、键盘聚焦或触屏点击查看文件格式、照片限制及未启用原因。初稿内容区单独滚动，字数与确认按钮固定在面板底部；桌面与移动抽屉共用此布局，短窗口也可找到确认入口。
- AI 初读、复看及修订对话生成期间，桌面和手机正文区显示半透明等待遮罩并禁止鼠标、键盘编辑；提交按钮保留但禁用，撤回初稿暂停。刷新恢复中的 running 阅读同样锁定；完成、失败或停止后恢复，减少动态效果设置下停止旋转。
- 首次确认初稿后的正文与等待状态同时更新；加载辅导配置、阅读记录和等待模型就绪期间持续显示初读等待，不短暂展示空白或可编辑稿件。再次进入已完成或失败初读的作业时直接恢复现状，不显示初读等待、不自动重新调用；确有 running 阅读时继续锁定并跟踪进度。手机在工作区更新后再关闭正文抽屉、回到对话；读取阅读记录或初读请求失败时解除等待，保留确认稿，仍可按原规则提交。
- 桌面聊天区已显示阅读进度时，正文遮罩不重复显示同一提示；聊天区没有阅读进度时，提示仍在正文遮罩显示。手机稿件抽屉保留阅读提示，避免遮住聊天后看不到锁定原因。
- 确认后进入工作区，后台第一次阅读使用确认稿快照；阅读期间正文只读且不可提交，结束后恢复自主修改和提交。
- `POST /api/v1/writing-sessions/{id}/readings` 的 `purpose` 分别为 `first_read / revision_review / whole_review`；`GET .../readings` 返回阅读历史。每条含稿件正文/版本、会话顺序号、教学版本、要求版本、模型与思考设置、反馈及实际生成输出。相同稿件与请求避免重复启动。
- 阅读成功后以真实 AI 消息写入同一会话，后续提问自然携带该消息；阅读证据与消息原子保存，重复请求不重复写入，失败不生成消息。左侧依据消息/阅读关联去重展示，保留来源稿件；右侧保留正文、作业要求与提交。
- 阅读反馈与聊天共用 Markdown 渲染，标题、加粗、列表、引用、表格及链接正常排版，宽表格在反馈内横向滚动；引用的学生原句和「当时的稿件」继续按原文展示，不改写保存的反馈或稿件。
- 初读后直接在输入框交流，或在右侧改稿。“我想讨论其他地方”“去修改稿件”“就这处聊聊”入口已删除。
- 输入区只保留一个发送按钮。改稿相对上次已完成阅读有变化时，显示“稿件已修改，点击发送即可请 AI 看看，也可以输入问题。”；输入问题后提示“发送时，AI 会一并读取修改后的稿件。”。有输入或附件时正常发送，不额外追加复看要求；没有输入或附件时，同一个按钮及发送快捷键发送预设“我修改了稿件，请看看这次修改。”，标记为平台预设复看。先确认保存成功再发送，保留聊天 id 和此前内容。不自动发送，不以复看作为提交门槛。
- AI 回复完成后按服务端实际读取快照更新改稿基准；再次修改又出现复看动作。失败/未完成的回复不视为已读成功，生成期间不能重复点击。保存失败保留输入，不发模型请求，不追加空消息。
- 学生直接说“整体再看看”也可复看；不再单列“整段复看”。“展开完整反馈”与“此前的阅读记录”已移除，正文直接给完整的一次反馈；需要回溯时从该条 AI 阅读的「…」查看当时稿件。
- 手机聊天为底部作业操作浮条预留空间；正文抽屉提供「返回对话」和「提交作业」。确认初稿后回到聊天，稿件保存与正式提交仍明确区分。
- 聊天或阅读遇到网关 HTML 错误时只显示可重试的连接提示，历史数据不改写。
- 初读及复看的教学判断、反馈数量与表达顺序由统一辅导提示词控制；原核心规则和阶段辅导方式已移入该可编辑字段。默认仍建议具体、少量反馈，但代码不再限制最多两处或强制先肯定。允许直接显示连续回复，教师过程记录同步展示；不再提供第二份“完整意见”展开入口。
- 聊天中的复看使用同一教学提示词、学生说明和当前全文。代码不识别“看修改”等词来切换阶段，不自动比较旧稿；需要版本对比时另行设计明确入口。
- 进行中的阅读暂时禁止提交；阅读失败、仍有疑问、正文未改或未复看，都不妨碍后续提交。学生可解释、反对或换一处讨论；默认辅导提示词要求在学生明确准备结束时停止推进新修改任务；文献综述的实际措辞由管理员维护；段落论证采用教师发布的完整提示词。
- 尚未提交时可主动撤回初稿：清除该次基线、正文、来源、操作、版本、阅读记录和对应对话。旧请求返回不恢复已撤回记录。交过一次后不能撤回；退回重交继续使用最初基线。
- 后端仍校验身份归属、初稿已确认和已批改只读；超过截止仍可写作；前端可见入口不能绕过这些正常条件。

### 管理员配置备用模型与等待提示（2026-11-08）

管理员打开“设置 → 模型 → 编辑模型”，在“备用模型（可选）”中选择另一供应商已有模型后保存；选“无”关闭。列表按供应商分组，保留实际模型 ID 以区分同名条目，无需重新填写地址和密钥。已发布的段落论证作业在下一次新请求中采用当前 API 线路、备用设置和连接能力，无需教师重新发布；学生刷新后可重试失败的阅读或继续对话。既有成功阅读、稿件、作业版本和提交证据不改写。

配置备用后，主线路在输出开始前超时会自动切换一次；等待区显示“响应较慢，正在自动重试……”。初读仍锁定编辑和提交，成功后只追加一条回复，两路均失败恢复编辑及提交并允许手动重试。已输出部分回复或已取消时不切换。刷新期间可读取当前重试状态；只有配置了备用的模型采用此策略，其他模型沿用原重发规则。

### S5 写作过程（全程留痕）

- 正文编辑区（桌面与手机抽屉）的可输入节点覆盖整个最小高度，正文下方的空白处也可点击聚焦并继续输入；点击已有文字按点击位置定位光标，只读状态保持不可编辑。

辅导对话遇服务商一时出错（限流、5xx、连接失败或超时）由服务端自动重发，最多 4 次、约 1 分钟内，学生不用自己点重试；回复已经开始显示后中途断开的不会重发，避免重复内容（见 `utils/retry.py`）。个人写作的辅导对话默认不重发，管理员在「设置 → 写作辅导 → 自动重发」打开后同样重发（config `education.auto_retry`）。

停止输入 1.2 秒后自动保存，一次落四类数据：

1. `POST .../autosave` — 内容快照；
2. `POST .../versions` — 版本（`trigger_type=autosave|manual|submit_preflight`，submit 版由后端提交接口自建，version_no 递增）；
3. `POST .../provenance` — **溯源段落**，来源四类：`user_typed`（手打）/ `ai_inserted`（点 AI 回复的 "Insert to Writing"）/ `ai_pasted`（点 AI 回复复制按钮后粘贴）/ `external_paste`（外部粘贴）；修订初稿作业另有服务端写入的 `declared_draft`（已声明初稿，见 S4.5），前端 source map 原样保留这一类，学生改动其中的字照常转为对应来源；
4. `POST .../operations` — 编辑操作日志（keyboard_input / delete_text / replace / ai_insert_clicked / paste_detected 等），每条必带 `occurred_at_ms`（客户端发生时刻）与 `client_sequence`；过程指标一律按发生时刻计算，服务端接收时间只做采集审计，避免批量上报把多次编辑压成同一时刻。

这些写入接口与修订处理、试读写入共用 `writing_access.ensure_writing_session_writable`：当前轮已批改返回 409，页面只读不能通过接口绕过。超过有效截止仍允许写入、导入及 AI 对话，待批改稿和退回稿均可编辑；个人延期仅改变超时判定，见 S9；个人写作不受此限制。对话生成入口在保存用户消息或创建新聊天之前也执行该校验；只读时仍可读取过程摘要和已经生成的通读结论、切换既有对话查看。

第五类留痕**不经前端上报**：AI 用内置工具 `ask_user` 中途停下来向学生提问时，问答由后端写进 assistant 消息的 `output`，提交时随 `get_prompt_timeline` 一并冻进 evidence snapshot。教师端看到的是从中派生的结果（见 T6），不需要学生端做任何事；该内置工具在模型设置里关掉时，`output` 里没有这一项，派生结果自然为空。

**留痕在作业定稿后对学生自己可见**（`WritingComposition`）：作业**已批改**（工作区只读）后，右栏正文上方显示「本次写作构成」，按当前正文字符给出 自己敲的 / AI 插入 / AI 粘贴 / 外部粘贴 / 来源未记录 的占比，外加**已回答澄清追问数**（`GET /api/v1/writing/{sessionId}/process-summary`）。该计数与教师端过程摘要共用 `count_clarifications`，同一份稿子两端必须报同一个数。面板只呈现、不评判、不预警——做成警告条会把学生逼去绕开留痕，反而先毁掉数据本身。**写作过程中（含提交后、批改前仍可改稿重交的阶段）不显示**：实时看到比例，学生会重敲粘贴内容来刷「自己敲的」占比，同样毁数据（2026-09-23 定）。个人写作区教师看不到、没有刷数动机，照常实时显示。

**正文编辑器导入**：从零写作及已确认初稿的修订作业共用导入界面。Word/PDF 先预览核对，再选择插入或明确替换全文；初次上传照片选择“照片转正文 / 插入图片”后直接添加到当前稿，成功保存材料后再插入正文，不多要求一次插入。文档预览内追加图片保留已核对的内容。正文插入记为外部粘贴，操作携带文件名和导入类型；附件不计入正文来源占比。材料保存失败时保留预览，不关闭弹窗。定稿与本人权限继续由后端校验，截止不再阻止导入。

另有 `POST /api/v1/writing-sessions/{id}/active-chat`（切换当前对话时回写会话的 active_chat_id；chat 不存在 404，chat 不属于该作业 folder 400）。

两条保留内容真实性的规则（写在 `WritingWorkspaceShell`）：

- **正文没变就不开新版本**（autosave / manual / submit_preflight 一视同仁；提交接口另存的 submit 版是终稿锚点，不受此限）。以前试读前、提交前强制存版，一次提交叠出两三个一模一样的版本。编辑器在选区/格式变化时也会触发 onChange，照存的话一篇稿子能攒出两百多个一模一样的版本，版本历史没法看，「改了几版」也失去意义。
- **只认学生自己造成的编辑**。`RichTextInput` 每次 onChange 带两个标志：`docChanged`（正文有没有真的变）和 `programmatic`（是不是组件自己把正文灌进编辑器）。两者任一不满足就直接返回。编辑器挂载时正文还没灌回来、此时是空文档，ProseMirror 照样报 `docChanged=true`，只看这一个标志会把它当成学生清空全文：整篇记一次删除、source map 被清掉，回填后又整体标成 `user_typed`，还会喂出假的「疑似未标注导入」。挡掉这两类之后，剩下的空文档就真是**全选删光**，如实留痕、构成占比即时清零。

保存可靠性：失败后**指数退避自动重试**（2s/4s/8s 共 3 次，徽章显示 Retrying…，全部失败才落 Save failed）；一个保存周期只创建一个版本（重试复用）；存在未保存变更时刷新/关闭页面会弹 **beforeunload 确认**；**客户端路由跳转**（切到别的会话/页面）时 beforeunload 不触发，改由组件销毁前补发一次 autosave 兜底。

### S5.5 提交前 AI 读者试读

仅当作业 `challenge_enabled=true` 时存在（修订初稿作业结构上没有这一环节，提交按钮直接进反思，见 T3）。这是与左侧辅导助手相反的另一个角色：**质疑读者只提问，不给可粘贴的文本**，且不进入聊天框，两边口吻不互相渗透。设计依据见 `PRD.md` 12.9。

流程 `点提交 → 契约声明 → 质疑 2~3 轮 → 收尾清单 → 回去修改 或 继续提交 → 反思 → 提交`。

界面上（`ChallengeDialog.svelte`）：

- 点「提交作业」后先强制落盘一次草稿（`manual`；试读针对服务端最新那一稿，正文没变时最新版就是当前稿，不再另开版本），再弹出试读。未选模型会提示先选模型。
- **首屏是契约声明，不是第一条质疑**：「我是一个不同意你的读者 / 我不会帮你改任何一句话，我只说哪里说服不了我 / 一共 N 轮」。不先亮契约，学生会一直向它求助然后判定这 AI 很笨。
- 正文是**卡片式单轮推进，不是聊天流**：一条质疑 + 一个回应输入框 + 一个「提交回应」。顶部常显「第 N 轮 / 共 M 轮」，让学生看得到终点；已答回合折在上方可回看。
- 「这次跳过」常驻但弱化（link 样式），任何阶段可点。**契约页上还没开始就跳过，同样会落一条 `skipped`**——连开都不开的那批学生才是最该被教师看到的，不落库的话他们反而在质疑维度上完全空白。
- 收尾页给「站得住的 / 还需要改的」两栏，出口有两个：**「回去修改」**（关弹窗回编辑器，这是试读能真正作用于正文的唯一入口）与「继续提交」（进反思弹窗）。
- 未答满时「提交回应」按钮禁用；刷新页面会通过 `challenge/current` 恢复到原轮次，已答内容不丢。
- 收尾清单回流到写作面板（`ChallengeChecklist.svelte`，桌面面板与移动抽屉都在 `AssignmentBrief` 下方），每条可勾选，状态经 `PATCH .../checklist` 存服务端。
- 清单下面挂着**本轮完整往来的折叠区**（默认收起，`ChallengeTranscript.svelte` 与教师端共用）。此前关掉弹窗就只剩三条摘要，而真正要拿这份记录去改文章的是学生——教师端反倒一直有完整记录，方向是反的。数据用写作面板已持有的那份，不额外请求。
- **每一轮质疑都引用原文里的一句**，界面上以琥珀色竖线标出。引用是修订判定的锚点，格式要求写在服务端拼的消息里，不在管理员可编辑的提示词里。

界面措辞一律回避「对抗」「挑战」「找茬」——那会让学生进入防御姿态；用「AI 读者试读」，学生的心理位置才是「我在准备」而不是「我在被考」。对外一律写全「AI 读者」，不简称「读者试读」：学生要知道问他的是谁。

- `POST /api/v1/assignments/{id}/challenge/start`（body: `writing_session_id` + `model`）→ 冻结当前最新版本为 `source_version_id`，返回 `{session, turns}`，含第 1 轮质疑。正文短于 100 字符返回 400（空白页上来被问三个问题只会让学生关页面）；本轮已有质疑记录也返回 400（一轮只质疑一次）。
- `GET /api/v1/assignments/{id}/challenge/current?writing_session_id=` → 恢复未完成的质疑，刷新页面不丢已答回合；本轮没有则返回 `null`。
- `POST /api/v1/challenge/{sessionId}/respond`（body: `turn_no` + `response_text` + `model`）→ 未答满就返回下一轮，答满 `planned_rounds` 就转收尾并把 `closing_summary_json`（`{stood, unresolved}`）写进 session、status 置 `completed`。**回合上限由服务端代码兜死**，跳答、重复答、超轮一律 400。
- `POST /api/v1/challenge/{sessionId}/skip` → status 置 `skipped`。允许跳过但跳过留痕，教师可见；强制不可跳过只会逼出敷衍答案。
- `POST /api/v1/assignments/{id}/challenge/skip`（body: `writing_session_id`）→ 契约页尚未开始就跳过时走这条，直接落一条 `skipped`（无回合）。本轮已有记录返回 400。
- `PATCH /api/v1/challenge/{sessionId}/checklist`（body: `checked_indexes`）→ 收尾清单的勾选状态持久化（完成后才可用）。
- `GET /api/v1/submissions/{submissionId}/challenge` → 教师读本轮质疑往来；本轮没做过质疑返回 `null`。

焦点维度取自作业的 `challenge_focus_keys`，必须是本作业 `rubric_schema.criteria` 里已有的 key（1~2 个），按轮次轮转（`focus_keys[(turn_no-1) % len]`）。未配置评分维度的作业不允许启用质疑——学生被追问的点就是最后被扣分的点。

**上一轮被教师退回、且教师勾了「让读者就这条意见追问」时**，那条退回意见会在发起本轮质疑时冻进 `challenge_session.followup_comment`，作为每一轮的首要指向。焦点维度仍照旧轮转（不替换，否则班级层面的维度聚合会塌），教师那句话叠在上面。

收尾清单的每条「还需要改的」都带 `turn_no` 与由它映射出的 `focus_key`——让模型报维度它会瞎编，报轮次错不了。归属不上的条目照样展示给学生，只是不进班级统计。

措辞由管理员维护在 `education.challenge_prompts`（`turn` / `closing` / `insight` 三段），与三档辅导风格同一机制。输出格式（引用原文、JSON 结构）由服务端拼的消息强制，管理员改措辞改不掉格式——格式是判定的地基。

### S6 提交作业

截止后仍可提交；桌面和手机写作区明确提示老师会看到超时标记，提交反思弹窗再显示玫红提示。学生作业列表中的超时未交任务使用浅玫红卡片，已交且该次确为超时的显示“超时提交”；准时交过的作业不会因后来超过截止自动变成超时提交。待完成总数包含超时未交。

确认初稿后，“提交作业”始终可见，按定稿、阅读和保存状态判断可操作性，超过截止不禁用。两类修订不走提交前读者试读，也不显示逐项处理 AI 建议的清单。

打开弹窗先刷新作业最新设置，保留题干、题型与选项等含义仍相同的回答。草稿保存题目签名；同 id 的题目已变也不能默默沿用旧答案。弹窗只有教师反思题与必要确认，无反思时直接确认提交。未修改初稿可以提示事实，不能阻止提交。

提交前保存正文，随后 `POST /api/v1/assignments/{id}/submit` 携带 `expected_config_revision`、稿件与反思回答。教师在弹窗打开期间更新配置时返回 409，刷新后提示重新核对。正常校验通过后冻结稿件、作业说明、评分与反思配置、教学快照、已完成的阅读和对话过程、适用退回意见。迟到回复保留来源稿件，不改变已冻结提交与提交结果。

从零写作保留 AI 使用自述及适用的 AI 读者试读；两类修订不再询问 AI 使用题。

### S7 提交后与轮次规则

- `WritingSession.status = submitted`。
- **重要：提交 ≠ 锁定。** 提交后、老师批改前，工作区照常可编辑，包括已超过有效截止的情况，提交按钮变为「重新提交」，学生可以反复改稿重交。首页卡片因此不写「待批改」而写「已提交·批改前可修改」，避免学生以为已经交死、或以为还能改是 bug。教师端此时看到的始终是学生最近一次提交的版本。
- 当前轮 review 为 `pending`（或不存在）时再次提交 = **覆盖当前轮**（批改前修改不产生新轮，覆盖提交按最新提交时点判断超时）；
- 当前轮已 `returned`（退回）后再次提交 = **开新轮**（round_no+1，旧轮 `is_current=0`，旧稿/反思/评语/分数全部保留可追溯）；
- 当前轮保持 `reviewed`（已批改）时禁止再交（后端 409，工作区只读）；正常重交流程由教师在实例允许时显式退回。已发布评阅不能通过“存草稿”改成 pending；更正成绩继续保持定稿只读。
- 学生可随时通过工作区**「提交记录」**弹窗回看自己各轮快照与评语（见 S4），与教师端轮次视图对称。

### S8 收到批改反馈

Socket 通知 + 首页卡片 + 工作区批改卡片三处同步：

- **reviewed**：绿色卡片 — 轮次号、**分数/满分**、按作业 `rubric_schema` 展开的**各维度名称 + 得分/该维度满分**（未评的维度显示 —）、总评、批改时间。同一张卡片也用在「提交记录」弹窗里，历史轮次同样按维度名称展示。**该轮已定稿：编辑器转只读、提交按钮消失**，提示「如需修改，请让老师退回作业」——仅在管理员开着「退回重写」时这样说；关着时老师没有退回入口，改为「已批改，作业只能查看。」。定稿（已批改）后工作区收成「只读回看」形态：顶部徽标改为「已批改 + 分数」，去掉保存状态和截止倒计时；作业要求、试读待改项（勾选框禁用）、留痕告知收进「查看作业要求与试读记录」（作业没开试读时只叫「查看作业要求」，修订初稿作业一律如此），批改卡片因此排在最前；左栏若该作业用过 AI 对话则自动载入上次的对话供回看，没用过则提示「这份作业没有 AI 对话记录」。**修订初稿作业写作中**也一样：进来时地址里没指定对话、会话有 active_chat_id 就直接载入那段（初读意见独立保存在阅读记录中，既有改稿讨论仍从上次对话继续）；使用工作区返回的活动对话，取消额外的存在性预读；历史或运行状态恢复失败时提示重试，不以空对话冒充恢复完成。
- **returned**：红色退回横幅 — 退回评语 + **新截止时间 `resubmit_due_at`** + "修改后重新提交"引导；后端把 `WritingSession.status` 打回 `draft`，**编辑器解锁**。

### S9 修改重交（有效截止规则）

教师全局批改队列、作业内提交列表的提交时间旁，以及批改工作台顶部均显示玫红“超时提交”；批改页同时显示该次适用截止。学生提交历史也展示同一标记。教师切换历史轮时按该轮冻结记录展示，后续改期限不影响既有标记。

学生该作业的**有效截止时间**按优先级取第一条命中的：

1. **个人延期** `assignment_extension.due_at`（教师单独给这个学生设的，最具体，压过下面两条）；
2. 最近一次退回的 `resubmit_due_at`（多次退回以最新为准）；
3. 作业原始 `due_at`。

个人延期只影响被授予学生的超时判定，教师授予和撤销都会发通知。当前轮未被批改时，无论是否超过有效截止，都可修改并重新提交（走 S6 流程；待批改重交覆盖当前轮、退回重交才 round_no+1，见 S7；教师再收 `submission_created`）。仅**当前轮已批改**会因定稿锁定工作区；隐藏及归属权限仍独立校验。提交时间达到或超过该次冻结的有效截止即标为超时，后来改作业截止、延期或退回期限不改写已交轮次的标记。

### S10 学生端状态机小结

```
not_started ──打开作业──▶ draft ──提交──▶ submitted(pending)
                            ▲                    │
                            │        ┌───────────┴───────────┐
                            │   reviewed(当前状态只读)      returned(退回)
                            │      正常重交由老师退回          │
                            └────── session 回到 draft ◀─────┘
                                     (新截止 = resubmit_due_at, 重交开新轮)
```

### S10.5 成长画像里的「面对质疑」

写作过程维底部多一块「面对质疑」（只在该学生至少有一轮做过试读时渲染）：做过试读的轮次数、最近一次的回应完成度、试读后回去改了的轮次数；有跳过的轮次会单列一行说明。

放在过程维而不是 AI 协作维是有意的：质疑读者不是帮手，并进「AI 协作」会把两个刻意分开的角色又混回去。

数据来自提交时冻结的 `stats_json.challenge`，画像层不回读 `challenge_session` / `challenge_turn` 原表。作业没开试读的轮次这几项是 `null`，表示**不适用**而不是表现差，不进任何分母。

### S11 我的成长 `/me/writing/growth`

- 「轮次之间的修改」一页只有退回重交才有数据：管理员关了退回、该学生也没有旧的重交记录时，学生端和教师端都不显示这一页（2026-10-03 起）。教师端「最近一次数据完整度」不再显示 `metric 2026-10-01.1 · aggregate r11` 这类内部版本号，只在看的不是当前指标口径时写「历史算法」，版本号放进悬停提示。
  写作首页页头右侧「我的成长」进入（面包屑「写作」返回），`GET /api/v1/me/writing/profile`。与教师端学生画像页共用 `StudentGrowthProfile` 组件（`variant` 区分），**指标值与趋势两端一致**，但**指数公式只发给教师端**：`index_formula` 在 `TeacherStudentProfileResponse` 上，学生端响应里没有这个字段，页面上「这些指数是怎么算的」折叠块也只在 `variant="teacher"` 渲染。学生看得见自己的分和变化，看不见及格线在哪 —— 阈值（改够三成、写满三天）一公开就是一份刷分说明书。三维：

- **产出**：三张趋势图。标准化得分（教师分 ÷ 作业满分的得分率，跨作业才可比）；成文篇幅（提交稿字符数，单位「字」）；评分维度（每条线一个维度，得分 ÷ 该维度满分；维度按键名+名称跨作业对齐，某次作业没有该维度时折线在那里断开，图上有副标题说明）。只折算得分率，不合成指数。每张图下的数据表默认收起
- **过程**：过程投入指数、**修订深度**（回头删改字数 / 写入字数，30% 记满分）、有效写作时长、临交突击占比、开工提前量。
  刻意不用版本数：一个版本只是一次自动保存，数量只反映打字时长
- **AI 协作**：AI 协作指数取实际适用质量项的均值；无学生提问时只看反思，无反思回答时只看提问，两者均无则不适用；AI 占比；**提问质量**、**反思质量**（都是教师批改时给的 1—5 分折算到 0—100，**未批改为空**；本轮有有效学生提问时「已批改」必须给提问分，无有效提问则不能给；平台自动发起的消息不算）。提问数只作参考、不计入。曾按反思字数、提问条数计分，以及「消化度 / 平均改写率」（AI 片段改写比例平均），都已废弃

另有轮次进步（退回→重交之间的改写幅度/字数/分差/响应时长）、规则生成的结论（`insights`，后端只给 code + 参数，文案走前端 i18n）。突发插入、疑似未标注导入等**风险信号不参与任何成长指数**。

> 2026-09-14 起反思题由教师按作业自定，「AI 帮了你什么」不再是全站统一的选项，**AI 用途分布、生成→打磨迁移比例及其洞察已下线**（`PROFILE_METRIC_VERSION` 2026-09-14.1）。

### T3 布置作业

教师新建页先读取 `/teacher/assignment-defaults`：返回账号的授权类型、默认类型及三类独立教学配置。无授权时提示联系管理员；只获部分类型授权时，新建表单也说明类型由管理员设置，并提示如何申请其他类型。已有作业管理照常可用。管理员在编辑教师弹窗设置三项授权和合法默认值，收回授权后不能新建、复制或切换到该类型，服务端同时校验。

表单提供类型、教学任务、评分和提交前反思。文献综述与从零写作保留只读 AI 说明；段落论证另有可编辑 AI 辅导、准备稿和试教发布区域。类型包括从零写作、文献综述修订、段落论证修订。新建采用当前教学版本；同类型复制可保留教师自定义说明、评分和反思；跨类型切换须确认替换为目标默认配置，不能混用题组。

两类修订的标准、提示词、默认说明、默认评分和反思分别维护。段落论证默认分配 20/20/35/25，一必答一选答；教师可自由改评分与反思。AI 辅导始终使用独立教学规则，教师作业说明只提供题目、材料与完成要求。

评分可选“按维度评分”或“仅总分与总评”。分项允许增删、改名和改分（单项亦可），满分等于分项和；仅总分直接设满分。学生提交后仍能修改方式、维度和满分；未批改提交按最新标准评阅，已发布成绩保留原标准。已有基线或提交后锁定类型；段落论证允许独立发布新的辅导版本，其他类型沿用教学配置锁定规则。

从零写作保留适用辅导档位和读者试读；两类修订不叠加辅导档位、不能启用读者试读。段落论证初读、交流和复看统一使用教师发布的模型和思考；其他类型继续使用学生选择与管理员 AI 步骤配置。

### T3.5 配置提交前 AI 读者试读（可选）

作业创建页与作业详情页的评分维度下方是 `ChallengeSettings.svelte`，**只有三个控件**：

- 开关（拨杆式，右侧显示「开启/关闭」；未配置评分维度时置灰，并提示先配置维度）
- 追问轮次：2 或 3，不提供无限
- 追问维度：从本作业的评分维度里勾 1~2 个

这一项**单独框成一块面板**（圆形问号图标 + 标题 + 「交出去之前的最后一道关」标签），开启时整块描边转黑/暗色转白，选好维度后底部给一条生效摘要（「交卷前，学生要就「立意 · 论据」接受 3 轮追问。」）。平铺在普通表单项里教师会直接划过去——它开了就会在交卷那一步拦人，不是一个普通选项。面板里还常驻一句与辅导风格的分工说明：辅导风格管写的过程，这一项只在点提交那一刻起作用。

焦点直接复用评分维度，教师不用学新概念；学生被追问的点就是最后被扣分的点，质疑方向与评分标准天然对齐。维度被改名或删除后，界面会自动剪掉失效的焦点 key（不剪的话保存会 422，教师看不懂那个报错）。关掉开关时焦点一并清空。「复制为新作业」会沿用这三个字段。

措辞不归教师管：`turn`（单轮质疑）与 `closing`（收尾）两段提示词由管理员在 `education.challenge_prompts` 维护，与三档辅导风格同一机制。

### T3.6 设定提交前反思题

默认题按作业类型独立预填，教师可增删、改题型/题干/选项/必答，支持单选、多选和文本。文献综述与段落论证推荐题分别维护；文献真实性核查题为可选推荐题。

反思在提交时回答，不进入修订 AI 上下文。题目可以随时更新，但只影响之后提交，旧轮保留当时题目与答案。全部删除或全部选答留空时，学生正常提交，批改不要求反思质量评分。恢复默认采用该类型当前配置，替换已有题组需确认。

### T4 作业编辑、截止、隐藏与删除

作业没有归档功能、`status` 或 `archived_at` 字段，也没有归档接口。列表的「进行中 / 已截止 / 待批改」由截止和提交情况派生，不能按旧接口改变存储状态。

- 设置入口 `/teacher/assignments/[id]/settings`，保存使用 `PATCH /api/v1/assignments/{id}`。可编辑标题、要求、截止及允许修改的配置；已有提交时禁止改变所属班级。
- 页面提示“修改作业设置需填写修改说明；隐藏和恢复显示除外”，不区分学生是否开始或提交。点击“保存修改”先展示本次差异，再填写“修改说明（必填）”；说明为空、纯空白或超过 1000 字不能保存，后端同步校验。无实际修改不发送请求。成功后显示最近修改说明，并清空输入以便下次重新填写；失败保留内容及说明，取消不保存。
- 评分方式、满分和评分维度在提交后仍可编辑，保存前展示差异并确认。尚未批改的提交使用最新标准；原暂存分数在标准变化后需重填，已写评语保留。已发布成绩及其更正保留原评分标准，班级平均分、批改队列、学生反馈、历史轮次和成长画像使用对应成绩的满分与维度。已有初稿基线或提交后作业形式锁定。作业更新前后都验证「修订初稿不能开读者试读」的组合。
- 批改页保存时同时核对稿件、评阅版本和评分标准；打开页面后评分标准被修改，保存返回冲突，刷新后按新标准评分。原提交的作业配置和过程证据不重写。
- 两轮评分标准不一致时，成长画像不直接计算轮次分差，避免把满分或维度调整当成学生进步／退步。
- 辅导档位和反思题可按当前配置规则修改，工作区下次装配读取最新设置；已提交轮次仍读取当时冻结的提示词、题目与答案。关闭档位时不注入档位提示词。
- 修改要求、截止、评分或反思会通知班级学生；单个学生延期在「提交与批改」的未提交名单中单独设置，不影响其他学生。
- 作业列表的「⋯」菜单及作业设置页提供「隐藏作业／恢复显示」。隐藏后归入「已隐藏的作业」分组，标题、截止与待批改数使用灰色，仍可打开、批改和恢复；筛选与排序同时适用于两个分组。班级概况中的作业表同样将隐藏作业整行置灰，标题旁标注「已隐藏」，保留查看与批改链接。
- 作业列表和设置页的隐藏／恢复操作直接调用 `PATCH /api/v1/assignments/{id}/visibility`，请求 `{hidden: true/false}`，无需填写修改说明，不改变配置版本或覆盖最近修改说明。有学生开写或提交也能隐藏，已有稿件、提交轮次、评分与证据保留；恢复只恢复可见性，原截止、延期和定稿约束继续有效。
- 隐藏后学生首页、最近写作、项目入口、通知摘要及成长画像不展示该作业；旧工作区链接、已有会话的过程读取、正文写入、提交与 AI 生成均由后端拒绝（403）。隐藏／恢复事件使学生首页重新加载。教师的查看与批改照常保留。
- 删除使用 `DELETE /api/v1/assignments/{id}`，前端确认后提交；仅无提交且无学生写作会话时允许，后端拒绝有业务记录的作业。删除时清理对应作业通知，不提示改用不存在的归档功能。
- 达到有效截止后学生仍可作答和提交，提交弹窗提示会标为“超时提交”，教师仍可查看、批改和分析；延期或退回期限的具体优先级见 S9。

> **教师端页头**：所有教师页共用 `TeacherPageShell`，导航只在顶栏一处（定义在 `teacher-nav.ts`）。页头内容与正文**共用同一栏宽**（壳的 `width`：默认 6xl，新建作业 5xl，批改工作台铺满），自上而下：**四个分区**分段控件（总览 / 班级 / 作业 / 批改；批改工作台归「批改」）、**面包屑**（第一级「教学」可点回总览，由壳统一补上）、**唯一 H1（当前对象）**与同一行右端的页面主操作（「+ 创建班级 / + 新建作业 / + 添加学生」，总览页在已有班级时也有「+ 新建作业」），对象页下方再有一条**子标签**（作业 4 个、班级 2 个；同一对象的各标签页栏宽一致，切换时页头不跳）。原来放在正文里、一滚就看不见的分区胶囊导航和各页的「返回 X」按钮都已删除。

教师列表内的班级、作业、学生和提交链接使用站内路由切换，正常点击不重新显示启动 Logo；点击表格非交互区域仍可进入对应详情。链接保留 Ctrl/⌘ 点击及新标签页打开，复制邀请码、勾选学生和更多菜单不触发行跳转。

### T5 追踪提交（待办导向）

- **教师首页 `/teacher`**（`GET /api/v1/teacher/overview`）回答「今天要做什么」：四张卡 — **待批改**（→ 队列）/ **已退回待重交**（→ 队列已退回；退回重写关着时不显示）/ **48 小时内截止** / **逾期未交人次**；**「需要跟进的作业」**（`followup_assignments`：进行中且未截止的按截止由近到远，其后是已截止但仍有人未交或有待批改的，最多 6 条），每行有「批改 N 份」「N 人未交」直达按钮；**最近提交** 5 条（只为这 5 条构建分析）。还没有班级时整页换成「从建一个班级开始」。原来的班级数、作业数与班级清单已去掉（班级分区里都有）。收到通知自动刷新。
- **全局审阅队列 `/teacher/review`**（`GET /api/v1/teacher/review`，**服务端筛选/排序/分页**，返回 `{items, total}`）：与作业内提交列表共用 `SubmissionQueue.svelte`。状态标签 待批改 / 已退回 / 已批改 / 全部（「已退回」只在退回重写开着时出现；默认待批改，可由 `?status=` 指定，`?classroom=` `?assignment=` 预选筛选），班级、作业（随班级联动）筛选，按最新/可疑导入/大段突发排序与两个风险开关排在同一行；列表是表格——学生（重交轮次标「第 N 轮」，下附作业 · 班级）、提交时间、状态（已批改带分数 x/满分）、过程信号（只显示非零项）、学生自述是否用 AI，整行进入批改页；每页 50 条 +「加载更多」；提交时间为相对时间；打开页面自动清 `submission_created` 未读，收到新提交通知自动刷新并保持已读。
- **作业内提交列表 `/teacher/assignments/[id]/submissions`**（作业的「提交与批改」标签）：就是固定了本作业的同一个队列（隐藏作业/班级列与筛选，通知已读按本作业清），状态标签多一个 **「未提交」tab** — 未提交学生名单（`GET .../unsubmitted`，每行带 `effective_due_at` 与个人延期）+ **一键提醒全部 / 单个提醒**（`POST .../remind`）+ **单个学生延期**（`PUT/DELETE .../extensions/{studentUserId}`，行内展开选新截止时间与可选原因，已延期的行标绿并显示原因）；收到新提交自动刷新。
- **修订初稿作业的最后一列是「修订记录」**（2026-10-03 起；「用了 AI 吗」对修订初稿永远是用了，原来那列没有信息）：新流程显示已完成阅读记录数与初稿终稿是否相同，不推算建议采纳率或通关率；有旧冻结清单的历史提交继续使用 `SubmissionListItem.revision_overview`（`services/education/revision_items.summarize_revision_snapshot`，读提交时冻存的 `stats_json.revision_items`，不重算）——「要改 N：改了 a · 部分 b · 没改 c」，下面两种灰色提示：**终稿与初稿相同**（只忽略空白逐字比较），或「k 处说改了、原句未动」。都是请老师去看一眼的提示，不是判定，所以不用红色。全局队列里两种作业混排时表头写「AI 使用 / 修订记录」，按行各显示各的。组件 `RevisionOverviewCell.svelte`，本次分析的逐份表格共用。

### T6 审阅单份提交 `/teacher/submissions/[submissionId]`

- 默认仍先看终稿与评分；「查看写作过程」切到分析页并定位过程面板，已输入的评分与评语保留。左侧显示所选稿件或差异，右侧选择过程；返回评分恢复提交稿，再看过程仍保留选择。
- 桌面双栏各自滚动；窄屏稿件与过程上下排列，整页滚动。选稿后定位正文，正文上方「回到过程记录」返回交流和修改节点，避免小屏被两个过矮的内部滚动区困住。
- **过程回放**：初读、学生消息、AI 回复与已保存稿件按时间排列，可选「全部 / 只看对话 / 只看修改」。交流的「查看对应稿件」定位当时实际供 AI 阅读的版本；保存节点显示前一步到该步的文字变化。初稿节点直接看全文；中间自动保存默认收起，可展开；底部「详细编辑记录」保留更细的输入/删除等事实。初读不再重复放在「反思与版本」。
- **版本对照**：默认「初稿 → 本次提交稿」（从零写作为空稿 → 提交稿）；任意选择起点与终点，可逐次前后查看。「看这期间的交流」保留左侧对比并在右侧筛选所选时间段，逐条定位稿件不会移动筛选范围。「查看全部过程」解除筛选。两种查看方式共享稿件选择，红绿差异不自动判断修改质量或建议采纳。
- 目录与正文均来自本次提交冻结证据，`GET .../process` 按需读取目录，`GET .../process/compare` 返回所选两稿与差异；携带 `expected_final_version_id`，学生已重交时返回 409 并要求重新加载。目录外版本拒绝访问。中间保存稿来自本轮，前轮细节从轮次切换查看。空稿明确显示为空，快照缺失不给伪造入口，不以实时正文替代。
- 学生只点击复看时标注「学生请求查看修改（快捷按钮）」；附带自己说明时标注「学生说明并请求查看修改」。未记录具体动作的旧预设消息显示「平台预设消息」。不根据按钮次数或建议采纳次数评分，原提问/反思适用性不变。


`GET /api/v1/teacher/submissions/{id}`（SubmissionDetailResponse），双栏审阅界面可看：

- **队列导航**：顶栏右侧「上一份/下一份待批改」（按 pending 队列最新序，页面加载时拉取一次队列上下文）；回队列走面包屑（批改 / 作业名〔→ 该作业的提交〕）。
- **固定头部精简为两行**：状态徽标 · 提交时间 · 轮次切换 · 右侧「过程关注点」（悬停看理由）；下面一条**来源比例条**（手打 / AI 插入 / AI 粘贴 / 外部粘贴 / 未知，下方逐项写字数与占比，外加总字数 · 提问 · 版本数），它同时就是正文高亮的图例。原来的 7 格统计卡和正文区里重复的一排图例已删除；
- **修订初稿作业**（2026-10-03 起）：头部「过程关注点」旁边多一枚灰色提示「初稿 N 句：改动或删去 M 句，终稿里新写 K 句」，终稿与初稿相同时写「终稿与初稿相同」（`GET .../draft-diff` 新增 `draft_sentence_count` / `changed_sentence_count` / `added_sentence_count` / `same_as_draft`，按句切分与对比视图同一口径）；左栏正文上方是「终稿 | 初稿 → 终稿」切换，进页面就取回初稿对比（原来那颗按钮在「分析」页最底下、整段对话时间线之后，等于找不到），对比视图转到过程面板的版本对照，不显示来源高亮开关。「AI 澄清追问」没有内容时整块不显示（哈工深关了「询问用户」，永远是空的）。
- **正文 + 来源高亮**：按溯源类型着色（手打 / AI 插入 / AI 粘贴 / 外部粘贴 / 疑似未标注导入）；
- **版本历史**：detail 默认返回截至本次提交的最近 20 条 + `version_count` 总数；「Show All」时经 `GET .../versions` 懒加载，仍截止到该次 final version，不展示提交后继续编辑的版本；
- **Prompt Timeline**：本次提交时冻结的学生与 AI 对话记录；AI 回复按 Markdown 渲染（`marked` + `DOMPurify`，标题压成小号），修订初稿作业里一条诊断动辄上千字，原样显示 `##`、`**` 读起来很吃力；
- **AI 澄清追问**（过程证据内）：AI 中途问了什么、学生怎么答的，由 `collect_clarification_exchanges` 从聊天消息的 `output` 纯派生，顶部四个计数（提问 / 回答 / **自由作答** / 跳过），自由作答绿底突出——点选项回传虽然带得回选项文字，但学生自己写的那句才看得出他在想什么。模型拼错参数被后端拒掉的调用记为 `invalid`，不计数也不展示。**只展示不进画像口径**（该工具是按模型配的开关，跨班不可比）；
- **AI 辅导风格**（反思 tab 内，这一轮没有档位生效时不显示）：教师读取提交时冻结的 `stats_json.coaching`，含 `style / prompt / task_mode / task_prompt`，可展开看当时的提示词原文。管理员关闭档位时 `style=null`、档位 `prompt` 为空；之后修改作业或管理员措辞不改写已提交轮次。证据 schema 变化应提升版本并走正式迁移，不能在读取时补写或修复历史证据。
- **辅导对话的 AI 思考**（反思 tab，辅导风格之后）：`stats_json.coaching.thinking` 冻存提交时生效的 `{control, level, source, students_choose}`；学生可开关的轮次，Prompt Timeline 里每条 AI 回复标出「思考：关 / 低…」（时间线条目的 `thinking_level`，取自回复的 `meta`）。其下「本轮各 AI 步骤实际用的模型」读 `stats_json.revision_items.models` 与 `stats_json.challenge.models`（老师看不到的模型显示 id）。
- **历史第一次通读清单**（`RevisionItemsReview.svelte`，仅展示旧轮实际冻结的清单；新轮改为独立阅读意见）：每个评分维度一行——通读的档位（要改 / 可改进 / 达标 / 暂缓）、一句话结论、原句、学生的处理和说明，读提交时冻存的 `stats_json.revision_items`；补看补上的标「补看」，挡住暂缓项的那一项补看时确认改到位的标「补看时已改到位」，提交时仍是暂缓的说明学生没改好那一项（或没点补看）。评分 tab 里每一行维度下面也有一行小字：「第一次通读：要改 · 学生：改了一部分 · 原句一字未动」（补看补上的写「补看：……」）。学生说改了（或改了一部分）而那句原句一字未动时标红——只说明动没动，可能是在别处做了等效修改，由老师判断。这一轮没通读成时说明原因。
- **提交前反思**（反思 tab）：先显示固定题「是否使用了 AI」（修订初稿作业不显示，学生没被问过），再按提交时冻结的题目快照逐题显示学生的回答（选项以标签呈现，「其他」带说明，未答的选填题标「未作答」）。教师后来改了作业的题，这里仍是学生当时回答的题；
- **来源统计行下方的信任口径**：来源占比由学生浏览器在写作过程中记录，可能不完整也可能被绕过，界面明说它用于和学生讨论过程、不作为学术不端的证据；「过程关注点」标注为启发式指路而非判定。同一句口径也出现在看板的高风险提交列表上方；
- **分析摘要**：疑似未标注导入、大段突增、手打 / AI / 外部粘贴与声明初稿等逐份过程事实，不含平均改写率或消化度。GET 分析接口只读已物化结果，缺少可用分析返回 409，不扫描原始历史或自动补建。显式 `POST /api/v1/teacher/submissions/{id}/analysis` 从该提交冻结的 evidence 构建分析并保存，不再按「历史轮一律拒绝」处理；没有冻结证据时返回 409。当前 UI 的历史轮操作仍只读，不能据此把接口的证据校验误写为仅限当前轮。
- **片段详情 / 写作过程时间线的中文化**：后端时间线条目里的 `label` / `message` 是拼好的英文串（`Version 7`、`ai_pasted:paste_detected`），前端不显示它们，一律按 `event_type` 与 `source_type` / `op_type` / `trigger_type` / `rewrite_level` 经 `$lib/utils/education.ts` 的 `getWritingSourceLabel` 等函数翻译；疑似导入的 `suspicion_reason` 是后端固定英文句，直接作 i18n 键；`source_operation` 条目带 `import_kind` 时（从零写作在编辑器里导入的文件或照片），动作写「从文件导入了文字 / 从图片导入了文字」，来源仍是外部粘贴；
- **连续手动改稿合并成一段「修改正文」**（`analysis.py` 的 `_build_operation_timeline`，事件 `typing_run`）：编辑器每次输入都记一条操作，输入法每上屏一个词就是一条，逐条列出时改一句话就刷出几十行「手动输入 +1 字」，把对话和版本淹没（2026-10-02 走查实测一句 21 行）。现在连续的手动输入/删除/替换并成一段，遇到对话消息、粘贴或 AI 插入（这些仍单独成行），或停笔超过 10 分钟才另起；每段显示时间范围、「+N 字 · −M 字 · K 次编辑」，点「看改了什么」展开写入与删去的原文（各截 400 字；退格是从后往前删，按原顺序拼回）。按学生端发生时间 `occurred_at_ms` 切段，不用入库时间——操作是攒到自动保存或发送前才上传的，入库时间会和对话消息挤在同一秒。当前 `_ANALYSIS_LOGIC_VERSION` 为 `7`；GET 不会自动重算，不可用时需经显式分析 POST 从冻结证据生成；
- **轮次切换器 + 前后稿 diff**（`GET .../diff`）：当前轮 vs 上一轮红绿标注；历史轮（is_current=0）整页只读。
- **修订初稿作业：初稿 → 终稿**（两类修订 `revise_draft / revise_argument` 均显示）：从提交证据冻结的初稿到本轮提交稿的完整修改（正文对照走 `GET .../process/compare`，`GET .../draft-diff` 保留头部句数统计），红绿标注与「与上一轮对比」共用 `TextDiffBlocks.svelte`。**按句对比**（句末标点或换行断句）：初稿到终稿常整段重写，逐字对比会把新旧两版绞成碎片，按句对比时删掉的旧句与写进的新句各自完整。退回重交后起点仍是最初那份初稿。修订初稿作业没有试读三栏，学生「接受/拒绝了哪些建议」靠这里和 Prompt Timeline 对照核实。
- **source map 片段不做文本清洗**：`NormalizedSegment` 原先对所有片段 `strip()` 并在文本变化时丢弃偏移量，从段落换行处开始的片段（如 `
三、…`）因此整段落成「来源未知」；source map 片段本就是编辑器原文、偏移量已逐字核对，现在原样保留。这个问题所有作业都有，修订初稿作业最明显（未动的初稿段落都从换行处开始）。
- **已声明初稿**（`declared_draft`）：来源比例条单独一行「已声明初稿」（紫色，非风险色，其他作业不出现），正文高亮同色；不计入外部粘贴、疑似导入或过程关注点。分析摘要多 `declared_draft_chars / ratio`。
- **过程指标的起点**：版本差异、大段突增与画像修订深度从本轮起点计算——重交轮是上一轮终稿，修订初稿首轮是已确认初稿，不能把整份初稿算成大段写入。初稿随证据冻结，当前证据 schema 为 `2026-10-01.1`，指标版本为 `2026-11-07.1`；分析逻辑版本独立为 `7`。历史迁移 `e8a0c2d4f6b7` 的空表守卫及显式重算属于对应部署步骤，不是普通读取时的自动清表、补建或重算。

分析结果提供六个只读接口，都是同一份缓存 payload 的字段切片：`GET .../analysis`、`.../analysis/summary`、`.../analysis/timeline`、`.../analysis/highlights`、`.../analysis/segments`、`.../analysis/segments/{segmentId}`。

### T6.5 看这一轮的 AI 读者试读

提交详情里，AI 澄清追问块之后是 `ChallengeRounds.svelte`（本轮没做过试读则整块不渲染）：

- 顶部一行结论：完成 / 学生跳过、答了几轮，以及**被质疑的几处里改了几处**
- 逐轮三栏并排：**被质疑的那句原文 → 质疑与学生回应 → 该句在最终稿里的样子**；某轮没答会显式标出，某句没动会明确写「没有变化」，被整段删掉会写「已经不在了」
- 末尾给读者的收尾结论（站得住的 / 还需要改的）

**判的是位置不是字数。** 老口径用全文改动量加最小字符阈值，方向是反的：被质疑之后最理想的修改往往最小（删掉一个站不住的例子、把「所有人都认为」限缩为「我采访的 12 个同学里有 9 个」），那些都过不了阈值；而在结尾补一句无关套话稳过。现在只看被引用的那句在最终正文里还在不在。

**这里只呈现「那处变没变」，不判「改得对不对、是不是真回应了质疑」**。引入 AI 自动裁定的方案已在 2026-09-09 否决，不再作为待定项；可能在别处作了等效修改，最终由教师结合正文与回应判断。

**信任层级与来源占比那一块不同**：质疑文本、引用的原文片段、回合数、收尾清单都是服务端生成的权威数据；学生回应是他自己敲的字（等同 typed）；「那句变没变」由发起质疑时冻结的 `source_version` 快照与最终提交正文直接比对得出，同样是服务端权威数据，不依赖客户端上报、也不受客户端时钟影响。因此这一块**不挂** `EduEvidenceDisclaimer`——那句免责说的是客户端上报口径，挂在这里会把权威数据错误降级。

这一块的价值在于：其它块给的都是量化占比，教师看完不知道该说什么；这里给的是「他被问到论据不足，回答说我觉得够了，然后一个字没改」——能直接拿到课堂上讲。

### T7 批改与安全更正

批改依据当前查看的提交稿件与冻结评分设置，页面展示轮次、稿件版本和提交时间。分项模式自动合计总分，仅总分模式直接填写总分与总评；AI 阅读意见与教师评分分开呈现，不自动计分。

反思质量仅在本轮有实际反思回答时适用；提问质量仅在有实际学生提问时适用，自动首轮和按钮触发消息不计入。无证据项目显示不适用、不按零分计入画像。无反思、无提问亦可完成批改。

保存调用 `/teacher/submissions/{id}/review`，必须提交 `expected_final_version_id` 与 `expected_review_revision`。学生已重新提交或另一标签页已更正时返回 409，保留未提交评语供教师参考，重新核对后再保存。

- 尚未发布可存草稿，草稿不进入学生可见反馈与正式成绩。
- 完成批改后学生正文只读；“保存更正”追加评阅版本并同步成绩、画像、统计和导出，不能降回 pending。
- 可查看评阅历史，每次发布、更正或退回保留版本、时间与相应提交证据。
- “退回学生重写”默认关闭：教师入口隐藏，直接请求返回 403。仅在管理员显式开启后可填写退回意见及未来截止并执行退回，正文解锁。退回意见保留在批改与提交证据中，不再自动注入修订 AI 的阅读和对话上下文；私人笔记、数值评分与未发布草稿也不注入。更正意见会通知学生；学生可自主决定重交，无需 AI 认可。
- 历史轮只读，原初稿、终稿、反思、清单和批改仍按实际冻结事实回看。

### T8 多轮循环

新轮只由**退回**触发：教师退回 → 学生重交 → 新轮 `submission_created` 通知 → 教师在同一批改页切到最新轮、看前后稿 diff → 再次批改。提交列表 / dashboard / overview 的统计口径均为**当前轮**（待批改数 = 当前轮 pending 数）。

### T9 本次分析 `/teacher/assignments/[id]/dashboard`

作业的「本次分析」标签（原名「班级概览」，实际是单份作业的分析）。提交列表管「批到哪了」，这里管「这份作业大家是怎么写出来的」。

- 不再有全班风险合计卡（见 T2 末段）；还没有提交时整页只显示空状态；
- **历史清单的全班第一次通读**（仅有旧冻结清单的修订初稿提交，`distributions.first_read`，`revision_items.build_first_read_distribution`；没有带清单的提交则整块不显示）：每个评分维度一行——要改 / 可改进 / 达标各多少人，「要改」的人提交时改了 / 部分 / 没改各多少、几处说改了却原句未动、几人暂缓项一直没补看；要改人数多的维度排前面。按人数，每个学生只取最新一轮；头部写「N 份提交带修改清单 · K 份终稿与初稿相同」。修订初稿作业的逐份表格去掉永远是 0 的「AI 插入 / AI 粘贴」，换成「外部粘贴」和「修改清单」两列（修改清单列按终稿未改、说改了原句未动、要改项数排序）；改写分布为空时整张卡不显示。
- 改写分布：基本未改 / 少量修改 / 部分改写 / 大幅改写（unchanged / lightly_edited / moderately_rewritten / deeply_rewritten，经 `getRewriteLevelLabel` 翻译）段落占比条形，条长按真实占比（原来有 8% 保底，计数为 0 也画一段）；全为 0 时显示空状态；
- **全班在哪些维度上站不住**（`distributions.challenge`，本次作业没人做过试读则整块不渲染）：每个评分维度一行，给一句能直接拿去讲评的话——「论据支撑：28 人被质疑，21 人没答住，其中 15 人被质疑的那句一字未动」，按没答住人数排序。同一行还有一个**「以此为下次的质疑焦点」**——点了跳到新建作业页并预填该维度（复用 `?from=` 复制流程，连 rubric 一起带过去，焦点才说得通）。完成试读少于 3 人时明确标注只能当个案看。这一层是纯内存聚合，不调模型、不落表；
- **归纳成论证类型**（该区块底部按钮，教师点了才生成，不随看板自动加载——这是唯一会调模型的班级分析）：把全班没答住的点归纳成 3~5 类「普遍站不住的论证」，每类给类型名、命中人次、两条脱敏样例、一句课堂讲评建议。四条约束缺一不可：按输入哈希缓存（内容没变不重算）、完成试读少于 5 人直接拒绝出结论且一次模型都不调、送模型的载荷里只有维度名和条目文本（没有姓名学号提交 id，有断言守着）、只报频次不给班级下评价性结论。未传身份字段不等于原文彻底匿名，教师讲评使用样例前仍需按具体内容核对；
- **「建议先看」**：只列有疑似导入或大段突增的提交（按疑似导入优先，最多 5 份），一份都没有时整块不显示；上方写明留痕的信任口径；
- **「每份提交是怎么写出来的」表格**：学生 / 手打 / AI 插入 / AI 粘贴 / 提问次数 / 过程信号 / 有无反思（按微反思存在性计算），点表头排序（默认按过程信号），**整行直达该生批改页**；
- 收到教学通知自动刷新（手动刷新按钮已去掉）。
- 班级维度：班级概况 + CSV 导出（T2）；学生维度：**学生成长画像**（T10）。

- 管理员在“写作辅导 → 段落论证资料搜索”选择连接设置中已配置密钥的 DeepSeek 官方连接，保存服务开关。提示词独立性、关闭后保留历史资料及保存发布／重新试教的说明集中在此展示。密钥不显示给教师或学生。
- 管理员开启资料搜索且服务可用时，教师在 AI 辅导准备稿独立勾选“允许按需搜索资料”（默认关闭），保存、试教并发布后对新请求生效；不修改完整提示词。试教工作台每个候选模型有独立搜索开关。教师端只展示开关，不附上述说明；服务未开启或不可用时，两处均隐藏搜索开关，不显示未开启提示。旧结果卡、已保存方案及采用对比仍显示其实际开关状态。更改后需重新测试，保存方案只保存真实结果的配置。
- 搜索开启时，当前辅导模型可调用搜索和读取来源工具；每轮最多 2 次搜索、3 次读取，最多 3 轮工具决策，随后结束检索并回答。返回资料以链接及说明展示；摘要、未见原文的转引、未确认版本的内容不得标为已核验史料。

- 管理员“段落论证教学模型”只列出模型设置中已公开且启用的普通模型，排除竞技场和管道模型；“推荐模型”只显示其中已勾选项。没有公开模型时提示先在模型设置中公开。保存教学模型时只提交当前公开且已勾选的模型，不保留隐藏的非公开选项。

### 2026-11-09 图文导入、统一编辑与下载（本地）

本节更新 S4.5 以及 2026-11-08 导入说明中“纯文本框、图片在下方分项、关闭识图禁止上传照片”的界面规则。

1. 学生通过“上传”选择文档或最多八张照片，也可拖入或粘贴文件。照片可调整页序后选择“照片转正文”或“插入图片”：前者文字直接进入编辑区、原图留在上传原件，后者保留图像且不自动识读。已有正文在光标处添加，不默认替换；取消不改稿，失败保留文件供重试。未配置或未开启转换时，就地说明原因，仍允许插图。
2. 导入后在连续的富文本稿件中核对。选择文字出现气泡工具栏；图片在对应阅读位置显示，支持放大、宽度、上下移动、替换、删除和撤销，图注随图移动。表格、标题与脚注保持结构；不显示内部材料编号，不做强制分页或文字环绕。复制只复制所选内容；粘贴在当前光标处插入或替换当前选区，保留选区外原文、正文空段和换行，浏览器剪贴板的 HTML 包装换行不进入稿件。全选复制普通正文后在句中或末尾粘贴时，首尾段落接在光标处，不自动另起一行；中间段落、空段、软换行和标题等结构照常保留。格式简化仍沿用原生粘贴与撤销流程，不额外插入空行。
3. 参考图及 Word/PDF 嵌入图默认不识读。开启参考图片识读后，可在图旁点击“读取参考图片”，结果按需展开，明确点击才插入正文；无文字不视为上传失败。照片转正文直接填入编辑框，无需额外点击插入；□ 提示核对模糊字，整批有未读出正文的页时明确失败。复杂 PDF 以原页图保留，原生文字层仍可查看并转入正文。
4. 确认前自动暂存完整稿件，刷新后恢复已保存内容；另一窗口改过暂存稿时拒绝覆盖。确认仍要求至少 200 个非空白正文字符，图片、占位符及未转入正文的识别文字不计入。正文不足明确说明处理方法。
5. 点击“确认这是我的初稿”固定图文起点，沿用同一编辑器和排版继续修改。确认后的修订作业也可继续导入或替换图片，仍受定稿和归属权限限制。初稿白色编辑框随浏览器可用高度伸缩，填满确认栏上方空间；点击框内空白或内边距即可定位光标输入。长稿与小窗口下内容区单独滚动，确认栏固定在底部。
6. “上传原件”收起展示。展开后可查看原件或下载原文件；原件不包含在线修改。Word/PDF 保留原件查看，学生主操作为“下载当前稿（Word）”，不把原件下载当作当前稿下载。
   确认初稿后的稿件顶部将“从文件或图片导入”和“下载当前稿（Word）”放在同一行工具栏，靠右对齐、等高并保持间距；桌面和手机共用排列规则，空间不足时自然换行。
7. 提交固定完整结构和资源。学生历史轮与教师提交页显示该轮图文稿件，图片可放大、脚注可查看；历史过程稿使用当时结构，文字对照另外提示格式/图片变化。教师仍可下载该轮关联原件。
8. 学生提交历史和教师批改页提供“下载已提交稿（Word）”。图片嵌入 Word，包含基本格式、表格、图注和脚注；不附加对话、反馈或评分。新 Word 自动分页，不恢复上传文件的复杂版式。导出失败或当前稿未保存时明确提示，不下载旧稿冒充当前稿。

本轮没有部署到 HIT，也不自动补造旧稿的图文结构。完整范围及验收记录见[优化方案](../development/图文稿件统一编辑与Word下载优化方案.md)。

## 稿件保存失败与本地恢复（2026-11-12）

1. 学生编辑初稿或正文，浏览器立即备份，再自动同步到服务器。只有完整保存成功才移除对应待同步备份；浏览器不能备份时出现明确提示，可复制全文或下载文字备份。
2. 保存失败时，写作区展示可理解的原因、重试与导出操作；登录过期提供重新登录入口，批改/权限错误提示联系老师，格式错误提示核对粘贴或重新导入。确定性错误不反复重试。
3. 刷新或重新登录后再次进入同一作业，先展示服务器稿件，并提示发现本地备份。学生可下载当前稿与备份，选择“恢复此稿并保存”或放弃所选备份；不能自动覆盖服务器稿或读取另一账号的备份。已批改或基线改变时不直接恢复写入；仅超过截止仍可恢复保存，仍可下载保留。
4. 存在未处理备份、保存失败或保存尚未完成时，AI 消息保留在输入框，明确显示未发送；手机可直接打开保存提示。保存恢复后学生再次点击发送，系统不会自动补发。
5. 错误详情可展开查看错误编号与检查位置，师生反馈编号即可定位对应保存校验；诊断日志不包含稿件正文。
