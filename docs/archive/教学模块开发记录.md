- 使用 Tabbit 操作真实前端页面；服务由仓库 `start_frontend.bat`、`start_backend.bat` 启动，端口为 5050、8080。

### 缺陷复现与范围

**V2，优先修复：已批改工作稿仍可由自动保存接口改写。** 用学生账号完成提交并由教师正式批改，页面已显示定稿且不能编辑。对同一会话调用 `POST /api/v1/writing-sessions/{id}/autosave`，提交一致的 `content_text`、`content_json` 数据；接口返回 200，随后工作区接口读到探针正文。提交历史中的冻结正文仍为原稿。已确认的缺陷范围是工作稿写入；其他写入入口需在修复任务中核查，不能把未测试入口也写成已复现。

**V3，提示问题：先批改队列末尾记录时错误提示清空。** 最新排序有两份待批改，打开较早的一份完成批改。页面提示“待批改队列已清空”，随后 `/teacher/review` 仍显示另一份。`saveReviewAndNext` 在没有后序记录时直接提示清空，没有区分仍存在前序记录。评分保存本身正确。

## 2026-10-14：只读写入与批改队列修复

V2、V3 基于 `feba8a722` 修复。10 月 13 日的失败记录保持原样，本节补充修复和复验结果；代码同步不代表生产环境已部署更新。

### V2：统一写作状态校验

- 新增 `services/education/writing_access.py`，统一有效截止和当前轮批改状态。已批改返回 409，超过有效截止返回 400；个人写作不受作业锁定影响，待批改稿在截止前可编辑，退回及个人延期继续按现行截止优先级执行。
- 自动保存、版本、来源、编辑操作、修改清单、补看、试读写入和提交入口接入同一校验。只读工作区、过程摘要、已生成的通读结论仍可读取；切换既有对话作为查看操作保留。
- 对话入口在创建聊天或保存消息之前拒绝只读作业，模型调用阶段也检查状态；避免先写入用户消息再拒绝生成。
- 原浏览器探针复验：自动保存、版本、来源、编辑操作及写作消息五个入口均返回 409，工作稿保持不变。补充实际 HTTP 复验：新聊天、已有聊天的 `/api/chat/completions` 请求均返回 409。回归测试另验证聊天和消息记录数均未增加。

### V3：按最新队列继续批改

- 保存批改后重新获取服务器待批改队列。原后序记录仍待批改时优先进入该记录；否则进入剩余队列首项，覆盖先完成队列末尾记录的情形。
- 仅服务器返回 `total=0` 时提示“队列已清空”。队列刷新失败时返回队列页，不宣称清空。
- 原浏览器场景复验：两份待批改中先完成末尾一份，队列剩一份，页面自动进入剩余提交且无清空提示。[复验截图](../development/assets/browser-regression-20261014/01-next-pending.png)显示剩余提交仍为待批改，提示为“批改已保存”。
- 最后通过接口恢复剩余测试提交为原来的已批改状态，专用测试队列总数为零。队列导航测试覆盖前序剩余、原后序记录、其他评阅者已完成目标、真正空队列和总数非零的情形。
