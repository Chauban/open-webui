> 状态：2026-10-01 编写；**2026-10-03 首次部署完成**；**2026-10-04 上线验收与压测完成**（§五）（main `b9aa66e2e`，比现网新，先于现网上线做测试；现网下次部署后两边再对齐到同一 commit）。

## 零、三条原则

1. **同一个 repo、同一个 commit。** 两台机器跑的代码完全一样，只在**环境变量**和**数据库里的管理员配置**上有区别。不为哈工深开分支，也不改代码。两边要始终保持同一个 commit，这样分析口径一致，跨校数据才可比。
2. **目前和南科大一样是内测。** 遇到带守卫的迁移（表非空就拒绝升级），可以和现网一样用 `--truncate` 清表（2026-10-04 用户定，部署脚本原先对哈工深禁用清表的检查已去掉）。**学生正式开始用之后要改回来**：到时恢复禁止清表，带守卫的迁移先停下来和用户确认。另外，每次部署前的自动备份必须成功，失败就不部署（`remote.sh` 已经是这个行为）。
3. **密钥各自生成，绝不复制。** `WEBUI_SECRET_KEY` 同时用来给教研导出的假名 ID 做 HMAC（`routers/education.py` 的 `_research_pseudo_id`）。两台机器的密钥不同，同一个人在两边导出的假名就对不上，这正是我们想要的效果。**不要为了方便把现网的 env 文件整份拷过去。**

## 二、和现网的差异一览

### 2.1 环境变量（`/opt/rightwrite/rightwrite.env`）

以主文档 §四 的模板为准，**只改下面这几行**：

```ini
# 在新机器上用 openssl rand 重新生成，不能复制现网的
WEBUI_SECRET_KEY=<openssl rand -hex 32>
DATABASE_URL=postgresql://rightwrite:<新密码>@127.0.0.1:5432/rightwrite

WEBUI_URL=https://<哈工深域名>
CORS_ALLOW_ORIGIN=https://<哈工深域名>

# ---- 哈工深专属：关掉两个会替学生出选项的功能（理由见 修订初稿方案 §9）----
# 只在首次启动时作为默认值写进数据库；之后以后台保存的为准，上线后要在后台核对一遍
ENABLE_FOLLOW_UP_GENERATION=false
DEFAULT_MODEL_METADATA='{"builtinTools":{"user_input":false}}'
```

- `DEFAULT_MODEL_METADATA` 必须用**单引号**包起来。systemd 的 EnvironmentFile 会处理引号，不加单引号的话 JSON 里的双引号可能被吃掉。
- 其余几项（Redis、连接池、`BYPASS_EMBEDDING_AND_RETRIEVAL`、`ENABLE_DB_MIGRATIONS=false`、cookie Secure、`WEBUI_NAME` 等）和现网一样，照抄主文档 §四。

## 三、首次部署步骤

顺序有讲究，按编号走。命令细节和原因看主文档对应章节。

1. **买机器、开端口、配 DNS**
   - 腾讯云控制台 → 防火墙：放行 80、443（默认只开了 22，主文档 §六第 8 条）。
   - 在域名解析里加 A 记录。**只签有解析的域名**（主文档 §七）。
   - 本机 `~/.ssh/config` 加 `rightwrite-hitsz` 别名，并验证能免密 sudo。

2. **装系统组件**：Python 3.12、Node 22、PostgreSQL 16、Redis 7、Nginx、certbot，版本和现网一致（主文档 §三）。PG 和 Redis 只监听 127.0.0.1；PG 建库 `rightwrite`、建用户 `rightwrite`。

3. **建账户和目录**：系统账户 `rightwrite`（无登录 shell、无 sudo），`/opt/rightwrite` 属主 `rightwrite`、权限 750。

4. **拉代码，并切到现网当前的 commit**（不是 main 的最新提交）：
   ```bash
   ssh rightwrite 'sudo -u rightwrite git -C /opt/rightwrite/app rev-parse HEAD'   # 先查现网的 commit
   # 新机器上 clone 后 checkout 到这个 commit
   ```
   这台机器到 GitHub 的路由可能和现网一样不稳，clone 要准备重试。

5. **装依赖**：先装 CPU 版 torch 占位，再装 requirements，否则会拉下 4–5GB 的 CUDA 库（主文档 §六第 4 条）。然后 `npm ci`。

6. **写 env 文件**（§2.1），权限 600，属主 `rightwrite`。密钥在服务器上生成，不经过聊天记录，也不落本地磁盘。

7. **装服务器端脚本和配置**：照 `deploy/server/` 装（2026-10-02 从现网备份下来，对照表和要改的地方见那里的 `README.md`）。包括 `migrate.sh`、`build.sh`、`backup.sh`、`offsite.sh`、systemd 的三个单元文件和 Nginx 配置。
   `deploy.sh`（服务器端版本）不用手动装：第一次用本地 `deploy/deploy.sh` 部署时会按哈希自动安装。

8. **systemd 服务**：用 `deploy/server/systemd/` 里的文件。关键是 `ExecStartPre=/opt/rightwrite/migrate.sh`，迁移和配置播种由单进程完成，否则 4 个 worker 会互相撞（主文档 §六第 1、2 条）。

9. **前端构建**：此时应用还没启动，可以直接跑 `build.sh`。仍然建议用 nohup 后台跑（主文档 §六第 9 条）。

10. **启动并做健康检查**：
    ```bash
    sudo systemctl start rightwrite
    curl -s http://127.0.0.1:8080/health          # {"status":true}
    systemctl show -p NRestarts --value rightwrite # 0
    ```

11. **Nginx 和 HTTPS**：以 `deploy/server/nginx/` 为模板，改 `server_name`；证书那几行交给 certbot 生成。确认 `proxy_buffering off` 和 WebSocket 那几行都在。Nginx 1.24 用 `listen 443 ssl http2;`，不要写 `http2 on;`（主文档 §六第 6 条）。
    ```bash
    sudo certbot --nginx -d <哈工深域名> --agree-tos --redirect
    sudo certbot renew --dry-run
    ```

12. **马上注册管理员账号。** 站点一旦能从公网访问，第一个注册的人就会自动成为管理员，要抢先占位。

13. **备份**：装上 `rightwrite-backup.timer` 和服务。异地备份要**单独建一个前缀或存储桶，并配单独的 CAM 子用户**，权限同样只能写、不能读也不能删（主文档 §九）。两台机器的凭据不能共用：任何一台被攻破，都不应该能碰到另一台的备份。
    做一次手动备份和一次恢复演练，比对表数、config 行数、alembic 版本。

## 四、上线后的管理员配置（按顺序做）

1. **接模型**：后台 → 连接，填 DeepSeek 的 API。确认 `deepseek-flash` 能正常对话、思考默认开启。
2. **模型可见性**：学生组只能看到 `deepseek-flash`，其他模型对学生组隐藏或设为私有。
3. **追问生成**：管理员设置 → 界面 →「追问生成」，确认是关闭的（env 默认应该已经关了）。
4. **询问用户**：逐个打开学生能用的模型 → 编辑 → 内置工具，确认「询问用户」**没有勾选**。全局默认的内置工具设置是整组替换的：某个模型只要单独保存过一次内置工具设置，全局默认就管不到它了（`utils/models.py:318`）。**以后每次编辑模型并保存，都要再看一眼这一项。**
5. **直连**：确认关闭。
5a. **打开新用户注册**：管理员设置 → 通用 →「允许新用户注册」打开。上游在第一个管理员注册后会**自动把注册关掉**（`routers/auths.py` 注释 “it auto-disables”），不打开的话学生拿邀请码注册会直接 403。2026-10-04 验收时发现是关的，已打开。外部可用 `curl -s https://hitsz.rightwrite.cc/api/config` 看 `features.enable_signup`。
6. **新建作业默认值与辅导风格**：设置 → 写作辅导 → 顶部，「新建作业的默认作业形式」选**修订初稿**（只是表单初始值，教师仍可改选）；「作业可选辅导风格」**关掉**；「新建作业默认评分维度」→ 修订初稿，点铅笔填成提示词里的 8 项（名称与分值见说明书第五节：综述只写已有研究 10、由不足导出本人研究 20、出处与参考文献 15、文献的相关性与充分性 20、分类与组织 15、每篇文献的介绍 10、学术表达 5、标题与引言 5；2026-10-04 核对库里实际值即此）。
7. **提示词**（等黄老师确认后）：教学设置里，把「修订初稿」任务说明整段替换成 `哈工深批注/产出/提示词.txt` 的内容。改完后，已有作业的文件夹系统提示要重新生成（见 `修订初稿方案` D9）。
8. **教师账号**：3 位老师注册后由管理员批准，并设为教师身份。学生凭邀请码注册，注册即激活，不用审批。
9. **陪黄老师配第一份作业**：作业形式和评分维度第 6 步已设好默认（修订初稿 + 提示词里那 8 项），确认一下即可。**老师改维度名称时要和提示词里的标准一致**：第一次通读按作业的评分维度逐项下结论，维度对不上，结论表和她的标准就对不上。反思题的配置见 `修订初稿方案` §8。

- **服务器容量（2026-10-04 实测，假模型每次回复 16.6 秒，2 核 8G / 4 worker）**：
  - **瓶颈是 CPU，不是内存**。全程内存可用 ≥3.9G、PG 连接 ≤50、服务 0 重启、对话 0 失败。CPU 耗在应用逐 token 处理流式回复（4 个 worker 各 30~55%，nginx ~27%）。
  - 默认（每 1 个 token 推一次）：**15 人同时等回复 CPU 就满**，页面接口 p95 20.8 秒；30 人回复中位 32 秒；60 人回复中位 56 秒、p95 82 秒，页面中位 20 秒。
  - 设模型参数 `stream_delta_chunk_size`（攒 N 个 token 推一次，不用重启）：=10 时 15 人完全正常（回复 17.0 秒≈模型本身、页面 p95 0.59 秒）、60 人回复中位 20 秒；**=30 时 60 人回复中位 18.0 秒、p95 19.6 秒，页面中位 2.2 秒**，但 p95 仍 20 秒、峰值 CPU 仍会顶满。
  - **已把 `deepseek-flash` 设为 `stream_delta_chunk_size=30`**（代价：回复不再逐字出，约半秒蹦一段）。要改回：后台 → 模型 → deepseek-flash → 高级参数里删掉该项。编辑模型保存后照 §四第 4 步再核对「询问用户」。
  - 结论：全班 60 人同一时刻都在等回复（上课一起点确认初稿）时，回复本身不慢，但这一两分钟里翻页会卡；平时十几人同时对话没问题。要彻底解决只能升配（4 核）或把通读改成非流式/错峰。
  - 方法与局限：k6 账号登录这一步我不能代输密码，最终改用**管理员浏览器会话在页面里发并发**（对话流 + Socket.IO 长连接 + 每秒 3 批页面接口），走完整 nginx→worker→PG→假模型路径；局限是单账号，且 Chrome 单页只撑到 127 条 WebSocket（200 档实际 127），连接数这一项没压满。压测脚本 `loadtest/loadtest.js` 已修 v0.11 的 chat_id 归属校验（见 loadtest/README）。
- 模型商并发（2026-10-03 已测，本机经后端转发打真模型，`loadtest/diagnosis_burst.py`）：DeepSeek-V4.1-Flash **60 人同时触发第一次通读，60/60 成功并都能解析成结论表**，耗时中位 29 秒、P90 64 秒、最长 85 秒。最慢的学生要等一分半，进度提示要让他知道还在跑；链路上的超时都比这长（后端 300 秒、nginx 3600 秒）。换模型或换账号后重测一次。

## 六、日常更新

### 6.1 `deploy/deploy.sh --target hitsz`（2026-10-03 已加）

脚本里写死了两处：`HOST=rightwrite`，以及最后的健康检查地址 `https://rightwrite.cc/health`。要加一个目标参数，例如：

```bash
deploy/deploy.sh --target hitsz          # 部署到哈工深
deploy/deploy.sh                         # 默认仍是现网
```

由 `--target` 决定 `HOST` 和健康检查的域名。`remote.sh` 不用改，因为两台机器的目录结构相同。

### 6.2 部署顺序

每次上线都是**先现网，后哈工深**，而且是同一个 commit：

1. `deploy/deploy.sh ...`：合并、推送、部署现网，并在现网上验证；
2. `deploy/deploy.sh --target hitsz`：把同一个 commit 部署到哈工深。

如果第 2 步因为带守卫的迁移停下来，内测期间照第 1 步的做法加 `--truncate` 清表即可；正式使用后见 §零第 2 条。

停机时间选在晚上或周末，避开学生集中写作的时段。国庆期间学生随时可能在写，部署前先看一眼当前有没有活跃会话。
